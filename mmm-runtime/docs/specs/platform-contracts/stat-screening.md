**继承是硬规则：** 上游任一层（映射 / 质量 / 业务签核）已经否决的指标，**不进入检验**。
这不只是记账——重新给它们打分等于把已经定了的事又摆到人面前当悬案，而且因为共线性是在
整个指标集上一起算的，死掉的指标会把还活着的指标的共线性顶高。它们仍然**列在表上**
（标 `inherited-drop`、三个统计量为 null），列出来是让漏斗可读，给数才是复活。

**行来自因子树**，三种状态，与数据质量评分表同一套词表：

| dataStatus | 含义 | 三个统计量 |
|---|---|---|
| `scored` | 长表里有这条序列，已检验 | 有数 |
| `no-data` | 树上要了，一条数据都没到 | **null，不是 0** |
| `inherited-drop` | 更早的层已否 | null |

**`null` 不是 0，这一层尤其要紧。** 共线性的 1.0 是「好」的那一端——一个默认的 1.0 会让
没人筛过的序列读起来像「无共线性」。这是全套判据里唯一一处「默认值恰好是最好的分数」，
也是唯一一处 `Optional` 比 `= 0.0` 重要得能单独写一段的地方。

可能不一样的 Pearson 运算。相关性结果的指纹对不上时判失败——用旧的相关性挑设计矩阵，
算出来的共线性对着一个并不存在的模型。

## 判定规则与阈值

### 波动性 CV

**定义（工作簿口径，不是教科书 CV）：** 先把序列 min-max 缩放到 [0, 1]，再算 `方差 / 均值`。
空序列 / 常数序列 / 均值 ≤ 0 一律返回 0。

| 分 | 条件 | 含义 |
|---|---|---|
| 0 | `CV ≤ 0.05` | 变异度极小，强烈建议剔除或找替代数据 |
| 0.5 | `0.05 < CV < 0.1` | 变异度弱，除非业务不可替代否则不建议入模 |
| 1 | `CV ≥ 0.1` | 变异度高，波动较为明显 |

**不差分。** 它问的是"这条序列动不动"，那是原始水平的属性。

**常数序列现在会被检验，不会被悄悄丢掉**（2026-08-11）。面板此前把「整个面板上恒定」的列
直接删掉，理由是「没有波动、没有共线性」——可一条从不移动的序列正是这项检验存在的理由，
删掉它意味着复核的人最该看见的那一行从来没到过打分表。

### 相关性 Pearson

因子 vs 响应，**单变量、有符号**，判定用 `|r|`。少于 3 对有效观测、或任一侧标准差为 0 时返回 0。

| 分 | 条件 | 含义 |
|---|---|---|
| 0 | `\|r\| < 0.1` | 基本不相关，不建议入模 |
| 0.5 | `0.1 ≤ \|r\| < 0.3` | 弱相关，视因子数量与业务重要性决定 |
| 1 | `\|r\| ≥ 0.3` | 较为相关，建议入模 |

跑在**对象内同比差分**上（period = 12），差分之后再做**对象内标准化**。两步都不能省：
月度原始水平上每个指标都和响应相关，因为它们共骑同一条季节趋势；而不做对象内标准化，
在合成数据上每个 |r| 都被压到 0.25 以下，包括按已知 6–8% 贡献生成的驱动。

### 共线性 VIF

**注意方向：VIF = 1（无共线）是好的那一端，得 1 分；VIF ≥ 5 是明显共线，得 0 分。**

| 分 | 条件 | 含义 |
|---|---|---|
| 0 | `VIF ≥ 5` | 存在明显共线性，需要关注 |
| 0.5 | `1 < VIF < 5` | 中等共线性，一般可接受 |
| 1 | `VIF ≤ 1` | 该特征与其他特征无线性相关 |

两种情形，都返回每列一个值：**可识别（n > p + 1）** 用精确的 `[inv(R)]_ii`；
**欠定（p ≥ n）** 退化为两两最大共线代理 `1/(1 - max r²)`。缺口按**两两完整**处理。
取值下限 1.0，上限 1000.0。

**对着什么算，是这一层最贵的一个坑。** 对着全部候选一起问，两种情形下都失败，
而且是同一个根因——现实中不存在一个把上百条共季节的营销序列放在一起的模型。
短面板落进两两代理，几乎每条序列都有某个同伴相关到 0.89 以上；长面板去求逆一个远非正定的
相关矩阵，于是每个值都顶到上限。两条路的结果一样：**约九成指标被筛掉**。
所以每个指标对着它**可能真的进得去的那个模型**来量：与响应相关性最强的 12 条构成设计矩阵；
不在集合里的指标用最强的 11 条同伴加自己。**分档不变、算法不变，只有喂进去的矩阵变了。**

### 合成与判定

```
Total = CV分 × Pearson分 × VIF分       （三档 0 / 0.5 / 1，取值 4 位小数）
  Good           if  Total >= 0.5      （三项全过，或恰有一项拿半分）
  Acceptable     if  0 < Total < 0.5
  unconsiderable if  Total = 0
```

**`>= 0.5` 是 2026-08-11 的改动。** 验收表原文写「0.5–1 验收通过 / ≤0.5 人工介入」，
0.5 同时落在两档；客户裁定它归验收通过——与数据质量评分表的同一处歧义按同一条裁决处理。
乘法可达的总分只有 `1 · 0.5 · 0.25 · 0.125 · 0` 五个值，所以这条线的实际效果是：
一个总分 0.5 的指标（强信号 + 一项中等）不再被摆到人面前。

**文档与真实工作簿另有一套加法四档**（`Total = CV + Pearson + VIF`，`≥3 Good / 1.5–3
Acceptable / <1.5 unconsiderable`）。**代码执行的是乘法版**，本 runtime 跟随代码。
两者行为差别很大：加法下一个 CV=2、Pearson=2、VIF=0 的指标总分 4 分是 Good；
乘法下同一个指标总分为 0 直接淘汰。**乘法更严，也更容易把强信号但共线的指标一票否决。**
这不是需要改的偏离，是需要**在客户口径上统一**的分裂：对客户说"总分 1.5–3 需要确认"
还是"总分 0.5 以下需要确认"，是两句不同的话。

### 三种不参与检验的判读

| autoVerdict | 什么情况 | 默认处置 |
|---|---|---|
| `response` | 响应指标。驱动因子是对着它做相关性检验的，它不检验自己，也不会被剔除 | `include` |
| `no-data` | 没有可检验的序列 | 空，等人定；回数据需求追交付 |
| `not-screened` | 进不了面板，通常是它在每个建模对象里都没有可用的月度取值 | 空，等人定 |

`response` 这一档是补上的：Y 留在树上、也留在打分表上，但它没有面板列，
此前会得到一个 `autoVerdict: "scored"` —— 那不是一个判读，而且会让复核的人对着一行
无法裁决的记录卡住验收。

### 处置默认值

| autoVerdict | 默认 disposition |
|---|---|
| `Good` | `include` |
| `Acceptable` | `review` |
| `unconsiderable` | `drop` |

**`review` 不是终态。** 人裁决后每行必须落到 `include` 或 `drop`；留在 `review` 的行
会卡住交付验收。

### 覆盖期下限

| 常量 | 值 | 作用 |
|---|---|---|
| `MIN_SCORED_MONTHS` | 12 | 低于此值该行仍然产出（判不可用、总分 0、写明"只有 N 个观测月"），**不静默省略** |
| `DETREND_PERIOD` | 12 | 同比差分周期 |
| `MIN_DETRENDED_POINTS` | 6 | 差分**之后**剩余行数的下限。守的是结果不是输入：13–14 个月的项目差分后只剩 1–2 行，相关性的守卫会对每个指标静默返回 0，把所有东西无理由地全丢掉 |
| `SCREEN_DESIGN_COLS` | 12 | VIF 设计矩阵宽度，与建模驱动数上限同源 |

### 红旗条件

- **总分为零必须点名是哪一项挂的**（波动性 / 相关性 / 共线性）。
- **`VIF ≥ 10` 一律建议剔除，不论总分多高。** 乘法标度表达不了这条：共线性 5 和 50 都是 0 分，
  一个总分只能归零一次。
- **指标数多于观测数时（`p ≥ n`），产出必须直白说明 VIF 只是两两近似值。**
- **某因子仅有的指标全部不达标 → 预警**，回流找替代数据。这是明写的规则，不是可选提示。

## 产出格式

### 1) 四份计算结果 [computed]

`data/derived/stat-{volatility,correlation,collinearity}.json` —— 各带 `test` / `signature` /
`panel` / `months` / `rows[]`（每行带自己的那一个统计量与 `months`）/ `skipped` / `orphanCount`。
相关性那份另带 `detrend`，共线性那份另带 `vifDesign` / `vifRegime` / `severeVif` 与每行的
`severeCollinearity`。

`data/derived/stat-panel.json` —— 卷积结果，见 `tools/catalog/stat.scorecard.yaml` 的
`output.shape`。

### 2) 主产出 —— `artifacts/s2/stat-scorecard.yaml` [store]

结构见 `skills/stat-screening/templates/stat-scorecard.yaml`。要点：`dataStatus` 三态；
未检验的行统计量与 `total` 写 **`null` 而不是 0**；每行 `source` 指回 payload；
`panel` 与 `factorAlerts` 整段抄。

### 3) 视图 —— `artifacts/s2/stat-scorecard.xlsx` [view]

```bash
~/.local/bin/mmm app workbook scorecard -w <工作区> --card stat
```

三张表：评分卡 · 统计 · 说明。工作簿带打分表的 `sourceHash` 自定义属性，
`workbook_current` 靠它判过期。**没人手改它。**

渲染硬要求：**没有统计量的行三个数与总分渲染成「—」**，不能渲染成 0，也不能留空。
共线性尤其要紧：0 在这个刻度上读起来像满分，1.0 读起来像"完全不共线"，
而真相是"没人量过"。`vifRegime` 是 `pairwise-proxy` 时，那句话要出现在给人看的那一页上。

### 4) 图表规格（登记为未做）

`st-scatter`：波动性 × |相关性| 散点，气泡大小 = 共线性，颜色 = 判读。复核用，不是给客户的。
runtime 没有实现——图表应用目前只服务业务校验。列在这里是为了它不被忘掉。

## Gate

| 触发条件 | 判定者 | 候选处置 | 路由 |
|---|---|---|---|
| 存在 `Acceptable` 档（`0 < Total < 0.5`） | DS | `keep` 保留（推荐）/ `drop` 只留 Good 档 / `review` 逐条挑 | **逐条才是真正生效的那一层**，最终每行落到 include / drop |
| 存在 `VIF ≥ 10` | DS | 降维 / 合并 / 剔除 / 知情保留 | **成组裁决**，定完重跑打分再摆一遍 |
| 存在 `no-data` 行 | 人 | 追交付 / 本轮不做 / 换指标 | 回数据需求与验收 |
| 某 L4 的全部指标 `unconsiderable` | DS + BA | `escalate` 预警 | **回流业务理解**找替代指标。紧急度高 |

**回流边在流程定义里没有配好**（这一关自身没有跨交付物的退回目标），所以因子级预警走的是
**上报**而不是自动退回：把选择题交给编排层，由人决定是否重开业务理解那一段。

## 备注

- **B1 · 加法四档 vs 乘法三档** 是本交付物最重要的一处口径分裂，见「合成与判定」。
  真实工作簿 Sheet2 的数据行全是 `1|1|1`、Total `1`、判定 `Good`——恰好在两套标度下判定相同，
  所以工作簿本身分不出用的是哪套。
- **B2 · 检验从"全国汇总序列"改到"面板"** 是平台 2026-07-27 的一次修正。改之前每个指标只有
  34 个点，共线性永远落在欠定的两两代理里；改之后观测数是 `n_objects × n_months`。
  同时，"在一个渠道里恒定、但渠道之间差异很大"的指标不再和真正的常数指标无法区分。
- **B3 · 区域与 L5–L8 残差在每个格子内部先滚起来**，用该指标自己的汇总规则。它们在模型对象
  **内部**，而不同指标上报的深度不一样——如果面板按它们建键，两个指标可能一行都不共享，
  然后在"什么都没有"上被静默地判成相关。
- **B4 · 与数据质量层的区别（不要混）：** 数据质量衡量**数据本身的质量**，失败处置是
  "0 分不能用、边缘分人决策"；统计检验衡量**指标对建模的适用性**，失败处置是
  "淘汰指标；因子全失则预警"。同一个指标可以数据质量满分而统计上完全不可用。
- **B5 · AI 在这一步只写一句话。** 每行 ≤22 词的入模利弊陈述，只基于三个已算好的数，
  **不得编造数字**。分数本身永远是算出来的，AI 的话只是解释它。
