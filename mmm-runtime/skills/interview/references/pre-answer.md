# 能力 2 · `interview/pre-answer` —— 先按现有材料答一版

类型 **C**，**可选**。产出 `artifacts/s1/interview/pre-answers.md`，
照 `../templates/pre-answers.md` 填，再渲染成 Word。

前提只有一个：手上有提纲。这个能力不做也不拦着后面——但不做就等于把整场访谈的时间
平均分给了所有问题，包括那些材料里已经写清楚的。

**这份东西是给访谈者的简报，不给客户看。** 它要回答三件事：我们现在以为答案是什么、
这个以为有多硬、什么会推翻它。目的只有一个——**把访谈那一小时花在真正不知道的事情上**。

---

## 1 · 逐题出一版（C）

提纲里的每一题都要有一块，一题都不能少。锚点是 `### Q<n> · <题干>`，题干与提纲逐字一致。

五个字段，缺一不可：

| 字段 | 写什么 |
|---|---|
| 初步回答 | 一到三句。这是一个**待验证的假设**，不是事实，措辞上就要看得出来 |
| 置信度 | `high` / `medium` / `low` / `none` 四选一 |
| 依据 | **文件 + 位置**。只写文件名不算依据——第二个人打不开你说的那一页 |
| 若成立 | 这条预答如果被证实，因子树上哪一行会怎样 |
| 现场留意 | 访谈时要竖起耳朵听的那件事 |

## 2 · 置信度是判断依据，不是判断心情

| 级别 | 含义 |
|---|---|
| `high` | 有文档明说 |
| `medium` | 从文档说的能推出来 |
| `low` | 行业惯例或推断，由访谈定夺 |
| `none` | 完全没依据 |

**`none` 是这份文件里最有用的一个值。** 一条自信的错预答比空白危险得多：访谈者以为
已经知道了，就不再听那个答案，错的版本会一路活进因子树。

没依据就写「没有依据」，不要编一句像样的。**"大致""可能""通常来说"这类词，
基本都是 `none` 被写成了 `low` 的痕迹。**

## 3 · 数据类问题不逐条另想说法（M）

数据题问的是可得性、颗粒度、拆分维度、口径——这四件事只有数据团队知道，材料里通常
什么都没有。所以数据题**统一用一句固定模板**，置信度 `none`：

> 没有依据。该指标的可得性、来源、颗粒度与口径要由数据团队在访谈中确认，
> 现有材料没有覆盖这个因子的完整数据规格。

**例外只有一种：** 材料里确实写了这个指标的来源系统或颗粒度（比如媒介代理的月报里
写明"抖音 Ads 可提供周度花费、曝光、互动"）。那就照实写，置信度往上抬，并在依据里
指到那一页。这时候这一题就不必在现场问了——**这正是预答存在的价值**。

## 3.5 · 联网：只对业务题，而且只到 `low`

这一步是整套流程里两处允许联网取材的地方之一（另一处是因子树的 `derive`）。判准相同：
**推导性质的步骤可以联网，因为它是在为材料没覆盖的地方去查外部口径**；确认与回写那几步
在人已经看过的东西上做判断，中途去捞新材料，人批的就不是他看见的那份。

**什么值得联网：** 行业惯例、品类季节性、竞品的公开动作、宏观口径、监管变化。
这些是关于世界的事实，网上有，而且查到之后访谈就不必花时间问。

**什么绝对不许联网：数据题。** 可得性、来源系统、颗粒度、拆分维度、口径——
这四件事是关于**这个客户内部系统**的事实。网上不可能有，所以搜出来的一定是编的，
而它会读起来和真答案一模一样。`web_grounding_scoped` 会逐题查，发现数据题带了 URL
就直接失败。

三条格式要求，一条都不能省：

| 要求 | 为什么 |
|---|---|
| `grounding` 里写 `url` + `accessed` 日期 | 查不到日期的引用不是引用——网页会改，半年后没人能复核 |
| `依据` 字段里也要出现那个 URL | 读预答的人不会去翻 frontmatter |
| 置信度 **≤ `low`** | 一条网上查来的行业惯例，对这个客户成不成立，只有访谈能定 |

联网来的东西措辞上要看得出来源是外部的：写"行业口径上……这不是这个客户的说法"，
不要写成好像客户已经这么说了。

## 4 · 数出访谈的真实议程

统计四档各多少题，`low` 与 `none` 加起来就是 `counts.focus`。按层级 × 团队把这些题号
列成一张表放在文件末尾：**这一页纸就是访谈当天真正要过的内容**，其余的题随提纲交给
对方书面回填。

## 5 · 渲染成 Word

```bash
~/.local/bin/mmm app report interview-pre-answers --workspace <工作区>
```

**这份 Word 是给访谈者的，不给客户。** 它写的是"我们现在以为答案是什么"，
把它发出去等于让客户看到一份对他的生意的猜测。Markdown 是真相，Word 是视图，
改内容改 Markdown。

## 6 · 交付

告诉编排层：**预答已写好，请验收 `interview/pre-answer`。** 同时报四个数：
多少题有文档背书、多少题完全没依据、多少题是联网查来的、访谈重点是哪几节的哪几题。

顺带交代下一步要什么：把访谈纪要或转录稿放进 `inputs/interview-minutes/`，一份一个文件。
**这里不做录音转写**——是音频就现在说，别等人传完一堆 mp3 才说。

要一份能直接带进会议室的表格：
`~/.local/bin/mmm app workbook interview --workspace <工作区>`。
它把提纲和预答并成两张表，并按置信度自动标出访谈重点。
