# 能力 4 · `interview/digest` —— 从纪要提出因子树的改动建议

类型 **C**。产出 `artifacts/s1/interview/proposals-<来源>.yaml`，照
`../templates/proposals.yaml` 填。

**预答说的是我们以为的，纪要说的是客户说的。这一步是两者的对账。**
而对账里最有价值的一段是：**预答错的地方，就是因子树要变的地方。**

前提只有两个：手上有纪要，工作区里有因子树。不需要先有预答——没有预答就少了一条
对账线索，多出来的部分照样能提，只是要在 `meta.note` 里说明这次没有预答可比。

---

## 1 · 一份纪要一次消化

多份纪要不要一次吃完。一次只看一份，理由和整理纪要时一样：**串味**。
消化时只用手上这一份纪要的内容，别把另一场访谈的印象混进来。

一份消化失败只损失它自己：跳过，说明是哪一份、为什么，继续消化其余的。

## 2 · 从哪里找改动

从纪要的 `**对因子树的影响：**` 那些行和 `[unplanned]` 段落里找候选，每条对着当前的
树核一遍。`[unplanned]` 那些段落尤其值得看——**客户在告诉你，你的树不知道该问什么。**

有预答时多一条线索：预答说"这个指标一直不可分"，纪要说"财务留了拆分口径"，
这种被推翻的地方直接对应一条 `amend`。

## 3 · 合并多份纪要的结果（M）

| 对象 | 规则 |
|---|---|
| 改动建议 | 按 `(kind, l1, l2, l3, l4, indicator)` 六元组去重 |
| 冲突 | **不许丢。** 同一件事两份纪要说法不同，写进 `meta.note`，并在确认时说出来 |

同一个口径被两个团队说成不同的样子，这件事本身就是一条结论——通常说明收数时会在
这里炸。它同时是能力 5 的 `conflict` 洞察的原料，**两边都要写，不要指望对方记得**。

## 4 · `proposals-<来源>.yaml` 的规矩

**每条建议都带逐字原话。** `evidence` 写受访者的话加纪要段号。没有原话就没有建议——
而且要回头看纪要：一句值得改因子树的话，当初就值得逐字记下来。
`proposals_have_evidence` 会拦下没有原话的条目。

**说访谈说了什么，不是说你从中得出了什么。** "直播占数字预算 40%" 支持新增一行直播，
它不支持因为你怀疑重叠就剔除达人那一行。那种判断属于洞察，写进 `insights.yaml` 的
`conflict`，由人去看。

**`amend` 和 `reject` 用行 id 指行。** 找不到某条访谈意见对应的行，这件事本身值得报告——
说明树和客户可能在描述两门不同的生意。

**颗粒度约束要落进字段。** "这个指标只能到月给不了周"是访谈最常带回来的东西，
写进 `granularity`，不要只写在 `rationale` 里——承接它的 `factor-tree/amend` 是按字段读的。

**`applied: pending` 由这一步写，只有因子树的 `amend` 步骤能改成 `accepted` / `rejected`。**
不要预先替人裁决。

**一条改动都没有是合法结果，而且必须说出来。** 写 `proposals: []`、
`counts: { proposals: 0 }`，并在 `meta.note` 里写清这场访谈覆盖了什么、为什么一条都没有。
**沉默的空文件在实盘发生过：交付物看起来是完成的，访谈的结果丢了，而文件里没有一个字提到这件事。**

## 5 · 新增 L2 的特例

访谈提出的改动要在骨架上加一层 L2 —— 这件事只有因子树的 `amend` 步骤能批，而且要在确认时
明说"骨架长了一层"。要新增 L1 的，那不是一行，那是一个发现，写进 `insights.yaml`。

## 6 · 人裁决之后：归档校正版工作簿

逐条裁决和写回因子树是 `factor-tree/amend` 的事，见
`../../factor-tree/references/apply-proposals.md`。**这一步产出的最后一样东西是一份
带日期的校正版工作簿**，归档到 `exports/`：

```bash
~/.local/bin/mmm app workbook factor_tree --workspace <工作区> \
  --out exports/factor-tree-<日期>-访谈校正.xlsx
```

`artifacts/s1/factor-tree.xlsx` 永远是当前版，采纳完访谈改动之后它就不再是客户在
`confirm` 那道门上签字的那一份了。归档的这份是"访谈到底改了什么"这个问题唯一便宜的
答案——否则只能拿两版 YAML 对着看。`amended_workbook_archived` 会检查它在不在、
是不是和当前的树一致。

**不要在 Excel 里改内容。** 工作簿是单向渲染出来的视图，改了下次重新生成就没了，
而且人是在这份表上签字的，表和树对不上，签的就不是他看见的那份。

## 7 · 交付

告诉编排层：**因子改动建议已写好，请验收 `interview/digest`。** 同时报四个数：
消化了几份纪要、多少条改动建议在等因子树裁定、其中新增/修改/剔除各几条，
以及这些建议动到树的哪几个 L3。
