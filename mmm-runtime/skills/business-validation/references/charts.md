# 步骤 page —— 出图册与逐卡解读（M + C）

```bash
~/.local/bin/mmm tool validation.panel  --workspace <工作区>
~/.local/bin/mmm tool validation.facts  --workspace <工作区>
~/.local/bin/mmm app charts book --workspace <工作区>
```

| 路径 | 是什么 |
|---|---|
| `data/derived/validation-panel.json` | 页面吃的那份数据，附带每个指标的汇总口径、单位、画法 |
| `data/derived/validation-foldcheck.json` | 跨端比对用的黄金状态（`validation.panel` 顺带写的） |
| `data/derived/validation-facts.json` | **你的取数来源**——每张卡在默认视角下的首末、峰谷、最大单期变动、最长连跑、缺口、与响应的相关、年度表 |
| `artifacts/s2/chart-book.html` | 渲染出来的图册，没人手改它 |
| `artifacts/s2/business-validation.md` | 解读，照 `../templates/business-validation.md` 填 |

## 只读算好的数，不看图、不读原始序列

`validation-facts.json` 小是故意的：它装的正好是"看一眼这张卡能诚实说出的全部内容"。

读原始序列等于在脑子里做算术，然后把结果写得像工具算的；看渲染出来的图等于描述像素位置。
两种都会产出和真话一模一样的文字，所以这条是硬规矩不是偏好。

产出文档的元信息块要声明它读的是哪份计算结果，验收时按内容比对——
计算结果重跑过而文档没跟着改，会被判为过期。

## 页面长什么样

**一张卡 = 长表里真实存在的一个 `L1›L2›L3` 组合。** 因子树声明了要什么，页面只画数据真的
到位的因子。完整路径是唯一键——同名的 L3 挂在两个不同父节点下是两张卡，不合并。

卡片滚进视野才画，所以十几二十个因子一次性打开也不卡。

**筛选器分两类作用域**，这个区分有业务理由：

| 作用域 | 有哪些 | 动它会怎样 |
|---|---|---|
| 全图（页面顶部一条） | 时间粒度 · 品牌 · 渠道 · 区域 | 销量底图和驱动一起动 |
| 只动叠加层（每张卡自己） | 数据来源 · L4–L8 下钻 · 指标 | 驱动变，**销量底图纹丝不动** |

不管现在看的是哪个文件来的、哪个子因子下的花费，参照系必须保持不变，否则"投入 vs 产出"
就失去基准了。

其它交互：图例点一下隐藏（被隐藏的序列**退出轴域计算**，所以藏掉一条量纲巨大的指标，
其余会自动放大）、左右轴各自的手填范围、时间刷选、恢复视图、年度表 + 同月对比。

**图上没有"换一个 Y"的选择器。** 响应变量在数据处理那一步就定死了，每个界面都从同一处读。
历史上这里放过一个"销量/销额"切换，结果这一层的图看的是一个 Y、拟合用的是另一个 Y，
两边讲不同的故事。

## 页面自己算数，而它算的东西被验证过两次

这一页会按读的人选的条件当场重算。这是架构文档 D10 有意推翻的一条旧决定，理由与机制见
`../../shared/fold-contract.md`。你要知道的是两件事：

1. **生成页面之前** node 会把页面内联的归约拿去重放几百个筛选态，和工具算的逐位比对，
   对不上就**不写这一页**。
2. **页面打开时**它再自查一遍内嵌的那批，对不上就**一张图都不画**，只出一张写明哪里对不上
   的失败卡。

所以如果 `~/.local/bin/mmm app charts book` 报了"这一页没有生成"，不要绕过它——那说明页面
和计算结果对同一个问题给出了两个答案。

## 解读怎么写

**解读是一张表，不是一篇文章。** 照 `../templates/chart-analyses.yaml` 填
`artifacts/s2/chart-analyses.yaml`，一张卡一条。

以前解读是自由 markdown，图册按标题字符串去找它：标题差一个字，那一段不报错、不提示，
只是不出现，而读的人看到「待写入」，以为没人写过。现在对不上就是一次响亮的失败。

每条对着 `data/derived/chart-analyses.json` 里的一个槽位写：

| 字段 | 要求 |
|---|---|
| `card` / `key` / `filterLabel` / `seriesDigest` | **从槽位逐字抄**，不要自己构造 |
| `headline` | 一句。客户一眼认出是自己的生意，点名一个真实期间和一个真实数值 |
| `trends` | **2–4 条**。方向与快慢，每条点名真实期间区间 |
| `anomalies` | ≤6 条。某条序列打破自己规律的地方，**只说发生了什么，不断言原因** |
| `inflections` | ≤6 条。方向反转的地方，点名两侧期间 |
| `caveats` | ≤6 条。缺口、覆盖太短、被截断 |

相关系数只许引 `correlationWithResponse` 这一个。

**引的每个期间必须出现在那张卡的 `periods` 里。** 一个不存在的期间是一个编出来的期间，
而这是散文里唯一一类机器抓得住的编造 —— 验收会点名它。

**没写的卡不是错。** 它会显示槽位里预填的计算读数，页面上写明这是计算读数。与其编一段，
不如让它显示读数。

**解读描述的是默认视角**（不筛选、最细粒度、默认那几条指标），也就是读的人第一眼看到的
那一幅。动过筛选或换过图型之后，页面会标出「这段解读对应的是默认视图」。

`artifacts/s2/business-validation.md` 是**生成的视图**：`charts.book` 从这张表渲染它。
改那份 md 没有用，下一次重出会覆盖。

## 空也是结论

一张没有观测值的曲线、只有一个点的序列、算不出来的相关系数——写下来，连同原因。
一份全是图的文档里夹着一张空图会通过评审，因为里面没有东西可反对。

页面自己也遵守这条：缺的月份画成断开、没铺满的时间桶打斜纹、撑不起的粒度按钮置灰不删、
下钻梯子里没有可选项的那一层是虚线灰框、被筛选排除掉的全国口径曲线数出来告诉读的人。
