# 步骤 `data-request/build` —— 生成数据需求包

类型 **A**（生成是 **M**，交付前自查是 **C**）。产出 `artifacts/s1/data-request/`：
一个 L3 一个工作簿、`00-response.xlsx`、覆盖报告 `coverage.md`。

---

## 0 · 澄清（三条，一次问完）

到这一步该拍的板都拍完了，只剩三件"答案会改变产出"的事。

### 1 · 谁来填每一张表

**为什么非问不可：** 这是决定数据到底会不会到的那件事。一张没有对接人的表就是一张
没人负责的表，签收呈现里"谁欠什么"是四段中的第二段。

```
【澄清 1/3】每张表指给谁
读到：因子树上 17 行有对接人，9 行空着。

  A. 按 L3 指一个负责团队（推荐）—— 工作簿就是按 L3 分的，责任边界和文件边界对齐。
     代价：一个团队内部还要自己分工。
  B. 按 L4 逐表指到人 —— 最准。
     代价：客户要一次指出几十个人，通常指不动，最后还是退回 A。
  C. 全部交给一个数据对接人转发 —— 看起来省事。
     代价：把风险集中到一个人身上，他休假这个项目就停了。
```

### 2 · 有指标缺定义 / 单位时发不发

**为什么非问不可：** 发出去之后再补，等于让客户填两遍。

```
【澄清 2/3】带着缺口发，还是补齐再发
读到：覆盖报告里 4 行没有单位、9 行没有对接人。

  A. 先回因子树补齐再发（推荐）—— 覆盖报告已经逐行列出了缺什么。
     代价：一个来回。而且树在确认之后，改它要走一次显式的重开。
  B. 带着缺口发，表里留空让客户自己写定义 —— 快一轮。
     代价：会拿回一列没人知道单位的数字，而它会在后面被和不兼容的东西加起来。
```

### 3 · 时间覆盖区间填多少

```
【澄清 3/3】期间是我们要的，还是他们有的
  A. 按档案的时间窗预填（推荐）—— 客户少一次决定。
     代价：要在签收时说明"这是我们要的，不是他们有的"，回收时逐表核对实际区间。
  B. 留空让客户填实际可得区间 —— 信息更真。
     代价：会拿到一堆参差不齐的区间，得再谈一轮才能对齐。
```

## 1 · 生成（M）

```bash
~/.local/bin/mmm app workbook data_request --workspace <工作区>
```

产出：一个 L3 一册，文件名是完整路径的短名（`Marketing-Paid-media-Digital.xlsx`，
截到 48 字符，撞名加后缀），外加 `00-response.xlsx` 和 `coverage.md`。
旧工作簿先删再建，所以那个目录永远反映当前的树，不会一轮轮堆积。

**工作簿是"被采纳的因子行 + 锁定的项目档案"的函数。** 要什么数据不是这里决定的，
是确认因子树时决定的；这里只把那些决定变成客户能填的文件。所以：
**不许手写工作簿，不许手改覆盖报告。**

## 2 · 每一册里有什么

**说明表（README）** —— 时间颗粒度、期间、按哪些维度报、"空白不等于零"那句话，
以及一张定义表：因子行 id、L4、指标、主/备选、**这个指标我们指的是什么**、单位、对接人。

> 平台承诺过给定义，代码里一个定义字段都没写，客户拿到的表上一个指标叫什么就是它的
> 全部说明。这张定义表是把那个承诺兑现了，**是要守住的地方，不是要拉齐的差异**。

**一个 L4 一张表** —— 表头是时间颗粒度、模型范围的维度名、该 L4 的每个指标
（主指标在前，备选加 `(alternate)` 后缀），再加 `Source system` 和 `Notes`。
第二行是标了"交回前删掉"的示例行。

**因子行 id 进了工作簿是有意的。** 数据回来时，靠它把一列重新挂回它当初被收集的那一行；
没有它就只能按指标名配，而指标名客户一定会改。

## 3 · 复核（A）

读 `coverage.md` 的元信息块：`acceptedDrivers` / `requested` / `missing` /
`orphanSheets` / `responseRequested`，以及 `counts.noUnit` / `counts.noOwner`。

生成时打出来的每一条警告都是真问题：

- **树里没有 `role: response` 的行** —— 这份需求没有被解释变量。**去修树，不要手加一张响应表。**
- **有被采纳的行没被请求** —— 那一行的 L3/L4 分组是空的或者写坏了。看那一行，不要看脚本。
- **有表一个指标都没有** —— 客户打开会看到一张没法填的表。

`missing` 或 `orphanSheets` 不为零、或者没有响应行，检查直接不过。**不许过，回去修树重建。**

## 4 · 交付前自查（C）

数出来的东西之外，还有两件只有读树才看得出来的事：

- **哪些行的维度比客户能报的更细** —— 只有全国数的序列被按地区要、只有月度的被按周要。
  这些行会空着回来，**现在谈比收数时谈便宜得多**。
- **哪些行的对接人是一个系统而不是一个人** —— 系统不会回邮件。

缺定义、缺单位、缺对接人的行，覆盖报告已经在「客户还没法动手的行」那一段逐行列好了。
这些字段本该在确认因子树和采纳访谈改动时就收齐——如果现在才发现缺，树已经在一道确认后面，
补它要走一次显式重开。**把这个代价说出来，让人在"重开补齐"和"带缺口发"之间选**，
不要替他选，更不要直接去改工作簿。

**不许为了让覆盖报告好看而增删或改名任何一个被请求的指标。** 那份需求就是确认时定下来的
东西；它错了，改法是改树，而改树会留下是谁改的主意。

## 5 · 交付

告诉编排层：**数据需求已生成，请验收 `data-request/build`。** 同时报四件事：
多少册多少个指标、什么颗粒度什么期间按哪些维度报、还有几行没有单位或对接人、
以及哪些要求你认为客户其实给不了。

**这四件事要在需求落进客户邮箱之前说出来** —— 这是客户会给这份东西的唯一一次注意力。
