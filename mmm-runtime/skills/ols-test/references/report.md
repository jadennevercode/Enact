# 步骤 report —— 建模报告（A）

```bash
~/.local/bin/mmm app report ols-test --workspace <工作区>
~/.local/bin/mmm app workbook scorecard --workspace <工作区> --card ols
```

第一条出 `artifacts/s2/ols-report.docx`（客户拿到手的那一份），
第二条出 `artifacts/s2/ols-scorecard.xlsx`（逐因子审阅表）。

**内容全部来自工作区里已有的四份文件**：建模方案、入模参数、拟合结果、因子裁决表。
这一步不算数、不判断、不补内容——文件里没有的就写「还没定」，不替它编一个。

## 八章，顺序是刻意的

| 章 | 回答什么 |
|---|---|
| 一 摘要 | 建了什么、五档建议各多少、口径边界 |
| 二 建模方案 | 用了哪些数据、切成几个模型、每个能识别几个驱动 |
| 三 入模参数 | 每项谁定的、为什么；哪些判据是固定的 |
| 四 拟合结果 | 逐模型对象的统计量、红旗、拟合失配 |
| 五 多次运行对比 | 跑了几次、为什么、采纳哪次 |
| 六 因子入模建议 | 五档建议 + 人的裁决 |
| 七 假设与局限 | 澄清登记、无可比区间的因子、方法边界 |
| 八 来源 | 读过哪些材料、多少字、有没有截断 |

用了哪些数据 → 按什么参数 → 跑出了什么 → 所以哪些因子该进模型。

## 三条必须出现在报告里的话

**没有单价时**：投资回报单位是「销量/花费」，与行业带不可比，本轮**没有做**投资回报的区间检查。
写清楚「这不是投资回报通过了，是这项检查没有跑」。

**有因子没有可比区间时**：那是「这项检查没跑」，不是「超出区间」，也不是「通过」。

**跑的是参考数据集时**：封面就要说，不能让它读起来像客户自己的数。

## 被弃用的运行也要出现

第五章列**全部**运行，采纳的和没采纳的都列，连同弃用理由。
只报被采纳的那一次，等于把这次采纳能不能被核对一起删掉。

采纳理由只有三类：修正了拟合失配、客户改了决定、修掉了口径或数据错误。
「拟合优度更高」「更贴合区间」不是理由——那是挑一次跑得好看的，
与被删掉的那套指标搜索是同一件事。

## 硬规矩

**每个数逐字抄自计算结果**：不四舍五入、不换单位、不心算、不重算。

**Word 和 Excel 都是渲染出来的视图，不要手改**。它们带着来源指纹，
改了下一次渲染就抹掉了；裁决要落在 `ols-scorecard.yaml` 里。

**缺件时报错，不降级**。没装 Node 或 docx 包时说清楚缺什么、怎么装——
一份「因为没装 Node 所以变成了 Markdown」的交付物，收件人不会知道它本该是什么样子。
`~/.local/bin/mmm doctor` 一次报清楚。
