# 步骤 review —— 逐因子判读与裁决（C + H）

```bash
~/.local/bin/mmm tool ols.scorecard --workspace <工作区>
~/.local/bin/mmm app workbook scorecard --workspace <工作区> --card ols
```

第一条写出 `artifacts/s2/ols-scorecard.yaml`（六块：meta / rows / factors / models /
summary / assumptions），第二条把它渲染成给客户审的 Excel（因子建议 · 模型概况 ·
评分卡明细 · 统计 · 说明五张表）。**Excel 是渲染出来的视图。** 客户在上面批注没问题——但要把他那一份**另存一个文件**发回来，
然后跑回写，不要直接改工作区里的那一份（下一次渲染会把它抹掉）：

```bash
~/.local/bin/mmm tool ols.factors-import --workspace <工作区> --from <客户发回来的那份>
```

它只读「人工判定」「备注」两列，其余全是算出来的。工作簿上盖着来源指纹，
**对不上就拒绝**——照一份旧工作簿回写，会把中间的改动往旧的方向悄悄盖掉。
**只有真的改过的行才算人工裁决**：判定和备注都与导出去时一样的行是没被动过，不是被审过。

写出 `artifacts/s2/ols-scorecard.yaml`——每个模型对象里每个入模因子一行，自动提名已预填。
照 `../templates/ols-scorecard.yaml` 填。

**这是一张存下来的裁决表，不是每次重新推导的结果。** 这就是整个设计：
拒绝会把指标排除，下一次拟合就没有它的记录，"树上没提到"会被读成"没有东西越界"，
指标就走回了模型。**一条拒绝之所以持续有效，是因为它被写下来了。**

## 状态分级（第一个命中即定）

| 状态 | 条件 | 含义 |
|---|---|---|
| 映射层未覆盖 | 在映射层被拒 | 上游数据覆盖问题：从来没有已发布的指标覆盖过这个因子 |
| 已淘汰 | 在质量 / 签核 / 统计 / 区间层被拒 | 对**已存在的数据**做出的筛选裁决 |
| 未进模型 | 未被淘汰但没进这次拟合 | 通常是自由度不够 |
| 无可比区间 | 进了模型但没有可比区间 | **诚实状态，不是通过** |
| 待裁决 | 投资回报**或**贡献度越界 | 进入逐行裁决 |
| 区间内 | 两者都在带内 | — |

**前两种必须分开**：一个是"上游没给数据"，一个是"对数据做了判断"。
混在一起会让一个数据稀疏的项目看起来像是模型把什么都扔了。

**不可复议：** 前三种状态不参与本步裁决——上一层已经裁过的事不许再摆出来当悬案。

## 因子表：客户审的是它

`rows` 是逐（模型对象 × 因子）的明细；`factors` 是**一因子一行、跨全部被采纳的运行**，
客户审的是后者。两者的分工：明细给要往下钻的人，因子表给做决定的人。

**只有无量纲的证据跨运行汇总**——入模率、符号一致性、显著率、最差灯色。
贡献度和投资回报**逐处列出，不取平均**：全国模型的 8% 和 EC 的 15%、TT 的 2%
回答的是不同问题，平均出来不表示任何东西。

**建议五态，裁决二态。**

| 建议 | 什么时候 |
|---|---|
| `include` | 符号一致（≥ 0.8）、多数对象显著、没有越界 |
| `conditional` | 符号在不同对象之间不一致——**必须写明它在哪些对象上成立** |
| `watch` | 越界但偏离 < 30%；或符号稳但多数不显著；或无带而判读存疑 |
| `exclude` | 红灯；或判读为不可信**且有可比区间佐证** |
| `insufficient` | 从来没进过任何一次被采纳的运行（自由度或共线） |

五态是为了能说出"它在这两个渠道成立、第三个不成立"——把这句话压成采纳/否决，
丢掉的正是唯一有用的部分。裁决仍然二选一，因为这是进模型输入表前的最后一关。

**无带时判读不能单独否决。** 判读为 `implausible` 但没有可比区间的，落 `watch` 交人逐条过目。
真实项目上曾经每一行都是无可比区间，于是"判读不可信"成了唯一还能否决的通路，
一个宣称自己不挑指标的步骤，实际上把每一次剔除都交给了模型一句话。
没有带就没有算出来的状态可以与判读并列——`review.md` 自己的边界写着"并列，永不取代"。

## AI 逐因子判读（C）

四选一 + ≤30 词理由：

| 判读 | 判据 |
|---|---|
| `consistent` | 结果对这个因子是可信的：在带内，或者出带但数字自身支持这个出带 |
| `questionable` | 出带；或在带内但系数很弱（`\|t\| < 2`）；或区间是远距离匹配来的 |
| `implausible` | 结果与这个因子可能的行为相矛盾：付费驱动系数为负、贡献远超其带、投资回报不可能为真 |
| `noBenchmark` | 没有带，只判系数的符号与显著性，并说明这一点 |

**AI 在这一步的边界：** 每个数都是上游算好的事实。
**可以引用，不许换个说法重述、不许改精度、不许产生新的。**
判定与算出来的状态**并列，永不取代它**。不许推荐动作，不许断言数字没显示的业务成因。
一次最多处理 30 行——把 200 个因子塞进一次请求既不可靠、失败了也救不回来。

无模型时按计算状态生成模板理由（出带 → questionable；带内但 `|t| < 2` → questionable；
无带 → noBenchmark；其余 → consistent）。**这一列永不留空、永不假装。**

## 自动提名怎么来的

```
红灯（越界且偏离 ≥ 30%）        → 否决，理由 = 越界说明 + "回流业务校验重审假设"
黄灯（越界但偏离 < 30%）        → 采纳，理由里注明"偏离不足 30%，这是复核不是剔除"
判读 = implausible              → 否决（即使没有带：无区间在算术上不可证伪，
                                  模型说这个系数不可信，那就是仅有的信号）
判读 = questionable             → 采纳（算术过了。把一句保留意见变成拒绝，
                                  会剔掉没有人决定要剔的变量）
无可比区间                      → 采纳（没有带可比，也没有任何东西与拟合矛盾）
其余                            → 采纳
```

## 呈现顺序

1. **按状态报计数** —— 区间内 · 黄灯 · 红灯 · 无可比区间 · 已被人钉住。
2. **拟合失配先讲。** 有对象基线占比 > 100% 或付费驱动反号时，**先摆这一段**：
   ```
   <对象> 的基线占比 <值>%，控制项吸收的销量超过了全部实际销量。
     A. 先减控制项重跑（推荐）—— 减少傅里叶阶数或关掉趋势。
     B. 按现状继续，逐行裁掉越界的指标。
        代价：治错了病——是拟合而不是数据在产生那些疯狂贡献，剔掉的是本来没问题的指标。
   ```
   **不要在这一段里提剔除指标当推荐项。**
3. **红灯行逐条**，按对象：拟合值、带、偏离百分比、以及最可能的解释。
   投资回报是带的十倍，通常是单位或口径问题，不是营销奇迹。红灯的候选处置见 `clarify.md` 第 4 条。
4. **黄灯行成组**：偏离都在 30% 以内，推荐保留，问一句要不要例外。
5. **无可比区间的行** —— 知识库对这个行业的这个因子没有先例。
   **那不是失败，也不是通行证**：说清楚你倾向哪一边、为什么。
   拿另一个行业的带来判是这套工具真出过的 bug。
6. **被留出的驱动**，重述成自由度或共线性限制，**不是判决**。
7. **每一个还没裁的行。** 离开时只能是采纳或否决。

成批采纳带内的行是合法的，而且要记下来：说清几条、哪几条。沉默不是决定。

## 三条合并规则

**人的裁决压过重拟合。** 重拟合刷新每个计算字段和自动提名；带"人裁决"标记的行保留人的处置与备注。

**被拒的行不许消失。** 只有被拒的行被延续；被采纳的行不再出现就随之消失
（那通常是它的渠道丢了数据，不该留成一条过期的采纳）。

**拒绝按模型对象记账。** 同一个因子可以在一个渠道越界、在另一个渠道正常。

## 收敛

保存一次拒绝会重新拟合，而判读是从**那次**拟合得出的。跑一遍之后交付物展示的是一个
被它自己的表格否决的模型；**再跑一遍它就稳定了**。稳定之前不要交验收。

## 收尾

写完之后告诉编排层：**"OLS 预验证已写好，请验收 `ols-test/review`。"**

**不记裁决、不流转状态。** 这一关一旦确认，上游的质量 / 统计 / 本步裁决就锁死；
要改上游必须先重开这一关。有红灯行时把回流选项一并摆出来——
**退回目标是业务校验与签核**，这是本阶段唯一一条跨交付物的回流边，回流原因必须记录。
