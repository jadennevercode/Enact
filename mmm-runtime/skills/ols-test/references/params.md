# 步骤 params —— 定变换与控制项参数（H）

```bash
~/.local/bin/mmm tool ols.propose --workspace <工作区>
```

写出 `artifacts/s2/ols-config.yaml`，照 `../templates/ols-config.yaml` 填。

## 参数分两档，这是本步的核心

| 档 | 谁能改 | 是什么 |
|---|---|---|
| **结构参数** | **客户可以改** | 每一条都是对生意的假设，客户比我们懂 |
| **固定判据** | **列出来给他看，不开放** | 每一条都是判定的尺子 |

**为什么判据不开放：** 被判的一方能调的判据就不再是判据。
显著性阈值一旦可以从 2.0 挪到 1.0，"这个系数显著"就不再表示任何东西。
**让客户看见有哪些线是不动的，比让他发现自己能动它要好。**
唯一例外是红灯线 `redDeviation`——30% 是个惯例不是定律，可以按项目挪，代价是写清楚为什么。

## 结构参数怎么跟客户说

不要念参数名，说它决定什么：

| 参数 | 跟客户说的话 |
|---|---|
| `adstock` | 这个渠道的钱投下去，多久还在起作用 |
| `saturation` / `hillHalf` | 投到多少之后，再加钱的效果开始变弱 |
| `trend` | 生意本身的长期涨跌，要不要单独扣掉 |
| `seasonality` / `fourierK` | 淡旺季要不要单独扣掉 |
| `pricePerUnit` | 一箱卖多少钱——**没有它，投资回报没法和行业带比** |

## 季节项默认是关的

**别照参数名想当然。** 默认 `seasonality: none`，理由记在引擎里：
34 个月的序列上，趋势 + 2 阶傅里叶是 5 个控制列，和大约 12 个驱动抢 34 个观测，
结果持续过度吸收——基线占比超过 100%（有一次到 250%）、付费驱动反号、
贡献度离所有行业带都远到区间检查失去意义。趋势保持开着：它只有一列，而增长中的市场确实需要它。

序列够长、付得起这个代价时再逐项目打开。**产出里写的是实际生效的值，不是文档里的值。**

## 谁定的要记下来

`params` 是引擎实际读的那一份；`paramDecisions` 只记"谁定的、为什么"。
**改参数要改 params**，`paramDecisions` 里对应那条同步标 `decidedBy: human` 并写理由。

**默认值可以不说话**——那正是默认值的用处。**被人挪过的数不行**：
一个没人解释得了的系数，日后没有任何办法追回它当初为什么是那样。

人改过的项在重新提议时保留，不会被默认值盖回去。

## 响应是销量而客户给不出单价时

照走，但**在交付里明说本轮不做投资回报的区间检查**，区间状态恒为「无区间」。
问题不在于不做，在于结果读起来像「投资回报通过了」，而那项检查根本没跑。
