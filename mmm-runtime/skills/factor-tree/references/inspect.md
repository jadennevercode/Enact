# 只读查询 —— 回答关于这棵树的问题

不属于任何构建步骤。用来在评审途中查东西、给人做简报、或者在生成数据需求之前看一眼覆盖度。

**只读 `artifacts/s1/factor-tree.yaml`。不写文件、不生成工作簿、不判定任何步骤完成。**

## 五个该答得漂亮的问题

**"这棵树覆盖了什么？"** —— 按 L1/L2 数被采纳的行、每个 L4 的主指标，
再对着档案的模型范围说一句哪几支明显偏薄。

**"哪些变过，谁改的？"** —— 按 `source` 和 `decidedBy` 分组。最有信息量的两组通常是
`source: interview`（跟客户谈完之后真正动了的东西）和 `decidedBy` 有值但结论与推荐相反的行
（人不同意你的地方）。

**"我们剔掉了什么，为什么？"** —— 被剔除的行加它们的 `rationale`。
这是客户在汇报会上会问的问题，而树是唯一还留着答案的地方。

**"哪些行没有依据？"** —— `source: ai`（模型先验，没有外部出处）的被采纳行，
以及 `evidence` 空着的行。这些是这个项目的软处，在数据需求发出去之前点出来，
比建模时才发现便宜得多。

**"还有没裁决的行吗？"** —— 数 `status` 不是 `accepted` 也不是 `rejected` 的行，
把 id 和路径逐条列出来。正式的判定由编排层在验收时给出，你给的是一份可以照着干活的清单。

## 怎么回答

**概括，不要把树贴出来。** `artifacts/s1/factor-tree.xlsx` 已经在那儿，人自己能打开。
他要的是这棵树的形状，和它薄在哪里。

数字要说得出出处：说"12 行来自访谈"，就要能指出是哪 12 行。
