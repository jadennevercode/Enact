# 步骤 · factor-tree/knowledge —— 把可用的行业知识召回出来

产出 `artifacts/s1/knowledge-package.md`：**这个项目能引用的行业先例**，
以及**什么没有行业先例**。它是下一步推导时唯一可以标 `source: template` 的依据来源。

**这一步不定骨架。** L1/L2 在上一步就随行业包（或客户上传的树）一起定下来了，
这里只是把它抄一遍备查。骨架不是这一步发明的，所以这一步也不需要人拍板。

**类型：C。** 召回是机器做的，判断"哪些召回结果与这个品牌真的相关"是你做的。

## 1 · 召回（M）

```bash
~/.local/bin/mmm script knowledge_recall <workspace> "L3/L4 与候选指标" --k 8
~/.local/bin/mmm script knowledge_recall <workspace> "品牌生意分析框架"
```

锚点是项目档案里的行业 L1–L3，**永远不是品牌名**——不锚定的召回会心平气和地把饮料的
骨架返给一个护肤品项目，而它在交付物里看起来完全合理。这条由脚本保证，不靠你记得。

问法要贴着下一步真正要用的东西问：这个 L2 下面通常有哪些 L3、某一类杠杆常用什么指标、
这个品类的生意通常怎么拆。**一次问一件事**，一个把三件事塞进去的问句，命中的是"什么都沾一点"。

**召回为空是正常结果，不是故障。** 空了就做三件事：

1. `knowledgeRecall: none` 写进信息块；
2. 在正文里说一遍：这个项目没有可引用的行业先例；
3. 告诉下一步：**没有一行可以标 `source: template`**。

**不要因为形状看着能复用，就去搬别的行业的包。** 脚本按目录锚点做了隔离，
你也不要绕过它——一棵饮料树套在护肤品牌上，足够像到能过确认，
也足够错到让模型建的是另一门生意。

## 2 · 挑出真正相关的（C）

召回回来的是候选，不是结论。逐条判断它跟**这个品牌**有没有关系，
留下的写进知识包并注明出自哪个包、哪个文件、哪一段；判掉的也写一句为什么判掉。

判断的标准只有一条：**下一步推导时，你会不会真的引用它。** 不会引用的条目留在包里，
只会让下一个人以为这棵树背后的依据比实际更厚。

## 3 · 抄一遍锁定的 L1/L2（M）

从上一步定下的基线里把 L1/L2 抄进知识包，注明它来自哪里（行业包 / 客户上传的树）。
这不是重新决定，是让推导那一步有一个单一的地方去读骨架。

**响应指标不在骨架里占位置。** 它在树里是单独一行，不挂在任何 L1–L4 下面——
骨架只管因子，不要为 Y 单开一支 L1。

## 4 · 客户自有框架怎么落到四层（C）

客户自己的框架通常只有两层：一组标题，下面挂一批子因子。映射方式是固定的，
免得同一份材料长出两棵形状不同的树：

| 客户框架里的 | 落在树的哪一层 |
|---|---|
| 组标题（"营销投入"） | **L1** |
| —— | **L2**：L1 内部的结构性切分 |
| 子因子（"社交/KOL"） | **L3** |
| —— | **L4**：子因子里面的具体杠杆 |

**客户的子因子不是 L2**，它们到 L3 落地，标 `source: upload`，在确认时接受裁决。

## 5 · 写知识包（M）

```markdown
---
step: factor-tree/knowledge
skill: factor-tree
generated: "2026-08-08T11:05:00+08:00"
grounding:
  - { path: "artifacts/s1/materials-index.md", chars: 2100, truncated: false }
  - { path: "inputs/industry-reference/competitor-benchmark-2025.pdf", chars: 38200, truncated: true }
knowledgeRecall: "kb:food-bev/beverage@v2"
recallHits: 6
counts: { l1: 4, l2: 8 }
---

# 行业知识包 —— 食品饮料 / 饮料 / 功能饮料

## 召回到什么

| 出自 | 条目 | 下一步打算怎么用 |
|---|---|---|
| food-bev/beverage · factor-tree.yaml | 消费者需求驱动 › 品牌广告/内容种草 › 品牌传播 | L3「品牌传播」下的 L4 与候选指标全量起底 |
| factor-tree-skeleton · levels & rules | 四层的定义 | 推导时判断某一条该落 L3 还是 L4 |

判掉的：`interview.yaml` 的分层题库（那是访谈那一步的事，不是因子树的依据）。

## L1 / L2 骨架（来自行业包 food-bev/beverage，上一步已定）

| L1 | L2 | 覆盖什么 |
|---|---|---|
| 生意基本盘 | 外部因素 | 品类趋势、宏观、竞争格局 |
| 消费者需求驱动 | 品牌广告/内容种草 | 品牌传播、社媒种草 |

## 品牌生意分析框架

这个品类的生意通常怎么拆，这个项目采用哪一种拆法，以及为什么。

## 什么没有行业先例

- KOL 分层口径：只来自客户自己的材料，没有行业惯例可依。
```

**「什么没有行业先例」这一节是必填的。** 它是知识包和一段自信的猜测之间的唯一区别，
也是访谈提纲该瞄准的地方。

## 6 · 交验收

验收时会查：知识包的信息块完整、取材没有超出白名单。这一步不需要人拍板。

做完说一句：**因子树的知识包已装配好，请验收 `factor-tree/knowledge`。**

## 一条会传到下一步的硬规矩

`knowledgeRecall: none` 时，推导那一步**不许有任何一行标成 `source: template`**。
标了就是宣称一个不存在的行业先例，而下一个人会比该有的程度更信它。
没有先例支撑但你确实认为该有的因子，走 `source: ai`（模型先验）或 `websearch`，
两者都要按 `derive.md` 的规矩留痕。

`artifacts/s1/project-profile.yaml`、`artifacts/s1/materials-index.md`、
`inputs/industry-reference/**`、`inputs/client-factor-tree/**`、行业知识召回。
