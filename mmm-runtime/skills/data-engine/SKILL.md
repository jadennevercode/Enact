# 发布数据集

客户发来的是一堆表格，模型要的是一张规定形状的长表。这个 Skill 是中间那段路，
**只产出这一份交付物**。

它有一个不能倒过来的次序：**先声明形状，数据才到**。看过数据之后才写的结构不可能失败，
不可能失败的检查是装饰。

你写的是**清洗脚本，不是数据行**。你看的是列画像——列名、类型、空值率、去重个数、
高频取值——**永远不看行**。这既省上下文，也堵住了一个洞：发布出来的表只可能来自
一次工具运行，跑的是一份写在磁盘上、人能读能否决的脚本。

**开始前：** 读 `../../shared/conventions.md` 定位工作区。数据阶段要用引擎，
不确定就先跑 `~/.local/bin/mmm doctor`。

## 第 0 步 · 澄清（先读完再问）

先读完项目档案、因子树、数据需求与验收，以及 `inputs/data/` 里已经到的东西。
**上面已经写了的一个字都不要问。**

| 澄清点 | 什么时候必须问 | 推荐 |
|---|---|---|
| 时间窗口以哪边为准 | 交付文件的覆盖期比档案锁定的窗口短 | 以档案为准，窗口外的行清洗时截掉并如实报出 |
| 哪些取值清单是封闭的 | 每次都要确认一遍 | 渠道类型与指标角色封闭，品牌与省份先开放 |
| 主数据对不齐时怎么办 | 交付里出现名册上没有的名称 | 填空值并作为未映射值上报，绝不按最像的名字硬套 |
| 对账用哪一列做数值基准 | 每批交付都要定 | 每批都指定；宽表要先约定按哪几列求和 |
| 空渠道是不是全国 | 每次都要确认一遍 | 是。空即全国，共享进每一个模型对象 |
| 因子树没要过的指标怎么处理 | 交付里出现树没声明的指标 | 照常发布，列在一旁，由因子树去采纳或驳回 |

答案写进变更账本。**问不到人时**按推荐走，并在产出物里标 `assumed: true` 加理由。

## 构建步骤

| # | 步骤 | 类型 | 做什么 | 详细 |
|---|---|---|---|---|
| 1 | `schema` | C→H | 起草目标表结构与取值范围，人拍板锁定 | `references/schema.md` |
| 2 | `intake` | H | 客户按数据需求交付文件，落进本项目的数据目录 | `references/intake.md` |
| 3 | `clean` | C | 每批交付：抽取 → 列画像 → 起草清洗脚本 → 沙箱执行 → 查形状 → 对数量 | `references/clean.md` |
| 4 | `publish` | H | 合成长表、把每个指标挂回因子行、登记数据字典，人拍板发布 | `references/publish.md` |

一批交付通常不是一个表。真实规模的参照：一次交付约 37 个数据源、约 160 张来源表页、
约 2.4 万行长表。**"一个 Excel 一批"这个假设会低估一个数量级。**

做完任何一步，交给编排层验收：「发布数据集的 X 已写好，请验收 published-dataset/X」。

## 硬规矩

**空渠道是全国，不是缺失。** 全国统一买的媒体要共享进每一个模型对象。给它安一个渠道，
就是分渠道建模把全国级媒体整块删掉的那个原因。

**没声明过的取值必须活着走到检查那一步。** 原始值用 `{{enum:<取值清单>:<原始列>}}` 映射，
它的 `ELSE` **有意保留原值**。把未知值映射成默认值或空值，藏起来的正好是必须被看见的东西。

**只有已采纳的映射条目才会生效。** 待定条目是惰性的——没人复核过的猜测不许进数据。

**因子树没要过的指标照样发布。** 在清洗里丢掉它们，等于藏起客户真实交付的数据。
它们发布成待认领的指标，列在一旁，由因子树采纳或驳回。**这个 Skill 不写因子树。**

**没通过形状检查的交付一律不进长表。** 不发布"大部分对了"，不开单子留着以后处理。

**对不了账就是没对上账。** 不指定数值基准列时，数值合计根本没有比对过——
那不叫通过，那叫没查。这是唯一能抓住「每列都合法、却少了三分之一数据」的检查。

**空结果是发现。** 一条返回零行的脚本、一份解析后什么都没有的交付、一个整列全空的字段，
都要写下来。看起来像成功的空结果比失败更糟，因为里面没有任何可以反对的东西。

## 取材范围

| 步骤 | 只能读 |
|---|---|
| schema | `metadata/schema/**`、项目档案 |
| intake | 客户交付的数据目录 |
| clean | 列画像、`metadata/schema/**`、因子树、颗粒度声明 |
| publish | 每批交付的形状检查结果、发布清单 |

**永远不读数据行。** 你的依据是列画像。

## 产出物与模板

模板在 `templates/`，照着填，不要自创结构：

| 产出 | 模板 |
|---|---|
| `metadata/schema/target-schema.yaml` | `templates/target-schema.yaml` |
| `metadata/schema/enums/<名字>.yaml` | `templates/enum.yaml` |
| `data/clean/<交付>/clean.sql` | `templates/clean.sql` |
| `data/clean/<交付>/asset.yaml` | `templates/asset.yaml` |
| `metadata/data-dictionary.yaml` | `templates/data-dictionary.yaml` |

长表、形状检查、对账、发布清单、归属清单都是工具写的，**你不手写其中任何一个数字**。

## 说话的规矩

1. 先说结论，再说依据，不铺垫。
2. 只说业务语言：说「确认」「检查项」「交付物」「数据来源」，不说 gate、predicate、artifact。
3. 每步三句话内交代：做了什么 / 结果是什么 / 需要你什么。
4. 要人拍板时永远给选择题：候选 + 推荐 + 每项后果，不给开放式提问。
5. 数字要报出处。说不出出处的数字就不说。
6. 拿不准就问。"大致""可能""建议进一步确认"通常是该问没问留下的痕迹。
