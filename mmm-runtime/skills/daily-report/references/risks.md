# 风险，两类

混在一起报，两类都会被跳过。它们要人做的事根本不是同一件。

## 机制性 —— 这套流程自己出的问题

六项，由 `state.py` 的 `problems()` 算出来，和 `/mmm:status` 的「问题」段是**同一份代码**，
所以两处永远说同一件事。

| 说的是 | 意味着 |
|---|---|
| 某份产出物只读了材料的一部分 | 它是基于一份文档的片段做出来的，拍板的人有权知道 |
| 背后没有行业先例（召回为空） | 该有知识包支撑的地方没有，结论只有本项目的依据 |
| 因子树一行没剔除 / 访谈零建议 | 一次什么都没否掉的审查，通常是没人真看 |
| **证据在确认之后又被改过** | **最严重的一条**：人批的那份和现在盘上这份不是同一份 |
| 记录为已完成，但检查现在不过 | 记录声称完成，判定式对着磁盘算出来不过 |
| 变更账本是空的 | 项目收尾时没有任何东西能沉淀进知识库 |

条数多的时候按类归并着说，不要逐条朗读。一个刚从 git 拉下来的工作区会因为文件时间戳
全被重写而报出一片"证据被改过"——**这种情况要说出来**，不要当成真事故，也不要因此
把这一整段吞掉。

## 业务性 —— 这门生意和这次交付的问题

每一条都必须挂着一个文件路径，说不出出处的风险就不报。脚本给的每条都带
`见 <路径>`，照抄。

| 风险 | 为什么它是风险 | 出处 |
|---|---|---|
| N 个因子最终没进模型 | 因子树当初放它们进来是有业务理由的；交付时必须说明结论不覆盖它们 | `artifacts/s2/funnel.yaml` · `missingFactors` |
| 同一条原因一次剔掉一批 | 那是一处供数缺口，对应一通电话，不是一批独立判断 | `funnel.yaml` · `layers[].dropped` |
| N 条口径是替客户预设的 | 客户一旦推翻，档案之后的每一层都要重做 | `project-profile.yaml` · `assumptions[].assumed` |
| N 个口径问题还没答 | 悬着的问题在下游变成返工，越晚答越贵 | `project-profile.yaml` · `openQuestions` |
| 模型范围超出建议规模 | 范围越大每个格子样本越少，估计越不稳 | `project-profile.yaml` · `scopeAdvisories` |
| 组合未逐条声明 | 轴的叉乘不等于真要建的格子，下游只能猜 | `project-profile.yaml` · `scopeRows` |
| 客户明确否掉了 N 个指标 | 被后面每一层继承，永远不再进模型 | `artifacts/s2/signoffs.yaml` |
| N 个指标落在边缘分值 | 不自动放行也不自动弃用，卡在这儿下游开不了工 | `artifacts/s2/quality-scorecard.yaml` |
| 引擎没装在这台机器上 | 数据阶段一步都跑不了。**这是阻塞，不是降级** | `scripts/doctor.py` |
| 数据需求签收 N 天还没到数 | 整个数据阶段停在等客户，不是停在我们 | `state/decisions.log` |

## 报的顺序

业务性在前，机制性在后。理由是它们的读者不同：业务性风险要么改交付说明、要么打电话给客户，
是项目负责人的事；机制性问题是这套流程内部的账，是做活的人自己收拾的。

一条都没有的时候两边都要明说。**"六项都查过了，没有发现问题"** 只有在脚本原样这么输出时
才能这么讲——自己替它下这个结论，就是把这一整段废掉。
