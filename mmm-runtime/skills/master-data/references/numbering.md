# 步骤 assemble · 编号（M）

**这是模型输入相对上游数据集唯一的新增物。** 没有它，这张表只是上游数据集的一个子集，
建模阶段的贡献分解只能靠指标名字符串回溯。

编号由 `master.assemble` / `master.funnel` 生成，落在长表末三列与选择快照里。**不手写。**

## 三列

| 列 | 形式 | 示例 | 约束 |
|---|---|---|---|
| `Variable` | 英文机器名 | `Digital_Display_Impressions` | 全表唯一 |
| `Variable no.` | 整数 | `1`、`32` | 一个变量一个号 |
| `Metric no.` | `<变量编号>.<序号>` | `1.1` | 同一变量下可挂多个指标 |

## 分组与顺序

**默认按 L4 因子分组**（澄清点 2 可改）：一个 L4 一个变量编号，它名下每个入模指标一个指标编号。
这样贡献分解能直接回溯到具体的 L4 因子，而那正是编号存在的理由。

顺序是确定性的，重跑不会换号：

```
响应排第一（变量编号 1），其余按 L1 → L2 → L3 → L4 → 指标名排序
```

## 机器名怎么来的

由因子路径（L4 + 指标）生成：非字母数字的部分切开，各段首字母大写，用下划线连接。
**全中文因而生成不出可读名字的，落到 `Var<变量编号>`。**
把中文音译成英文既不是客户的说法也不是机器的说法，所以不做。

**人指定的名字当前引擎不支持。** 要客户自己命名时，把名字记进项目的口径备忘，
并在交付时说明"表上的机器名是自动生成的，客户命名待引擎支持"。**不要假装它已经生效。**

## 两级还是三级

真实交付物里出现过 `1.1` 和 `32.1.1` 两种深度。**本 runtime 目前只产出两级。**
第三级要等到"一个变量下的指标本身还要再分组"才有意义，而这条流程还产不出那种结构。
需要三级时，先说清楚第三级分的是什么，作为一次显式的扩展来做。

## 编号一旦发出去就改不动

它是建模阶段的引用键。所以：

- **不要在重跑之间改分组依据。** 改了，同一个指标会换号，而建模那边的引用还指着旧号。
- 分组依据写进选择快照，锁定时一起冻结。
- 新增一个指标会往它所属变量的末尾追加一个指标编号，不重排已有的号。

## 校验

- 每个已采纳指标恰好有一个变量编号和一个指标编号，**响应也有**。
- 变量编号在同一个 L4 内一致；指标编号全表唯一。
- 长表里每一行都有这三列的值。空值意味着这一行的指标不在已采纳集合里——
  那它本来就不该出现在长表里，是过滤出了问题。
