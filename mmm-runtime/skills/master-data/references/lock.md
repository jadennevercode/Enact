# 步骤 lock —— 锁定模型输入（H）

整个 runtime 的最后一关。**锁定的不是一个中间产物，是建模将要训练在其上的那张表。**

**取材范围：** `artifacts/s2/master-data.md`、`artifacts/s2/funnel.yaml`。
没有新材料——锁的是装配那一步产出的东西。

## 锁定要冻结快照

只记一条批准不算锁。**已解析的选择必须一起冻结成快照**：响应变量、变量集、排除集、
变换参数、以及建模编号的分组依据。快照写在 `funnel.yaml` 的 `lockedSelection` 段里，
由工具生成，建模阶段读它。

不冻结的后果很具体：上游任何一次重跑都会重新解析这些东西，
于是建模训练在一张与人签过字的表**不同**的表上，而从表面上看不出来。

## 呈现之前先自查

1. **五个归宿之和 = 因子树的活跃行数。** 对不上是收口的 bug，不是批准的理由——报告并停下。
2. **响应在已采纳集合里。** 没有因变量的模型输入，整个交付作废。
3. **表描述的指标集 = 拟合实际用的指标集。** 这就是这一步存在的意义。
4. **快照非空。** 空的快照等于没锁。

任何一条不过，重跑装配那一步，**不要绕过去解释**。

## 呈现顺序

1. **要定的是什么** —— 锁定这份模型输入吗？因子树当初列出的每个因子现在都有了归宿。
2. **依据** —— 漏斗表：五个归宿各自的计数，以及它们相加等于的那个树总数。
3. **损失发生在哪** —— 按层顺序（映射 / 质量 / 签核 / 统计 / 变量选择 / 区间检验）报每层掉了几条。
   这是唯一一张看得出这一阶段是筛选还是清剿的视图。
4. **每一个"从未拿到数据"的因子，逐条列出。** 这些不是模型的选择，是收数的缺口，
   而这里是最后一个便宜的发现时机。客户在最终汇报上第一次看到这张清单，是一场糟糕的会。
5. **每一个"部分采用"的因子**，连同留下它的对象和没留它的对象。模型之间不一致是正常的，值得一句话。
6. **因子级预警**：模型将要对哪几块生意失语。这一段单独列，不要混在漏斗里。
7. **快照里冻结了什么** —— 响应、变量数、排除条数、参数、编号分组依据。
8. **接下来会怎样** —— **这是交付终点**：建模与报告不在范围内。锁定之后要改任何上游，
   必须先重开这一关；不重开就改上游会被拒。

## 两个候选

| 候选 | 后果 |
|---|---|
| `lock` **锁定模型输入**（推荐） | 建模基于这张表；上游全部冻结 |
| `rework` **重审变量** | **退回到 OLS 预验证**，回流原因必须记录 |

有"从未拿到数据"的因子时，第三条路是**回流业务理解找替代指标**；
选择知情锁定的话，预警必须进交付说明。

## 收尾

写完之后告诉编排层：**"模型输入已写好，请验收 `model-input/lock`。"**

**不记裁决、不流转状态、不代人锁定。**

锁定之后，改任何装配所依据的东西——映射、两张打分表、签核、区间裁决——都要先重开这一关，
把后面的步骤退回重跑。那很贵，而且是故意的：一份锁定之后又悄悄变过的模型输入，
会让所有基于它算出来的结果都在描述一个已经不存在的东西。

交出门的工作簿是计算出来的，**从不手改，要改就重新导出**。
