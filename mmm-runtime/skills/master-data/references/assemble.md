# 步骤 assemble —— 装配主数据表与漏斗（M + A）

```bash
~/.local/bin/mmm tool ledger.derive   --workspace <工作区>
~/.local/bin/mmm tool master.assemble --workspace <工作区>
~/.local/bin/mmm tool master.funnel   --workspace <工作区>
~/.local/bin/mmm tool export.xlsx     --workspace <工作区>
```

| 路径 | 是什么 |
|---|---|
| `data/derived/master/<对象>.csv` | 已采纳的宽表，一个模型对象一个文件 |
| `artifacts/s2/funnel.yaml` | 漏斗 + 因子树收口 + 因子级预警 + 选择快照 |
| `artifacts/s2/model-input.xlsx` | 交出门的工作簿，**从不手工拼、从不手改** |
| `artifacts/s2/master-data.md` | 读法，声明它读的是哪份计算结果 |

## 六层账本（结算顺序，不可乱）

| 顺序 | 层 | 产出它的交付物 | 否决的语义 |
|---|---|---|---|
| 1 | 映射 | 因子映射 | 没有已发布的指标覆盖这个因子 |
| 2 | 质量 | 数据质量评分 | 数据本身不可用 |
| 3 | 签核 | 业务校验与签核 | 客户明确否决 |
| 4 | 统计 | 统计检验 | 指标对建模不适用 |
| 5 | 变量选择 | OLS 预验证 | 没进这次拟合（自由度 / 未勾选） |
| 6 | 区间检验 | OLS 预验证 | 投资回报或贡献度越界且被裁决拒绝 |

**任一层的否决被之后每一层继承，不可逆流。** 主键是（归一化 L4, 归一化指标），按模型对象记账，
缺省对象表示对所有模型生效。质量层的"待定"与统计层的"待复核"在人裁决前算暂定，不算最终否决。

## 已采纳集合是唯一的答案

"模型建在什么之上"只有一个来源，颗粒度参考表、长表、导出、收口表全都问它，**没有一个自己重推**。

这不是洁癖，是修过的一个真 bug：三个消费方各自回答同一个问题然后互相矛盾。
颗粒度表在错误的键空间里连接——拿因子行声明的（L4, 指标）去匹配数据的（L4, 指标名），
而这两者恰恰在有人做过配对时才不同，也就是有映射存在的时候。

**响应必须显式放行。** 它没有账本行（没有任何一层裁决过它，因为它就是驱动要解释的东西），
按已采纳键去过滤会把因变量本身滤掉——在演练案例上是 2939 行里静静少了 374 行。

## 逐对象取行

每个模型对象用**与拟合完全相同的行选择规则**取行。

**不要按"品牌 + 渠道类型"切。** 那样看起来等价，实际会丢掉每一条全国行（渠道为空）
和每一条竞品行（这个对象不点名的品牌），而那恰好是模型真正拟合用的共享行。
某个渠道的表因此曾经只剩下一列响应。

## 三类表

**表 1 · 模型颗粒度参考表**（8 列）

`生意因子-Level 1 | Level 2 | Level 3 | 生意影响因子-Level 4 | 指标选择 | 角色 | 渠道 | 区域`

- `渠道`：该指标原始行里出现的渠道类型集合；没有具体渠道类型（全国 / 全渠道数据）时写 `全渠道`
- `区域`：省份组别集合；只有全国口径时写 `National`
- `角色`：`response` 或 `driver`。**响应必须出现在这张表上**——它不在因子树里
  （因子解释它，不声明它），漏掉它这张表就在描述一个它并不包含的模型输入
- **空白的渠道 / 区域 = 没有被选进模型**，这是约定，不是缺失

**表 2 · 长表**（22 列）

```
Task name | 品牌 | 省份组别 | 省份 | 渠道类型 | 渠道 | 年 | 月 | 数据源 |
数据类型Level1..Level8 | METRICS类型 | METRICS | VALUE |
Variable | Variable no. | Metric no.
```

末三列是这一步的新增物，见 `numbering.md`。数据类型 Level1–4 对应因子树 L1–L4，
**与因子树严格一致**；Level5–8 是该 L4 的下钻颗粒度，没有就填 `NA`。
**每行 = 一个（维度组合, 指标, 值）。维度对不齐就填 `NA`，不删行、不合并。**

**表 3+ · 每个模型对象一张宽表**

一行一期，一列一个已采纳指标，**响应列排第一**，其余按名称排序，缺口留空**不补零**，数值 4 位小数。
表名 = 模型对象标签，≤31 字符，去掉 `[]:*?/\`，重名加后缀。

## 汇总规则

比例类 / 覆盖率类跨地区**取平均**，花费与销量**求和**。
一个指标在一个期间内有多行（下钻残差路径）时，按它自己的汇总规则合并。
**对比例类求和会造出一个没有意义的数**——这条在统计检验、业务校验、模型输入三处都成立。

## 上限与截断

| 限制 | 值 | 处置 |
|---|---|---|
| 长表展示上限 | 5000 行 | 超出**明确标注**，导出时不设上限 |
| 宽表展示上限 | 400 行 × 60 列 | 超出**明确标注，不做无声截断** |

## 漏斗

每层"进来多少 / 拒了多少 / 活下来多少 / 拒的是哪几条"，既有跨对象合计也有逐对象拆分——
**同一个指标可以在一个渠道死在统计层，在另一个渠道活到最后。**

## 因子树收口

漏斗按数据交付了什么记账；收口表按因子树想要什么记账，**两者都要有**。

| 归宿 | 含义 |
|---|---|
| `adopted` | 该行的至少一个供给数据键被采纳进模型 |
| `partial` | 部分模型对象采纳，部分否决 |
| `rejected` | 数据存在但被某一层裁决否掉 |
| `notSupplied` | **从来没有已发布的数据覆盖过这一行** |
| `notModeled` | 有数据但没进任何模型（自由度不够，或与兄弟因子共用一个数据键、所有权归了兄弟） |

**五个数之和必须等于因子树的活跃行数。对不上就报告并停下，不猜。**

## 因子级预警

某个 L4 的全部候选都没能进模型时，`missingFactors` 会列出来。
这不是漏斗里的一条剔除记录——**漏斗列的是指标，这张表列的是模型将要对之失语的生意板块**。
它要进交付说明，也要在锁定时单独摆一段。

## 红旗，必须硬校验

- **响应变量不在已采纳集合里** → 表里没有因变量，整个交付作废
- **收口的五个归宿之和 ≠ 因子树活跃行数** → 报告并停下
- **模型输入表描述的指标集 ≠ 拟合实际用的指标集** → 这就是本步存在的意义
- **全国行按"品牌 + 渠道类型"切** → 会丢掉全国行与竞品行
- **超出展示上限** → 标注，不静默截断
- **某因子全部候选不达标** → 交付说明预警
