# data-quality/review —— 处置边缘分值、弃用项与没收到的数据（H）

**人复核的是例外，不是四百行。** 自动判读已经预填在每一行上：满分的那一档批量接受、
上游已否的那一档只是列在表上，需要人的只有中间那一档和"数据没到"那一档。
四百行的评分表，真正要看的通常是十几行。

## 呈现顺序

1. **按档计数** —— 多少行自动通过、多少行需要你决定、多少行数据没到、
   多少行上游已否。另有多少孤儿。一行说完。
2. **阻断型失败点名** —— 是哪个子项、算出了什么数。
   说"2024 年缺 9 个月"，不要说"完整性偏低"。
3. **「一条数据都没到」的行单列一节** —— 它们不是 0 分，不要混进弃用清单。
4. **边缘行逐条列出，总分最低的在前** —— L4、指标、总分、弱在哪个维度、
   驱动它的那句子项说明。一屏 12 条是合理上限；
   **如果有 80 条，按失败的子项分组**——80 行栽在同一个子项上是一场对话，不是八十场。
5. **每条边缘行给出你的建议，以及建议基于什么。**
6. **后果** —— 后面只画活下来的；这里判弃用的会被业务校验、统计检验、
   OLS 预验证、模型输入一路继承，不再重新打分。

## 每条边缘行的候选处置

| 处置 | 什么情况 | 落到哪 |
|---|---|---|
| `keep` | 带保留意见入模 | 理由写进 `note` |
| `drop` | 弃用 | 后面每一层继承 |
| 回上游 | 判据看起来不对 | 回发布数据集重清洗，或回数据需求与验收追交付 |

**只有 `keep` 和 `drop` 两个值。** `review` / `flag` / `pending` 不是裁决——
它们对下游每一层读起来是"保留了"，对人读起来是"还没解决"，两边最差的组合。
保留意见写进说明，台账上仍然是 `keep`。

**人改的是处置，不是分数。** 分是算出来的。觉得分算错了，那是判据或输入有问题，
应该回上游修，而不是在表上盖掉一个数——检查项会逐行比对，盖不过去。

## 「一条数据都没到」的行 —— 这是另一件事

`dataStatus: no-data` 的行没有分，也不该有分。候选：

① 回数据需求与验收追这次交付（推荐，数据在路上）
② 本轮不建这个指标 → `drop`，并在因子树上登记
③ 换一个指标 → 回因子树，再回数据需求重新收数

**0 分找数据 Owner，没数据找交付。** 这两句话对应两个不同的人，
把它们放进同一张清单，就会有一半的行送错桌子。

## 总分为 0 的行

候选：① 确认弃用 ② 认为判据有问题 → 回上游查。

第二条不是客套：粗于月度的常见成因是清洗时把月份丢了，而不是客户真的只给了季度；
大面积的完整性 0 分常常是档案时间窗与实际到数的口径没对齐，而不是数据真的稀烂。

## 某个因子全灭 —— 又是另一件事

某个 L4 下**全部**指标总分都是 0，或**全部**都没有数据时，评分表里会有一条高优先级预警，
两类的 `routeTo` 不一样：

| 类型 | 候选 | 上报给谁 |
|---|---|---|
| 全部 0 分 | ① 找替代数据源 ② 接受该因子本轮不建模，回因子树登记 ③ 换指标重新收数 | 业务侧 + 客户 |
| 全部没数据 | ① 追这次交付 ② 该因子本轮不建模 | 数据需求与验收 |

呈现时**单列一节**，不要混在弃用清单里。三个指标死一个和三个全死，处置对象都不一样。

## 批量接受是合法的

"接受 312 行满分的行"是人有权做的一个真实决定，记成一次动作 + 条数。

不合法的是：一行走到确认面前处置还是空的，因为没人看过——那是沉默，检查项会点名拒绝它。

**如果复核者一行都没否，在关这道确认之前明说出来。**
一场什么都没否掉的复核，通常是一场没人读的复核。

## 视图：Excel

```bash
~/.local/bin/mmm app workbook scorecard -w <工作区> --card quality
```

产出 `artifacts/s2/quality-scorecard.xlsx`，四张表：评分卡 · 统计 · 说明。
**没人手改它**——它带着评分表的指纹，手改之后 `workbook_current` 会判它过期。
数字一律来自评分表，不许重打。

表上有两处渲染是硬要求：

- **`computed: false` 的子项渲染成「未校验」**，不能渲染成 1。
  "没查"和"查了没问题"在一张要签字的表上不能长得一样。
- **没有分的行（`no-data` / `inherited-drop`）四维分与总分渲染成「—」**，不能渲染成 0，
  也不能留空——留空读起来像漏填，0 读起来像判死。

## 签核

签核问题的原文：

> 哪些指标可用？这里的一次弃用会被业务校验、统计检验、OLS 预验证和模型输入继承——
> 该指标不会被重新评分，也永远到不了模型。标「没有数据」的那些不是被判死，是还没到。

交给编排层验收：「数据质量评分已复核完，请验收 data-quality/review」。
**你不自己关这道确认，也不自己记裁决。**
