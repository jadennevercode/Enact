# data-quality/score —— 四个维度各跑一遍，再卷成总分（M + A）

分是工具算的，你**誊抄**。

```bash
~/.local/bin/mmm tool quality.consistency   --workspace <工作区>
~/.local/bin/mmm tool quality.accuracy      --workspace <工作区>
~/.local/bin/mmm tool quality.completeness  --workspace <工作区>
~/.local/bin/mmm tool quality.granularity   --workspace <工作区>
~/.local/bin/mmm tool quality.scorecard     --workspace <工作区>
```

前四个各写一份维度结果，最后一个读这四份卷成 `data/derived/quality-evidence.json`。
**顺序不能反**：四份缺一份，卷积工具会失败并告诉你缺哪一个。
四份结果带同一个行集指纹，对不上也会失败——混着卷积出来的评分表内部自洽、
但每个数都错，读的时候看不出来。

工具卡见 `tools/catalog/quality.<维度>.yaml` 与 `quality.scorecard.yaml`。

## 行从哪来

**因子树里 `status: accepted` 的每一行**，一行一个 `(L1×L2×L3×L4×指标)`，
按 (L4, 指标) 去长表里找对应的序列，逐行标状态：

| dataStatus | 含义 | 四维分 | 谁来处理 |
|---|---|---|---|
| `scored` | 长表里有这条序列，已打分 | 有分 | 按判读走 |
| `no-data` | 树上要了，一条数据都没到 | **留空，不是 0** | 回数据需求与验收追交付 |
| `inherited-drop` | 因子映射层已判"不做" | 留空 | 继承，不再打分 |

数据里有、树上没要过的指标是**孤儿**：不进表，只记 `orphanCount` 并在呈现时说一句。

## 四个维度、十个子项

**一致性（3 项）**

| 子项 | 1 分 | 0.5 分 | 0 分 | 阻断 |
|---|---|---|---|---|
| 维度一致性 | 全部行统一在一个单位上 | 不在主单位上的行 ≤10% | >10%，或与因子树声明的单位不一致 | 有单位列时**是** |
| 时间一致性 | 全程统一的月度网格 | 偏离主导网格 ≤10% | 偏离 >10%，或粗于月度 | **是** |
| 口径一致性 | 全程单一数据源 | 换过源且同比 ≤30% | 换过源且同比 >30% | **是** |

**准确性（2 项）**

| 子项 | 1 分 | 0.5 分 | 0 分 | 阻断 |
|---|---|---|---|---|
| 数值准确性 | 非法值 <5% | 5%–10% | >10% | **是** |
| 业务准确性 | 与登记合计偏差 <5% | 5%–10% | >10% | 有登记时**是** |

**完整性（2 项）**

| 子项 | 1 分 | 0.5 分 | 0 分 | 阻断 |
|---|---|---|---|---|
| 字段完整性 | 响应序列，或字段齐全 | 该 L4 有花费但没有任何表现指标 | 该 L4 名下没有任何范围内字段 | **是** |
| 数据完整性 | 无缺失 | 缺失 >0 且 <10% | 缺失 ≥10% | **是** |

**颗粒度（3 项）**

| 子项 | 1 分 | 0.5 分 | 0 分 | 阻断 |
|---|---|---|---|---|
| 时间颗粒度 | 月度及以下 | **无此档** | 粗于月度 | **是** |
| 模型颗粒度 | 要求的轴全都有 | 有一部分，需额外聚合或拆解 | 要求的轴一个都没有 | **是** |
| 下钻颗粒度 | >2 个 L5–L8 维度 | 1–2 个 | 0 个 | 否 |

**阻断型 7 项 · 建议型 3 项**（维度一致性与业务准确性在缺对照输入时降为建议型）。

三处判据值得单独记住：

- **数据完整性按缺失率算，不按历史跨度算。** 分母 = 该序列报出的格子数 × **档案时间窗**
  的月数。不用序列自己的行数（那样谁都不缺），也不用合同的完整网格（"从来没报过某个渠道"
  是模型颗粒度的问题，在这里再算一次等于罚两次）。
  一份声明建模 2023-01 到 2025-12、实际只交到 2024 年起的数据，这一项给 0 并说出缺了 33%。
- **模型颗粒度对照的是合同，不是"有几个省份组"。** 要求 = 档案 `modelScope` 里有取值的轴
  ∩ 因子树那一行 `dimension` 声明的轴。用因子树声明去收窄是关键：一个全国投放的媒体，
  树上就写着它按月×区域报，没有渠道拆分不是缺失，是它本来的样子；
  反过来，树上承诺了、数据没交的轴是真缺口。
- **下钻颗粒度不阻断。** 它说的是 deep dive 能走多深，不是这条序列能不能建模。

## 总分与判读

```
维度分 = min(该维度全部阻断型子项)      没有阻断型子项时 = 1
总分   = 一致性 × 准确性 × 完整性 × 颗粒度
```

| 总分 | 判读 | 处置 |
|---|---|---|
| ≥ 0.5（即 1 或 0.5） | accept | 验收通过 |
| 0 < 总分 < 0.5 | borderline | **交人决策** |
| == 0 | unusable | 弃用并预警 |

**相乘不是相加。** 上游有文档写成相加，那是转录错误：实盘 Excel 与平台代码都是相乘。
任何人下次读到 `Final = 完整性 + 颗粒度 + 真实性 + 一致性` 都应当认为那是错的。

## 誊抄评分表

照 `../templates/quality-scorecard.yaml` 填。**这一步是誊抄，不是计算。**

- 四个维度分、总分、四句维度说明、每个子项的分数与说明，**逐字从结果里抄**。
  维度说明工具已经算好了（该维度最弱的那个阻断型子项自己的话），不要自己去找。
- **不得四舍五入**（结果里是 `0.25` 就写 `0.25`，不写 `0.3`），**不得重算**。
- `dataStatus` 不是 `scored` 的行，四维分与总分**写 `null`，不要写 0**。
- 每一行填 `source`，指回结果里的那一条。没有 `source` 的行等于没有出处。
- `autoVerdict` 预填，`disposition` **留空**——那是下一步人的事。
- `escalations` 段整段抄过来，`inheritedDrops` 与 `orphanCount` 抄那两个数。

检查项 `scorecard_matches_payload` 会逐行比对分值、总分与判读。
两边对不上就是抄错了，回去改抄的那一份，**不要去改结果**。

写完交给编排层验收：「数据质量评分已写好，请验收 data-quality/score」。
