# 数据质量评分

问的是**「这条数据本身能不能用」**，不问它对模型有没有用（那是统计检验的活）。
一个指标可以数据质量满分而统计上完全不可用。

**一行 = 因子树里一条已采纳的（L1 × L2 × L3 × L4 × 指标），不分模型对象。**
一个指标只被裁决一次，每个模型对象继承这个裁决。按对象分行会得出"同一条序列在这个渠道
能用、在那个不能用"——那是关于模型的陈述，不是关于数据的陈述。

**这个 Skill 只产出这一份交付物。** 分是工具算的，你抄；处置是人定的，你呈现。

**开始前：** 读 `../../shared/conventions.md` 定位工作区，确认因子映射已经签核。
数据阶段的工具从统一入口进：`~/.local/bin/mmm tool <id> …`。

## 第 0 步 · 澄清（先读完再问）

判据全是确定性的，人要定的只有边界处置口径和两处缺失的对照输入。

| 澄清点 | 什么时候必须问 | 推荐 |
|---|---|---|
| 要不要"保留但带保留意见"这一档 | 有人想要中间态时 | 不要。二值 keep/drop，保留意见写进说明 |
| 长表有没有单位列 | 维度一致性报"未校验"时 | 本轮没有就明确标成"未校验"，不要当成通过 |
| 有没有财务/系统口径的对照合计 | 业务准确性报"未校验"时 | 同上。客户能给就登记进 `metadata/reference-totals.yaml`，这一项立刻变成可计算且阻断 |
| 档案时间窗与实际到数不一致时算谁的 | 数据完整性大面积扣分时 | 算档案的。窗口是合同，缺了就是缺了，要让人知道 |
| 颗粒度粗于月度算不算硬失败 | 出现季度序列时 | 算。直接弃用并预警，不插值 |

## 硬规矩

**行来自因子树，不来自数据。** 树上要了、数据没到的行照样出现，标 `dataStatus: no-data`，
四维分留空。**`no-data` 不是 0 分**：0 分是"查过了，不能用"，找数据 Owner；
`no-data` 是"根本没到"，回数据需求与验收追交付。按数据分组出行的做法说不出第二句话——
那一行压根不存在，读起来和"这个因子没人要过"一模一样。

**总分是四个维度相乘，不是相加。** 一个维度是 0，整条序列就没法用——
一个在错误口径上完美完整的指标，不是"75% 可用"。相乘可达的总分只有六个值：
1 · 0.5 · 0.25 · 0.125 · 0.0625 · 0。

**判读只有一套档位：** 总分 ≥0.5 验收 / 0 与 0.5 之间交人 / =0 弃用并预警。
别处看到别的读法都是旧的。对客户就说这一套话术。

**评分表逐字誊抄，不得四舍五入、不得重算。** 每一行的四个维度分、总分、每个子项的分数
与说明，都从运行结果里原样抄进来，并用 `source` 指回那一条。**你不重新算一遍，也不"顺手"
把 0.4999 写成 0.5。** 检查项 `scorecard_matches_payload` 会逐行比对——抄错一个小数点，
和算错一个小数点在表上长得一样，但只有一个能靠重跑工具发现。

**建议型子项拉不低维度分。** 维度分 = 该维度全部**阻断型**子项里最低的那个。
把一个建议型当成阻断型，曾经导致整个项目每一个指标都被清零。
反过来，**阻断型是封顶不是参考**：它一旦低了，同维度里没有任何东西能把它抬回来。

**"没查"和"查了没问题"不能长得一样。** 缺对照输入时，维度一致性与业务准确性恒为 1 分
且不阻断（`computed: false`）。视图与 Excel 上必须渲染成**"未校验"**，不能渲染成 1。
这是全表里最容易被误读的两格。补上长表的 `unit` 列、补上 `metadata/reference-totals.yaml`，
这两项自动变成可计算且阻断——判据不用改。

**某个因子下全部指标都是 0 → 预警，不是多几行弃用。** 三个指标死一个，
是这个因子少了个视角；三个全死，是**这个因子在模型里彻底不存在了**，
而因子树当初把它放进来是有业务理由的。这条越过数据 Owner，直接上到业务侧与客户。
**全部指标都是 `no-data` 的因子也预警**，但路由不同：那是回数据需求追交付。

**上游否掉的永不重新打分。** 因子映射判"不做"的行仍然列在表上（标 `inherited-drop`），
但不给分——列出来是让漏斗可读，给分才是复活。

**一条自检：** 因子映射记了排除、而本层继承集是空的 → **停下来说出来**。
一个什么都没过滤掉的过滤器，看起来和一个干净的项目一模一样。

**孤儿单独报，不进表。** 数据里有、因子树没要过的指标记在 `orphanCount`，呈现时说一句。
一个没人认领的指标静默消失，和它不存在长得一样。

**打不出分本身是发现，全都打成 0 分同样是。** 某个子项在整个项目里从来没失败过一次 →
怀疑输入（曾经有人在按全国汇总之后才打分，于是三个子项在结构上不可能失败）。
反过来，18 行里 18 行栽在同一个子项上，通常也是一条关于输入的陈述——
比如档案声明建模 36 个月而数据只交了 24 个月。工具会把这句话直接打出来。

## 说话的规矩

1. 先说结论，再说依据，不铺垫。
2. 只说业务语言：说「确认」「检查项」「交付物」「计算结果」，不说 gate、predicate、artifact。
3. 每步三句话内交代：做了什么 / 结果是什么 / 需要你什么。
4. 要人拍板时永远给选择题：候选 + 推荐 + 每项后果。四百行不要逐行朗读——
   按档计数，只呈现需要决定的那一档；80 条栽在同一个子项上是一场对话，不是八十场。
5. 数字要报出处。说不出出处的数字就不说。说"2024 年缺 9 个月"，不要说"完整性偏低"。
6. 拿不准就问。"大致""可能""建议进一步确认"通常是该问没问留下的痕迹。
