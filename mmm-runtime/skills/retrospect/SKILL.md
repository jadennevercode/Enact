# 复盘与沉淀

**这个 Skill 只产出这一份交付物。** 它是唯一一层往回写的关卡：别的 Skill 都只往项目目录里写，
它经人批准之后写插件——知识库和 Skill 文件本身。

两个环，一个道理：**一个项目做完，学到的东西不该只留在这个项目目录里。**

| 环 | 原料 | 收尾时变成 |
|---|---|---|
| 知识沉淀 | 变更账本、被剔除的因子行、落在行业区间外却被确认属实的因子 | `knowledge/` 里的条目 |
| Skill 优化 | 反馈账本里用户的纠正与习惯 | 对 `skills/` 里那份文件的修改 |

**开始前：** 读 `../../shared/conventions.md` 定位工作区。记反馈可以随时做，
汇总和落地只在项目收尾时做。

## 第 0 步 · 澄清（先读完再问）

先把两本账都读完。**账本里已经写着的不许问。**

| 澄清点 | 什么时候必须问 | 推荐项 |
|---|---|---|
| 这个项目真的到终点了吗 | **每次汇总前必问** | 没到就只记反馈，不汇总——中途的结论会被后面的检验推翻 |
| 哪些口径客户要求保密 | 账本里有 `source: client` 的条目时 | 留在项目里，不进知识库 |
| 这条只对这家客户成立，还是换个客户也成立 | 每条候选都要判 | 说不清就不提名 |
| 改 Skill 影响所有后续项目，确认要改吗 | 每条改进项都要说一遍 | 无默认，人拍板 |

## 构建步骤

| # | 步骤 | 类型 | 做什么 | 详细 |
|---|---|---|---|---|
| 0 | 随时 | A | 项目进行中：用户纠正做法、说出习惯，当场记一条 | `references/capture.md` |
| 1 | `harvest` | C | 收尾：汇总两路候选，写出复盘报告草稿，裁决列留空 | `references/harvest.md` |
| 2 | `promote` | H | 沉淀候选一条一张卡问人；批准的写进知识库并登记 | `references/promote.md` |
| 3 | `promote` | H | 改进候选一条一张卡问人；批准的改 Skill 文件，改完跑静态检查 | `references/optimize.md` |
| 4 | — | — | 告诉编排层：复盘与沉淀已写好，请验收 `retrospective/promote` | — |

第 0 步不属于收尾，它贯穿整个项目，也不只这个 Skill 做——别的 Skill 在自己的工作里
被纠正时记的是同一本账。收尾时的两类候选共用一道确认：**它在落地之前**，
批准之后才动知识库和 Skill 文件。

## 硬规矩

**AI 只能提名，不能自己入库、不能自己改 Skill。** 这一条比别处更严，因为这里写的不是项目
目录，是插件：一条悄悄进了知识库的错结论，会被之后每一个同行业项目当成行业先例读出来。

**没到终点不汇总。** 中途的结论可能被后面的检验推翻。用户中途要求复盘，就只汇报现状，
说清楚为什么现在不落库。

**一个数据点不是行业典型值。** 一个项目的一次观察，标成「某项目观察」可以，
写成「行业典型值」不行。数字类条目要两个独立项目各自确认过，才从案例升为行业先验。

**每条落库都带来源戳：哪个项目、哪次确认、什么时候。** 半年后没有来源的条目，
没人敢用也没人敢删。

**改插件之前先说影响面。** 插件是所有项目共用的，改完下一个项目立即生效，
而且是所有项目——这句话要写在卡片上，不是等人问起才说。

**改完必须跑静态检查，结果原样报出来。** 见 `references/optimize.md`。

**客户要求保密的口径与定义只留在项目里。** 这一条没有例外，也不问。

| 产出 | 模板 |
|---|---|

批准后落地的位置在插件里，不在工作区：知识库条目写进 `knowledge/` 并在
`knowledge/index.yaml` 登记；Skill 的修改落在 `skills/<名字>/` 下。
两者都在 git 里，改动本身就是复核面——提交留给用户。

做完任何一步，交给编排层验收。**你不自己关确认、不记裁决、不流转状态。**

## 说话的规矩

1. 先说结论，再说依据，不铺垫。
2. 只说业务语言：说「确认」「检查项」「交付物」「计算结果」，不说 gate、predicate、artifact。
3. 每步三句话内交代：做了什么 / 结果是什么 / 需要你什么。
4. 要人拍板时永远给选择题：候选 + 推荐 + 每项后果，不给开放式提问。
5. 数字要报出处。说不出出处的数字就不说。
6. 拿不准就问。"大致""可能""建议进一步确认"通常是该问没问留下的痕迹。
