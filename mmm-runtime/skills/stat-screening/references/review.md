# 步骤 review —— 逐行定去留（H）

每一行离开这一步时只能是 `include` 或 `drop`。**`review` 是过渡态，会卡住验收。**

**取材范围：** `artifacts/s2/stat-scorecard.yaml`。没有新材料——复核的人裁的是工具算出来的东西。

## 默认处置

| 自动判定 | 默认处置 | 含义 |
|---|---|---|
| 良好（总分 ≥ 0.5） | `include` | 直接入模 |
| 可接受（0 < 总分 < 0.5） | `review` | 送到人面前 |
| 不可用（总分 = 0） | `drop` | 不可用 |
| 响应指标（`response`） | `include` | 模型要解释的那个数，不检验自己，也不剔除 |
| 没有数据（`no-data`） | 空，等人定 | 不是被判死，是还没到 |
| 上游已否（`inherited-drop`） | `drop` | 继承 |

## 呈现顺序

工具已经在**每一行**上预填了自动判定，人复核的是**例外**。

1. **按档位报计数。** 一行：n 个良好 · n 个待定 · n 个不可用 · n 个没有数据 ·
   n 个上游已否未参与检验。另有多少孤儿。
2. **严重共线性单列一段。** 共线性 ≥ 10 的行全部列出，连同它们的值。
   **这一段的建议是剔除，不论总分多高**，逐条记理由。
3. **共线性成组呈现，成组决定。** 每组列出全部成员和各自的值，推荐留哪一个——
   通常是**业务上真正能被操纵的那一个**，不是相关性略好的那一个。**一组一个决定。**
   定完之后重跑打分，把新的值再摆一遍，因为拿掉一个成员会让其余每一个都变。
4. **「一条数据都没到」的行单列一节** —— 它们没有统计量，不是 0 分。
   候选：回数据需求追交付 / 本轮不做 / 换指标。
5. **边缘行逐条列**，总分最低的排最前：L4、指标、三个数、以及**是哪一项挂的**。
   把零说成生意的话：**"这条序列 36 个月几乎没动过"** 是复核的人能行动的一句话，
   "波动性 0 分"不是。
6. **每行的建议和它的依据。**
7. **接下来会怎样** —— 留下来的正是 OLS 预验证要拟合的。

## 三条候选，但真正生效的是逐行

确认上的三个选项只是走向表述：

| 候选 | 后果 |
|---|---|
| `keep` 保留可接受档（推荐） | 与良好档一起入模，由 OLS 预验证再用行业区间检一遍 |
| `drop` 只留良好档 | 模型更精简；部分因子会一个指标都不剩，触发因子级预警 |
| `review` 逐条挑 | **这才是真正生效的那一层** |

无论选哪个，最终每一行都要落到 `include` 或 `drop`。
**成批接受是合法的，而且要记下来**："接受总分为 1 的那 88 行"是一个真实的决定，
按一个动作带计数记录它。不合法的是没人看过就走到验收——那会被逐行点名。

## 记录

```yaml
disposition: drop
decidedBy: human
note: "与门店数共线（共线性 41）。保留门店数，那是团队真正能动的那一个。"
```

`decidedBy: human` 钉住这一行：重跑会刷新自动判定并展示它，但不动人的处置。
改判时 `note` 必填。

## 统计上的剔除不总是正确的剔除

该说的时候要说出来。一个客户在签核那关认下来的因子，在这里波动性不合格，
那是**数据的问题，不是生意的问题**——客户没说错自己的生意，是这条序列没说对客户。
它可能值得重新收一次而不是被剔掉。裁的是人，你的活是把这个区别摆到明面上。

## 因子级预警怎么上报

某个 L4 的全部候选指标都判不可用时，**它不是打分表里的一行，是一段单独的预警**：

```
预警 · <因子名> 在模型里将没有任何东西代表它
  候选指标：<指标 A>（波动性 0.03）、<指标 B>（波动性 0.04）
  两个都几乎不动。
  A. 回流业务理解找替代指标（推荐）—— 模型不会对这块生意失语；代价是要重开上游、工期后拖。
  B. 该因子不入模，在交付说明里预警 —— 因子树上留一个洞。
```

**这条回流边在流程定义里没有配好**（这一关自身没有跨交付物的退回目标），
所以它走的是**上报**而不是自动退回：把上面这段选择题交给编排层，由人决定是否重开业务理解那一段。
不要自己去改上游，也不要把它写成一句备注了事。

## 视图：Excel

```bash
~/.local/bin/mmm app workbook scorecard -w <工作区> --card stat
```

产出 `artifacts/s2/stat-scorecard.xlsx`，三张表：评分卡 · 统计 · 说明。
**没人手改它**——它带着打分表的指纹，手改之后 `workbook_current` 会判它过期。
数字一律来自打分表，不许重打。

表上有一处渲染是硬要求：**没有统计量的行（`no-data` / `inherited-drop` / `response`）
三个数与总分渲染成「—」**，不能渲染成 0，也不能留空。共线性尤其要紧：0 在这个刻度上
读起来像满分，1.0 读起来像"完全不共线"，而真相是"没人量过"。

`panel.vifRegime` 是 `pairwise-proxy` 时，**那句话要出现在给人看的那一页上**。

## 收尾

写完之后告诉编排层：**"统计检验已写好，请验收 `stat-screening/review`。"**

**不记裁决、不流转状态。** 从这里开始，活下来的就是 OLS 预验证要拟合的；
一个剔除会被 OLS 与模型输入继承，并在漏斗里显示为在统计层掉队。
