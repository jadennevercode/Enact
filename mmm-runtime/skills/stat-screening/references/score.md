# stat-screening/score —— 三项检验各跑一遍，再卷成总分（M + A）

```bash
~/.local/bin/mmm tool ledger.derive   --workspace <工作区> --layer statistical
~/.local/bin/mmm tool stat.cv         --workspace <工作区>
~/.local/bin/mmm tool stat.pearson    --workspace <工作区>
~/.local/bin/mmm tool stat.vif        --workspace <工作区>
~/.local/bin/mmm tool stat.scorecard  --workspace <工作区>
```

**顺序不能反。** `stat.vif` 读 `stat.pearson` 的结果——共线性要对着「与响应最相关的那 12 条」
构成的设计矩阵来算，没有相关性就没有那批。`stat.scorecard` 读前三份卷成
`data/derived/stat-panel.json`。三份带同一个行集指纹，对不上会失败——混着卷积出来的打分表
内部自洽、但每个数都错，读的时候看不出来。

工具卡见 `tools/catalog/stat.cv.yaml` / `stat.pearson.yaml` / `stat.vif.yaml` /
`stat.scorecard.yaml`。

## 行从哪来

**因子树里 `status: accepted` 的每一行**，与数据质量评分表逐行对得上。逐行标状态：

| dataStatus | 含义 | 三个统计量 |
|---|---|---|
| `scored` | 长表里有这条序列，已检验 | 有数 |
| `no-data` | 树上要了，一条数据都没到 | **留空，不是 0** |
| `inherited-drop` | 映射 / 质量 / 签核任一层已否 | 留空 |

`null` 不是 0，这一层尤其要紧：**共线性的 1.0 是「好」的那一端**，一个默认的 1.0 会让
没人筛过的序列读起来像「无共线性」。

## 检验跑在面板上，不跑在汇总序列上

面板的行键是 **(模型对象, 月)**。一个指标在它上报的每个渠道 × 产品格子里都被量到，
观测数从"月数"变成"对象数 × 月数"。

把全部渠道和产品先塌成一条全国序列再算，会让"在某个渠道里恒定、但渠道之间差异巨大"的指标
和真正的常数指标无法区分，也让共线性掉进欠定区。

工具内部按这个顺序做，每一步都有它非这样不可的理由：

| 顺序 | 做什么 | 为什么 |
|---|---|---|
| 1 | 逐指标滚月 | 一个月内同一指标可能有多行（下钻残差路径）。**按该指标自己的汇总规则滚**：比例、覆盖率取平均，花费、销量求和。对比例类求和会造出一个没有意义的数，而三项检验打的就是这个数 |
| 2 | 对齐日历 | 每个对象重索引到完整连续区间 |
| 3 | **缺口保持为空，不补零** | 补零会把"这个指标 2023 年前不存在"变成"它两年是零"：波动性量到一个阶跃函数，相关性把零块和响应的趋势关联起来，而所有短指标共享同一个零块，共线性就把它们判成彼此共线——三项检验打的全是填充值 |
| 4 | 去趋势去季节 | 两项相关类检验跑在**对象内同比差分**上。月度原始水平上每个指标都和响应相关、也和彼此相关，因为它们共骑同一条季节趋势；量到的是趋势不是指标。**差分必须在对象内部做**——顺着面板往下差，会把一个渠道的头几个月减去另一个渠道的末几个月 |
| 5 | 对象内标准化 | 全国性驱动在每个对象里是同一条序列，而响应在对象间差几倍。直接合并会把真实关系埋在截面尺度下 |

**波动性不差分。** 它问的是"这条序列动不动"，那是原始水平的属性。

**常数序列会被检验，不会被悄悄丢掉。** 一条从不移动的序列正是波动性检验存在的理由。

## 三项检验与分档

| 检验 | 定义 | 0 分 | 0.5 分 | 1 分 |
|---|---|---|---|---|
| 波动性 | 序列先缩放到 [0,1]，再算 方差 / 均值 | ≤ 0.05 | 0.05–0.1 | ≥ 0.1 |
| 相关性 | 因子 vs 响应，单变量、有符号，判定用绝对值 | < 0.1 | 0.1–0.3 | ≥ 0.3 |
| 共线性 | 方差膨胀，**1 是好的那一端** | ≥ 5 | 1–5 | ≤ 1 |

**总分 = 三项相乘。** ≥ 0.5 良好 / 0 < 总分 < 0.5 需人工介入 / = 0 不可用。
可达的总分只有 1 · 0.5 · 0.25 · 0.125 · 0 五个值。

空序列、常数序列、均值 ≤ 0 的波动性一律 0；有效观测少于 3 对、或任一侧标准差为 0 的相关性返回 0。

## 共线性对着什么算 —— 这是最贵的一个坑

共线性是设计矩阵的属性：这一列的方差被**模型里的其他列**顶高了多少。

对着全部候选一起问，两种情形都失败，而且是同一个根因——现实中不存在一个把上百条共季节的
营销序列放在一起的模型。短面板落进两两最大代理，几乎每条序列都有某个同伴相关到 0.89 以上；
长面板去求逆一个远非正定的相关矩阵，于是每个值都顶到上限。两条路的结果一样：
几乎所有指标共线性 ≥ 5，总分归零，**约九成指标被筛掉**。

所以每个指标对着它**可能真的进得去的那个模型**来量：取与响应相关性最强的 12 条构成设计矩阵
（12 = 建模宽度上限）。不在这个集合里的指标，用最强的 11 条同伴加上它自己来量。
**分档不变、算法不变，只有喂进去的矩阵变了。**

## 两条必须写进产出的声明

**规制：** `panel.vifRegime` 是 `exact` 还是 `pairwise-proxy`。后者表示变量数 ≥ 观测数，
完整的多元共线性指标不存在，报出来的是"最共线的那一个同伴能解释这个指标多少"。
**这句话要出现在给人看的那一页上**，不是只躺在字段里。

**严重共线性：** 共线性 ≥ 10 的行 `severeCollinearity: true`。一律建议剔除，不论总分多高。

## 观测期下限

| 常量 | 值 | 作用 |
|---|---|---|
| 最低观测月数 | 12 | 低于此值，该行仍然产出（判不可用、总分 0，并写明"只有 N 个观测月"），**不静默省略** |
| 同比差分周期 | 12 | — |
| 差分后最少行数 | 6 | 守的是结果不是输入：13–14 个月的项目差分后只剩 1–2 行，相关性的守卫会对每个指标静默返回 0，把所有东西无理由地全丢掉。低于此值整个跳过差分 |
| 共线性设计矩阵宽度 | 12 | 与建模驱动数上限同源 |

## 逐行写一句理由

≤22 词，**只基于该行自己的三个数与判定**，不得造数。分数永远是算出来的，这句话只是解释它。
没模型时用确定性模板兜底（"几乎与响应不相关" / "与其余指标严重共线" / "在整个期间几乎不变"），
句首标明判定档位。

**总分为零的行必须点名是哪一项挂的**——`zeroReason` 字段抄工具的输出。

## 誊抄打分表

照 `../templates/stat-scorecard.yaml` 填。**这一步是誊抄，不是计算。**

- 三个原始统计量、三个档位分、总分、`zeroReason`、`severeCollinearity`，**逐字从结果里抄**。
- `dataStatus` 不是 `scored` 的行，统计量与总分**写 `null`，不要写 0**。
- 每一行填 `source`，指回结果里的那一条。
- `panel` 块整段抄过来，`factorAlerts` 整段抄过来。
- `disposition` 留空或抄工具的提案；人裁决那一步才定终态。

检查项 `scorecard_matches_payload` 会逐行比对。两边对不上就是抄错了，回去改抄的那一份，
**不要去改结果**。

## 空也是结论

没有指标到达这一层时工具会失败并说明是哪一种空——树是空的、数据一条没到、还是全被上一层否掉。
那是一个发现，不是通过。
