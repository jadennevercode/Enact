# 统计检验

对每个活到这一层的指标问三件事：它**动**得够不够（波动性）？它跟响应**一起动**吗（相关性）？
它和别的驱动**分得开**吗（共线性）？三项各得 0 / 0.5 / 1 分，**相乘**得总分。

**它衡量的是「这个指标对建模有没有用」**，不是「这条数据本身干不干净」——那是数据质量层的活。
同一个指标可以数据质量满分而统计上完全不可用。

**这个 Skill 只产出这一份交付物。** 它也是最容易被一个坏面板弄得毫无意义的一层——
所以下面的规矩多数是关于数据的形状，不是关于检验。

**开始前：** 读 `../../shared/conventions.md` 定位工作区，确认业务校验与签核已确认。
数据阶段的工具从统一入口进：`~/.local/bin/mmm tool <id> …`。

## 第 0 步 · 澄清（先读完再问）

先读完签核结论与因子映射。**已经写在里面的不许问。** 详见 `references/clarify.md`。

| 澄清点 | 什么时候必须问 | 推荐项 |
|---|---|---|
| 哪些因子业务上不可替代 | 有 0.5 分档的行时（只有人给得出这份名单） | 无默认 |
| 观测期够不够 | 有指标的观测月数 < 12 时 | 仍打分并标注证据不足 |
| 高共线性指标怎么处置 | 有共线性 ≥ 10 的行时 | 逐条：降维 / 合并 / 剔除 / 知情保留 |
| 某因子的指标全部不达标时找不找替代 | 出现因子级预警时 | 预警并回流业务理解找替代 |

**合成公式与档位不问。** 三项相乘、≥0.5 良好，已经裁定，见下面「口径」。

## 硬规矩

**行来自因子树，不来自数据。** 与数据质量评分表逐行对得上——两张表的漏斗数字必须能相互核对。
树上要了、数据没到的行照样出现，标 `dataStatus: no-data`，三个统计量留空。
**null 不是 0，这里尤其要紧**：共线性的 1.0 是「好」的那一端，一个默认的 1.0 会让
没人筛过的序列读起来像「无共线性」。

**每个数都来自一次真实的工具运行。** 波动系数、相关系数、共线性指标、三项分值、总分全部来自
四份计算结果，产出文档要声明它读的是它们。**逐字照抄：不四舍五入、不换单位、不心算、不重算。**
写着"共线性大约 5"而计算结果是 `4.87` 的文档已经不能核对了。检查项
`scorecard_matches_payload` 会逐行比对。

**总分是三项相乘**，一项不合格总分归零。一个相关性极好但和别人完全重合的指标不是"三分之二
可用"——它在那一对里有一个走人之前完全不可用。

**共线性指标超过 10 的一律建议剔除，不论总分多高。** 乘法标度表达不了这条：共线性 5 和 50
都是 0 分，一个总分只能归零一次。所以它单独标一个严重共线性，在复核时单列一段。

**共线性成组定，不逐行定。** 它说的是"这一组"：拿掉一个，其余每一个的值都会变。
沿着排序列表一行一行地砍，会砍掉三个变量，而实际上砍一个就够了。定完一组之后重跑打分。

**变量数 ≥ 观测数时，必须直说共线性只是两两近似。** 那时完整的多元共线性指标根本不存在，报出
来的数是"最共线的那一个同伴能解释这个指标多少"；把近似值当精确值呈现，会诱导出一个这个数支撑
不了的决定。产出里写明是哪一种规制。

**某个 L4 因子的全部指标都不达标 → 预警并回流。** 这是明规则不是可选提示，上报方式见
`references/review.md`。**总分为零必须点名是哪一项挂的**（波动性 / 相关性 / 共线性）——
只说"不可用"给复核的人什么也没留下。

**只继承，不重审。** 映射层忽略的、质量层弃用的、客户签核否掉的，根本不参与检验——
这不是整洁问题：共线性是整组一起算的，一个已经死掉的指标会把还在场的指标的共线性抬上去。
它们仍然列在表上（标 `inherited-drop`、不给数），列出来是让漏斗可读，给数才是复活。
**中间状态过不了验收**：`review` 是过渡态，人裁决后每行必须落到 `include` 或 `drop`。

**三种行不参与三项检验，各自有自己的判读：**
`response`（响应指标，驱动因子是对着它检验的，它不检验自己，也不会被剔除）·
`no-data`（没有可检验的序列）· `not-screened`（进不了面板）。

## 口径：三项相乘，≥0.5 良好

| | 合成 | 档位 | 良好线 |
|---|---|---|---|
| 业务规则文档与真实工作簿 | 三项相加 | 0 / 0.5 / 1 / 2 | 总分 ≥ 3 |
| **平台代码与本 runtime（执行口径）** | **三项相乘** | **0 / 0.5 / 1** | **总分 ≥ 0.5** |

**裁定：跟随代码，四处同源，不改。** 对客户统一说这一套话术："总分是三项检验相乘，任何一项
不合格总分就是零；0.5 以下的需要你确认。"**不要说"1.5 到 3 之间需要确认"**——那是另一套标度
的话。乘法更严：信号很强但和别人共线的指标，加法下能靠另外两项补回来，乘法下一票否决——
说到这类行时要点明，让人知道自己在批的是什么。

验收表原文写「0.5–1 验收通过 / ≤0.5 人工介入」，0.5 同时落在两档；**客户裁定 0.5 归验收通过**，
与数据质量评分表的同一处歧义按同一条裁决处理。乘法可达的总分只有 1 · 0.5 · 0.25 · 0.125 · 0
五个值，所以「≥0.5」= 三项全过，或者恰有一项拿半分。

## 说话的规矩

1. 先说结论，再说依据，不铺垫。
2. 只说业务语言：说「确认」「检查项」「交付物」「计算结果」，不说 gate、predicate、artifact。
3. 每步三句话内交代：做了什么 / 结果是什么 / 需要你什么。
4. 要人拍板时永远给选择题：候选 + 推荐 + 每项后果。几十行不要问几十次——按档位与共线性成组呈现。
5. 数字要报出处。说不出出处的数字就不说。把零说成生意的话：
   「这条序列 36 个月几乎没动过」是复核的人能行动的一句话，「波动性 0 分」不是。
6. 拿不准就问。"大致""可能""建议进一步确认"通常是该问没问留下的痕迹。
