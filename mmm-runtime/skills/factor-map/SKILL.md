# 因子映射

因子树用「L4 + 指标」说要收什么，数据用「L4 + 指标名」落地，标签是源文件自己高兴
怎么叫就怎么叫的。**没有任何东西会自动把这两套叫法接起来。** 这个 Skill 就是接头，
**只产出这一份交付物**。

它比看起来重要。曾经有**一个人明确不做的 123 行因子，在数据侧一个键都没匹配上**——
于是"已排除"这个过滤器过滤了零行，一个被人亲手否掉的因子照样被打分、被筛查、被拟合。

**开始前：** 读 `../../shared/conventions.md` 定位工作区，确认发布数据集已经确认过。

## 第 0 步 · 澄清（先读完再问）

先读完归属清单、发布清单、因子树。

| 澄清点 | 什么时候必须问 | 推荐 |
|---|---|---|
| 一个因子行能不能由多份数据供给 | 第一次做，或出现一行多供给时 | 能。一行可多供给，但一个指标只能供给一行 |
| "不做"的门槛 | 每次都要说清楚 | 只有"本项目确实不建这个因子"才算，并且必须写理由 |
| 待定行找不到数据是追数还是不做 | **逐行问**，这是本交付物的主要澄清量 | 见下面的三选一，没有第四种 |
| 之前不做的行现在有数据了怎么办 | 重算后出现这种行 | 显式提出来问，不当成"改善"静默放过 |
| 指标角色与聚合方式在哪里定 | 有人想在这里改时 | 角色看目标表结构，聚合方式看因子树那一行的 `aggregation`。这里两个都只读不改 |

答案写进变更账本。**问不到人时**按推荐走并标明是假设。

## 硬规矩

**"不做"会被后面每一层继承。** 质量评分不给它打分、业务校验不画它、统计检验不筛它、
OLS 拟合不了它、模型输入里它显示为"在映射这一步被否"。理由原文就是唯一能向
三个月后读漏斗的人解释这个缺口的东西。

**明确排除压过自动映射。** 反过来的话，一个**有**数据的因子在这一步根本无法被否决——
排除只对"没人供给的行"可达，于是"把这个留在模型外"这句话，
在某个数据源碰巧覆盖到它的那一刻就蒸发了。

**行的身份是路径加指标，绝不是路径本身。** 一棵树在同一条路径下常带好几行。
只按路径查找，在参考树上曾把 16 个指标里的 8 个绑错，而每一个看起来都完全正确。

**一个指标至多供给一行。** 一个指标同时认领两行是发布环节的问题，退回发布数据集去修，
不在这里解。判据：**绑定是数据的解读问题，属于脚本；不做是范围的决定问题，属于人。**

**候选的分数是算出来的，不是你挑的。** 分数 = 0.45×名称 + 0.35×路径 + 0.12×单位
+ 0.08×覆盖；低于 0.30 的不呈现，最多 5 个。你可以把那句解释改写得更好读，
**分数与排序永不经过你**。凭感觉说"这个最接近"是没有出处的数字。

**无人认领的指标不归你采纳。** 它们列在一旁，由因子树去采纳或驳回。
**这个 Skill 不写因子树**——一个东西有两个写入者，就是"一行的身份"和"一行的裁决"
开始分家的地方。

**待定不是一个能活过签核的状态。** 检查项会点名是哪几行。那是检查在做它的工作。

**一条自检：** 如果这里记了"不做"，而下游拿到的继承集是空的，**立刻停下来说出来**——
一个什么都没过滤掉的过滤器，看起来和一个干净的项目一模一样。

## 产出物与模板

- `artifacts/s2/factor-map.yaml` —— 照 `templates/factor-map.yaml` 填。
  三态、供给记录、候选、无人认领清单都在里面。
- `artifacts/s2/ledger.md` —— 台账视图，核心是**人口对账表**。
  它的每一个数字都引用选择结算结果，**一个都不许重打**。

没有这张对账表，177 → 85 → 29 这串数字会被读成"数据在流失"，
而真相是**这是三个不同的人口**。

做完任何一步，交给编排层验收：「因子映射的 X 已写好，请验收 factor-map/X」。

## 说话的规矩

1. 先说结论，再说依据，不铺垫。
2. 只说业务语言：说「确认」「检查项」「交付物」「数据来源」，不说 gate、predicate、artifact。
3. 每步三句话内交代：做了什么 / 结果是什么 / 需要你什么。
4. 要人拍板时永远给选择题：候选 + 推荐 + 每项后果。待定行按 L1 › L2 分组呈现，
   给出整组建议，让人改例外——54 行不要问 54 次。
5. 数字要报出处。说不出出处的数字就不说。
6. 拿不准就问。"大致""可能""建议进一步确认"通常是该问没问留下的痕迹。
