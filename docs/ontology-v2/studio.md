# Ontology Studio 与人工建模界面

状态：本地实现，尚未完成真实用户验收。位置保持在智能中心。Sources 负责连接和发现，Issue 负责澄清与协作，Studio 负责模型阅读、绑定检查、测试及版本治理。用户业务模型是唯一主语；Semantica 原生产物是可展开的技术投影。

## 已实现的页面结构

| 页面 | 默认呈现 | 详细内容 |
| --- | --- | --- |
| 概览 | 业务说明、待回答的问题、五元素数量、知识和发布情况 | 继续对应的建模 Issue |
| 本体模型 | 可交互业务图；主体+属性、关系、行动、规则四个子页 | 业务定义、别名、状态、来源依据、原生产物 |
| 数据与行动 | 先看主体有哪些数据、行动能做什么；清楚标记未绑定 | 再看连接、资源与绑定规格；配置成功不等于测试通过 |
| 测试与质量 | 检查维度、真实分子/分母、失败原因、业务问题用例 | 查询与预期/实际结果、完整机器报告 |
| 版本与变更 | 工作草稿修订记录及发布版本；合并原建模记录 | 查看指定发布版本、返回草稿、停用理由 |

主体卡将属性放在所属主体下面，显示数据类型、必填、单位和示例。关系卡显示来源主体、关系含义、目标主体。行动卡显示作用主体、输入、输出、影响、前后条件、适用规则和绑定状态。规则卡显示 permission / prohibition / obligation / constraint、作用行动、适用条件及状态。无法解释的技术声明明确显示“尚未提供业务解释”，不编造描述。

Data Binding 与 Action Binding 独立于模型元素。未绑定行动仍是行动。旧模型只能显示旧模型确实具有的内容，不能从 API 绑定伪造新业务行动。

## 原生可视化复用边界

直接复用 Semantica Explorer 的 Sigma/Graphology、场景生命周期及点击选择、悬停、适配视图、聚焦、路径插件；使用原有 Louvain 社群分组、最短路径算法和 ForceAtlas2 布局。提供完整/分组/聚焦模式、搜索、类型筛选、邻域深度、距离热图、布局启停、缩放、组成员展开、路径目标选择、节点/边检查器及可访问列表。

选择状态与图实例按组件隔离，销毁组件会释放 worker 和 renderer。没有嵌入带全局 store 的 Explorer 应用。默认业务图不混入来源、PROV 空白节点；来源依据和技术 JSON 只放在展开区。原始 MIT 来源与改编范围记录于 `packages/views/semantic/explorer/README.md`。

大图画布限 500 节点 / 1500 边，选中节点和路径优先，明显提示部分结果。此限制不能替代 API 分页或百万关系性能验证，相关性能验收尚未执行。

## Issue 中的真实人工交互

Issue 顶部建模区域通过 `GET /constructions/for-issue/{issueID}` 定位当前或祖先 Issue 的 construction。普通 Issue 无 construction 时不出现此区域。

1. 小队从已连接知识提出每轮最多三个澄清问题。人用自然语言回答，或明确标记未知；历史回答可展开。
2. 小队提出七类可读卡片：主体、属性、关系、行动、规则、数据绑定、行动绑定。每张卡区分来源事实、小队建议、未知以及有实际决定记录的人工确认。
3. 人可以确认、改业务名称/含义、暂不确定或不纳入。修改不要求编辑 RDF/JSON。请求携带当前 revision，并持久记录真实成员身份。
4. scope → model → operations → release 四关依次评审。关卡卡片包含业务摘要、分组结论、检查、未解决问题。前关未通过则不能跳关确认；stale 包不能确认。
5. 确认请求同时携带展示时的 artifact digest 和 review subject digest。服务端并发冲突不会清空本地输入。此 UI 不代表用户已经批准任何业务决定。

`OntologyInterview`、`AuthoringProposalCard` 与 `ReviewPacketCard` 是独立可测组件；Issue detail 仅增加一个挂载点。用户决定与任务生成内容通过不同 API 权限处理，服务端权限是最终依据。

## 质量与一致性

沿用 Semantica Health / SHACL 的概览、维度、发现和用例组织，接入真实 `quality_v2.dimensions`，每项有 numerator、denominator、status、description、engine。

- denominator=0、缺少结果或不支持的引擎显示未测试；不显示 100 分。
- CQ 显示执行结果而非词语是否匹配，结构字段完整度不替代业务覆盖率。
- SHACL 覆盖率与校验失败分别保留；覆盖率 100% 仍可能有阻断。
- 原生逻辑一致性占位实现不能计为通过。OWL DL 未执行时明确保留 not_evaluated。
- 汇总只平均有执行结果的维度，同时显示已测试维度数/全部维度数；出现失败仍明确显示失败，不把汇总当发布授权。
- 发布直接请求当前草稿；不在发布按钮里先偷偷重建候选产物。四关审核由服务端根据精确版本校验。

## Agent 配置

Agent 本体页读取/写入真实 Ontology assignment，选择本体后必须选一个已发布版本。启用、替换与移除写入 `/api/semantic/agents/{agentID}/ontologies`。停用版本不能重新启用。原 Ontology Skill Package 标记为旧来源独立展示，不算原生本体配置；运行时仍需再次检查绑定的发布版本。

## 本轮补充验证（2026-09-09）

- Studio 默认使用一次限时 1 秒的原生 FA2 Worker 预排，计算期间显示整理布局，完成后静态呈现。手动布局控制保留；减少动态效果偏好下也只显示布局结果。1440px / 390px SwiftShader 浏览器已验证分组、业务图、行动和政策卡；手机主 Tab 使用横向滚动，避免换行覆盖正文。此轮完整模型来自明确标注的仅浏览器响应样例，不是用户确认的业务本体。
- 中文真实 QOL-13 入口是单句制作本体请求。本次用户明确委托实施助手代其交互；第一轮三题回答、卡片决定及范围审阅已通过成员接口保存，并自动恢复协调者。其余关口按实际进展记录，不能由组件测试代替。
- 人回答或复核成功与小队恢复状态分别显示。queued / coalesced 表示已排队，deferred 表示正常等待，只有 failed 提供“重试通知小队”。重试只调用独立 resume endpoint，不重复提交人类答案或批准。GET authoring 的持久状态是统一展示依据，成功 mutation 先写入同一查询缓存。
- 最后复检：完整 views typecheck、相关 ESLint、resume/authoring/review 共 10 项测试通过；此前图算法一并运行时 12 项通过。未将这些测试视为真人业务验收或部署完成。

### 图谱阅读与草案刷新

关系标签默认按当前阅读上下文出现：悬停、选中对象/关系与路径。搜索定位通过 Sigma 公共坐标转换，避免布局后相机使用未归一化坐标；选择路径恢复完整视图，路径终点的名字不被邻域规则隐藏。选择本身不弹出覆盖邻居名字的悬浮卡，指针悬停保持原生行为。

行动草案刷新保留前后版本指针及原决定。已被替代草案只能查看；宿主内查看关联草案是只读预览，需返回应用后单独发起新版审阅，不允许将旧批准请求迁移到新 ID。运行页以版本提示和锚点连接历史，旧批准不产生新版执行权。


## Policy 解释器用例补充规格

状态：已部署并完成本轮实际页面复验；构建流程仍在 operations 最终复检，来源尚未发布。测试页在原生结构校验之外，独立展示发布前由真实 Policy 解释器执行的用例。普通用户阅读业务情境、预期判断、实际判断和原因；输入参数及 fixture 由 Family 管理，不要求用户填写技术表单。

验收要求：

1. 结果来自服务端实际调用解释器的测量记录，包含被测 artifact digest、解释器、时间、Action 和 fixture 标识。小队自由填写的“通过”评论或事件不能产生通过率。
2. 当前版本与历史结果分开；版本不符显示已过期，未执行或零用例显示未测试。
3. 有明确预期的用例才判断预期是否满足。权限拒绝或未知若正是用例预期，可以是通过的反例测试；不能因此把实际业务行动标成允许。
4. 显示正确对象、错误案例、错误方案、错误目标、旧证据和权限未知等业务用例；允许展开规则理由，默认不堆参数或机器标识。
5. 独立显示解释器用例数量与结果，不混入 SHACL 或连接数据覆盖率，不将模拟通过当作真实行动回读成功。
6. 测试不创建执行步骤、行动意图、审批或系统回执，也不改变本体内容、版本摘要或四关审批。测试记录用于审计与阅读，不能提交给正式执行接口充当来源证据。
7. 保留原生质量评分的未测处理；服务异常显示未完成，不能转成成功或缺省 100 分。

本轮服务端用 7 个有明确预期的中文合成用例调用真实 Semantica `native/policies`，测得 7/7 符合预期并保存为 server-owned 结果；这些 fixture 没有形成行动意图、审批、回执或真实行动证据。生产页面的桌面、390px 和 Policy 原因展开均通过复验，390px 下文档宽度保持 390，未发现 page error。证据位于 `/private/tmp/enact-ui-qa/policy-live/evidence.json`。这只证明草稿 Policy 解释器与展示链路可用；operations 最终复检、release、来源发布及向现有 `quality-traceablity` 消费空间安装仍未完成。
