# 前端信息架构重组

**状态：** 2026-09-07 已批准 · 实施中
**范围：** `packages/core/paths`、`packages/views`、`apps/web`、`apps/desktop`
**English：** [frontend-ia-restructure.md](frontend-ia-restructure.md)

## 1. 目的

共享视觉系统已在 [web-desktop-visual-refactor.md](web-desktop-visual-refactor.md) 中统一，
但它下面的导航结构没有：侧栏仍然按上游产品的方式分组，Enact 自己的几条主张在界面里没有落点。

本文确定目标信息架构、每一个现有功能的去向，以及搬迁顺序。它改的是分组、标签和页面壳，
不改数据模型、服务端与客户端状态的归属、路由机制，也不改 Issue 看板与泳道的交互。

## 2. 现状的六个问题

| # | 现状 | 与产品模型的冲突 |
| --- | --- | --- |
| 1 | 侧栏按归属分组——个人 / 工作区 / 配置，13 个平铺入口 | Enact 的模型是人和智能体同为一支队伍，然后工作 → 能力 → 执行。现在的分组讲的是另一个故事 |
| 2 | 落地页处处是 Issues 列表（web、桌面新标签页、完成引导后、接受邀请后） | 一份工作清单回答不了"能不能过、还差什么、谁要拍板" |
| 3 | 成员只存在于设置的成员标签下；智能体与智能体小组各占一个顶层页面 | 主张是"智能体就是队友"，名册却被拆在三处 |
| 4 | Skills 和 Ontology 是页面，MCP、知识库、快捷操作是设置标签，智能体详情里又各有一个 tab | 产品文档里描述的能力库，在界面上没有家 |
| 5 | 没有工作区级执行记录，没有验收队列；收件箱把"需要你拍板"和"知会一下"混在一起 | 人工验收是产品规则（`done` 留给人），却没有任何界面按它组织 |
| 6 | 用量页标签是 Analytics，代码却在 `views/dashboard`；Ontology 详情是弹窗；桌面标签栏硬编码英文 | 命名与层级是继承来的，不是选定的 |

## 3. 原则

1. **按工作模型分组**：我 → 工作 → 团队 → 能力 → 运行 → 设置。
2. **人和智能体是同一份名册。** 团队是一个入口，三个 tab。
3. **验收是一等公民。** Issues 内置"待验收"视图、工作台首屏第一块、详情页明确的验收与退回。
4. **能力集中，市场是引入门。** 能力库拥有 Skills、Ontology、知识库、MCP 与快捷操作；
   Marketplace 保留自己的入口，并可从能力库页头到达。
5. **设置只保留账户与工作区管理。** 团队用来干活的资产不属于设置。
6. **尽量少动路由。** 变的是标签、分组和新壳；详情路由永不移动。被壳吸收的列表路由做
   一次性重定向——产品未上线，按仓库规则删除旧路径而不是双路径并存。

## 4. 目标导航

六组十二个入口。"我"这一组不带组标题。

| 组 | 入口 | 路由 | 说明 |
| --- | --- | --- | --- |
| *（我）* | 工作台 | `/{slug}/home` | 新增，成为落地页 |
| | 收件箱 | `/{slug}/inbox` | 增加"需要拍板 / 全部"分段 |
| | 对话 | `/{slug}/chat` | 不变 |
| | 我的任务 | `/{slug}/my-issues` | 增加"待我验收"内置范围 |
| 工作 | 任务 | `/{slug}/issues` | 增加"待验收"内置范围 |
| | 自动化 | `/{slug}/autopilots` | 不变 |
| 团队 | 团队 | `/{slug}/team?tab=people\|agents\|families` | 新壳，吸收智能体与智能体小组列表 |
| 能力 | 能力库 | `/{slug}/capabilities?tab=skills\|ontologies\|knowledge\|mcp\|quick-actions` | 新壳，吸收 Skills 与 Ontology 列表及三个设置标签 |
| | 市场 | `/{slug}/marketplace` | 不变 |
| 运行 | 运行时 | `/{slug}/runtimes?tab=machines\|resources` | 增加从设置搬来的资源 tab |
| | 观测 | `/{slug}/usage` | 由 Analytics 改名，路由不变，增加执行记录 tab |
| 设置 | 设置 | `/{slug}/settings` | 19 个标签减到 16 个 |

新增三个顶层入口（工作台、团队、能力库），收敛四个（智能体、智能体小组、Skills、Ontology）。
所有详情路由——`/agents/{id}`、`/squads/{id}`、`/skills/{id}`、`/members/{id}`、
`/marketplace/{id}`、`/runtimes/{id}`——保持不变。

侧栏其余部件位置不动：工作区切换器、新建任务按钮、固定区、搜索入口、帮助菜单。
Discord 卡片删除——`DISCORD_URL` 早已是 `null`，组件什么都不渲染。

## 5. 每个功能的去向

只列出移动、并入、新增、改名或删除的条目。未列出的一切保持现有位置与行为。

### 5.1 壳层与全局

| 功能 | 现在 | 目标 | 动作 |
| --- | --- | --- | --- |
| 落地页 | web 工作区布局、桌面新标签按钮、引导完成、接受邀请后都是 `/issues` | `/home` | 移动 |
| 侧栏分组 | 个人 / 工作区 / 配置 | 我 / 工作 / 团队 / 能力 / 运行 / 设置 | 改结构 |
| `WORKSPACE_PAGES` | 13 键 | 12 键：增 `home`、`team`、`capabilities`；删 `agents`、`squads`、`skills`、`ontologies`。它们的 segment 仍可解析，桌面标签图标照常工作 | 改结构 |
| 命令面板"页面"组 | 由 `WORKSPACE_PAGES` 生成 | 自动跟随；`PAGE_KEYWORDS` 补三个新页面的别名 | 跟随 |
| 导航快捷键 | 11 个 `go*`，缺 `goOntologies` 与 `goMarketplace` | 每个入口一个：`goHome`、`goInbox`、`goChat`、`goMyIssues`、`goIssues`、`goAutopilots`、`goTeam`、`goCapabilities`、`goMarketplace`、`goRuntimes`、`goInsights`、`goSettings` | 改结构 |
| 桌面标签标题与图标 | `tab-presentation` 按 segment 解析；标签栏文案硬编码英文 | 补三个新页面；标签栏文案接入 i18n | 改名 |
| 桌面新标签目标 | `/issues` | `/home` | 移动 |
| Discord 卡片 | 侧栏底部，已禁用 | — | 删除 |

### 5.2 工作台（新）

四块内容，全部由已有查询拼出，无新 API。

| 区块 | 现在的来源 | 内容 |
| --- | --- | --- |
| 待我验收 | 没有，只能在 Issues 手工筛 | 状态分类为 `in_review` 且我创建或订阅的 Issue，按智能体分组 |
| 需要我处理 | 与知会类通知混在收件箱里 | 未读收件箱项，类型为智能体受阻、任务失败、被提及、快速创建失败 |
| 正在进行 | Issues 的"智能体正在工作"筛选片；智能体列表的在线点 | 正在运行的智能体和它们各自在做的 Issue，复用已有的 working-agents 投影 |
| 自动化异常 | 自动化列表的"上次运行"列 | 上次运行失败，或因等待运行时而暂停的自动化 |

页头带三个快速入口：新建任务、交给智能体、新对话，全部复用现有的弹窗与 store。
空工作区状态是首次引导的挂载点，其内容属于另一份规划，本轮不实现。

### 5.3 团队（新壳）

| 功能 | 现在 | 目标 | 动作 |
| --- | --- | --- | --- |
| 成员名册 | 没有列表页，设置的成员标签兼做；`/members/{id}` 已存在 | 团队 → 成员 tab：只读名册，行进入详情页，页头链到设置的成员标签做管理 | 新增 |
| 邀请、改角色、移除、分享链接 | 设置 → 成员 | 留在设置。这是授权，不是名册 | 保留 |
| 智能体列表及其工具栏、范围、表格、批量与行级操作 | `/agents` | 团队 → 智能体 tab，页面主体去掉自身页头后挂载 | 并入 |
| 智能体小组列表 | `/squads` | 团队 → 智能体小组 tab | 并入 |
| 新建智能体 / 新建小组按钮 | 各自列表页头 | 团队页头的一个"新建"菜单：新建智能体、新建智能体小组、邀请成员 | 移动 |
| 智能体、小组、成员详情 | `/agents/{id}`、`/squads/{id}`、`/members/{id}` | 路由不变，面包屑改挂到团队之下 | 保留 |

tab 顺序是成员、智能体、智能体小组，默认落在成员。名册是另外两个 tab 所处的框架；
`/agents` 与 `/squads` 的重定向都显式带上目标 tab，所以旧书签打开的还是原来那一页。
如果日常使用发现落在名册上有摩擦，改默认值只是改一个常量。

### 5.4 能力库（新壳）

| 功能 | 现在 | 目标 | 动作 |
| --- | --- | --- | --- |
| Skills 列表 | `/skills` | 能力库 → Skills tab | 并入 |
| Ontology 网格 | `/ontologies`，i18n 挂在 `settings` 命名空间 | 能力库 → Ontology tab；i18n 迁到 `capabilities` 命名空间 | 并入 |
| 知识库仓库 | 设置 → 资源的知识库区 | 能力库 → 知识库 tab，列出工作区知识库和绑定它的智能体；智能体详情的知识库 tab 仍是绑定入口 | 移动 |
| MCP 服务器库 | 设置 → MCP | 能力库 → MCP tab；智能体详情的 MCP tab 仍是分配入口 | 移动 |
| 快捷操作 | 设置 → 快捷操作 | 能力库 → 快捷操作 tab | 移动 |
| 能力库页头 | — | 标题、计数、"新建"菜单（Skill、MCP 服务器、快捷操作、知识库）和次级动作"从市场引入" | 新增 |
| Skill 与 Ontology 详情 | `/skills/{id}`；Ontology 详情是弹窗 | 本轮不变。把 Ontology 详情升级为 `/ontologies/{id}` 是后续选项 | 保留 |

### 5.5 运行时、观测、市场

| 功能 | 现在 | 目标 | 动作 |
| --- | --- | --- | --- |
| 机器列表及其各类对话框 | `/runtimes` | 运行时 → 机器 tab（默认） | 并入 tab |
| 代码仓库、本地目录、其它资源 | 设置 → 资源 | 运行时 → 资源 tab | 移动 |
| Analytics 标签 | "Analytics" | "观测"。路由 `/usage` 不变；把 `views/dashboard` 改名 `views/insights` 是可选项 | 改名 |
| 用量与错误两个 tab | `/usage` | 不变，作为前两个 tab | 保留 |
| 执行记录 | 没有工作区级视图，运行只在单个 Issue、单个智能体、单条自动化下可见 | 观测 → 执行记录 tab：工作区任务表（时间、Issue、智能体、运行时、状态、时长、成本）加筛选和转录弹窗。**需要新增工作区级 `GET /api/tasks`** | 新增 |
| 市场安装后的去向 | 停留在列表页 | 成功提示增加"打开"动作，跳到装好的智能体或 Skill | 新增 |

### 5.6 瘦身后的设置

账户标签一个不动：个人资料、偏好、快捷键、任务、聊天、通知、API 令牌。
工作区标签保留通用、GitHub、集成、成员、计费、标签、任务状态、属性、插件、实验室。

三个标签移出：资源（仓库与目录去运行时，知识库去能力库）、MCP 与快捷操作（都去能力库）。
现有的 `?tab=` 重定向表增加 `resources` → `/runtimes?tab=resources`、
`mcp` → `/capabilities?tab=mcp`、`quick-actions` → `/capabilities?tab=quick-actions`。

### 5.7 任务详情

| 功能 | 现在 | 目标 | 动作 |
| --- | --- | --- | --- |
| 右栏顺序 | 属性 → 快捷操作 → 插件 → 父任务 → PR → 详情 | 属性 → **执行与交付** → 快捷操作 → 父任务 → 插件 → 详情 | 移动 |
| PR 卡 | 右栏独立区 | 并进执行与交付，和当前智能体状态、最近一次运行、带数量的产物入口、用量合计放在一起 | 并入 |
| "标记完成" | 头部按钮，始终一样 | 状态分类为 `in_review` 时显示"验收通过"，写入 `done`；其它状态不变 | 条件改名 |
| 退回 | 没有，需要手动改状态再写评论 | 头部溢出菜单与新区块：弹出评论框，发表评论并把状态改回 `todo` 分类 | 新增 |

执行日志留在时间线里。页面其余部分不变。

## 7. 实施顺序

阶段 0 到 2 是纯搬家，可以独立发布；3 到 5 是差异化行为；6 收尾平台与验证。

| 阶段 | 内容 |
| --- | --- |
| 0 | IA 契约：`WORKSPACE_PAGES` 与 `paths.ts` 的键、侧栏 nav schema、快捷键注册表、命令面板关键词、四语言 |
| 1 | 侧栏重新分组；设置移出资源、MCP、快捷操作；`?tab=` 重定向 |
| 2 | 三个壳：团队、能力库、运行时资源 tab 与观测 tab 化；面包屑；拆分 `resources-tab.tsx` |
| 3 | 工作台与验收：四个区块、内置验收范围、收件箱分段、落地页切换 |
| 4 | 任务详情：执行与交付区块、条件化验收按钮、退回动作 |
| 5 | 执行记录：工作区任务端点及其 tab；自动化运行历史链接到它 |
| 6 | 桌面标签栏 i18n、新的 tab subject、移动端"更多"页链接、文档路径、内置 skill 里的路由引用、e2e、断点与主题走查 |

## 8. 风险

| 风险 | 应对 |
| --- | --- |
| `issue-detail.tsx` 有 3556 行，改右栏顺序容易引入回归 | 先把每个区块抽成组件且不改行为，再调整顺序 |
| `resources-tab.tsx` 有 1458 行，要拆成三处 | 先补组件测试锁住现有行为，再拆 |
| 执行记录依赖一个还不存在的服务端端点 | 单独提交；阶段 5 可以延后而不阻塞其它工作 |
| 吸收四条列表路由会打断已持久化的桌面标签和外部链接 | 保留 segment 可解析以维持标签图标；每条列表路径一次性重定向到对应 tab；详情路由不动 |
| 页面测试与 e2e 大量断言页头标题和侧栏标签 | `navigation.spec.ts` 在阶段 0 更新，其余跟随各自阶段 |
| 四种语言加术语表 | 新词先进 `conventions.mdx`，再进代码 |
| 移动端必须保持产品语义一致 | 移动端 tab 不变；"更多"页链接和验收范围语义在阶段 6 对齐 |

## 9. 明确不做

- 不改 Issue 看板、泳道、甘特的交互，也不改任务数据模型。
- 不做工作区级产物页。产物仍归产出它的 Issue 或对话，这是 2026-09-05 的决定。
- 不引入组织层。
- 不重组移动端页面。
- 不实现首次引导的内容，工作台只留挂载点。

## 10. 已定的取舍

2026-09-07 批准时有四个待定项，结论如下：

1. **团队是一个入口三个 tab**，不是两个顶层入口。
2. **快捷操作搬到能力库**，不留在设置里。
3. **`/usage` 保留路由**，只改标签，因为改路由会打断已持久化的桌面标签和文档链接。
4. **执行记录留在规划里并单独成阶段**，排在前端工作之后，依赖服务端端点。
