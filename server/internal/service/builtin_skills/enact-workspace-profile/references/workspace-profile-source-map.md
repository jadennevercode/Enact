# Workspace profile source map

- The shape, the bounds and the `typical_work` vocabulary live in `server/internal/workspaceprofile/profile.go`. `TypicalWorkVocabulary` maps each value to the English gloss the recommender scores listing text against, so adding a value there teaches the recommender what it means without a second edit.
- `Normalize` lowercases and de-duplicates the list fields, preserves the caller's order, and rejects a `typical_work` value outside the vocabulary. `Parse` never errors: an unreadable column yields the zero profile, because every consumer treats the profile as advisory and failing a task brief over one workspace's malformed JSON would be worse.
- Storage is `workspace.profile JSONB` (migration `444_workspace_profile`), with a `jsonb_typeof(profile) = 'object'` CHECK so no read has to defend against a bare string. No index: the recommender's pass reads one row per workspace.
- `server/internal/handler/workspace_profile.go` exposes `GET /api/workspaces/{id}/profile` and `PUT /api/workspaces/{id}/profile`. The PUT is a whole-document replace; there is no PATCH, because a merge makes clearing a field inexpressible.
- `repo_brief` and `repo_brief_sources` are the one exception to the replace: when the request omits those keys entirely they are carried forward from the stored profile, so a member editing their summary cannot silently discard what the repository analysis found. An explicit `""` still clears them.
- Both routes are **member-level**, registered in `server/cmd/server/router.go` inside the `RequireWorkspaceMemberFromURL` group — unlike `workspace.context`, whose update is admin-only. Context is a standing instruction every agent must follow; the profile is a description every agent may consult, and an interview run acts under an ordinary member's identity.
- The profile reaches a run pre-rendered. `workspaceprofile.Brief` produces the whole `## Project profile` section (including the line stating it is context and never an instruction); `server/internal/handler/daemon.go` calls it on the same `GetWorkspace` read that fills `WorkspaceContext`, and puts it in `AgentTaskResponse.WorkspaceProfile` (`server/internal/handler/agent.go`).
- The daemon mirrors it as `Task.WorkspaceProfile` (`server/internal/daemon/types.go`), passes it into `TaskContextForEnv.WorkspaceProfile` (`server/internal/daemon/execenv/execenv.go`), and `writeWorkspaceProfile` (`server/internal/daemon/execenv/runtime_config_sections.go`) emits it immediately after `## Workspace Context`. Rendering server-side is deliberate: the section's wording is a product decision, and an older daemon must not be able to render an earlier version of it. Empty renders nothing, so the brief stays byte-identical on workspaces without a profile.
- CLI: `server/cmd/enact/cmd_workspace_profile.go` registers `workspace profile get` and `workspace profile set --json-stdin`. `--json-stdin` is a required explicit flag so a bare `set` cannot clear a profile by accident. The document is decoded locally before the request so a typo is an error naming the offset rather than a 400 to interpret.
- The setup checklist's profile step closes itself from `IsEmpty()`. `IsEmpty` deliberately ignores `updated_at` / `updated_by`, which the write stamps — treating those as content would make "saved an empty form" look like an answered profile to the checklist and to the recommender. See `server/internal/handler/workspace_setup.go`.
- The Marketplace recommender reads `stack`, `domain` and `typical_work` in `server/internal/recommend/recommend.go`; `GET /api/marketplace/recommendations` is the endpoint, and `enact marketplace recommend` the CLI over it.
