# Resources source map

- `server/cmd/enact/cmd_resource.go` registers `resource list/add/update/remove`.
- `resource add` supports shortcuts for `github_repo` (`--url`, non-JSON `--ref` for the checkout ref, `--default-branch-hint`) and `local_directory` (`--local-path`, `--daemon-id`, `--ref-label`, `--execution-mode`), or a generic JSON `--ref '<json>'`. The shortcut merging lives in `buildResourceRefFromFlags` / `buildResourceRefFromRefFlag` in the same file.
- `resource update` merges shortcut edits with the existing `resource_ref` so a partial edit does not clobber required fields; a non-JSON `--ref` updates `github_repo.resource_ref.ref`. It re-reads the row through `fetchWorkspaceResources` first because the server replaces `resource_ref` wholesale.
- `resource update` / `remove` accept a short id prefix, resolved by `resolveWorkspaceResourceID` in `server/cmd/enact/cmd_id_resolver.go`.
- `local_directory.execution_mode` is validated in `server/internal/handler/workspace_resource.go` (`validateLocalDirectoryRef`); the daemon reads it in `server/internal/daemon/local_directory.go` (`localDirectoryAssignment.UsesWorktree`) and builds the per-task worktree in `server/internal/daemon/execenv/local_worktree.go`.
- Saving `execution_mode=worktree` is gated on the daemon having advertised the `local-worktree-v1` capability (`protocol.DaemonCapabilityLocalWorktreeV1`), checked by `requireWorktreeCapableDaemon` in `server/internal/handler/workspace_resource.go` against the daemon's most recently seen runtime row; not capable → HTTP 422 `daemon_version_unsupported`. The authoritative gate is at claim time (`worktreeClaimBlockReason` in `server/internal/handler/daemon.go`), which reads the capability off the claim request itself and cancels the task with a reason. `MinLocalWorktreeCLIVersion` (`server/pkg/agent/version.go`) is only the number shown to the user; nothing gates on it.
- One `local_directory` per (workspace, daemon) is enforced by `findLocalDirectoryConflict` in `server/internal/handler/workspace_resource.go` (HTTP 409). The daemon re-checks in `findLocalDirectoryAssignment` (`server/internal/daemon/local_directory.go`) and fails the task rather than guessing when two match.
- `server/cmd/server/router.go` exposes `GET/POST /api/resources` and `PUT/DELETE /api/resources/{resourceId}`, plus `GET /api/artifacts`.
- `server/pkg/db/queries/workspace_resource.sql` is the CRUD query surface for `workspace_resource` rows (migration `432_workspace_resource`).
- Resources reach a running task through the claim response: `applyWorkspaceResourcesToClaim` (`server/internal/handler/workspace_resource.go`) fills `AgentTaskResponse.WorkspaceResources` (`server/internal/handler/agent.go`). That field deliberately keeps the wire name `project_resources` so already-installed daemons keep receiving it.
- The daemon mirrors it as `Task.WorkspaceResources` (`server/internal/daemon/types.go`), converts it with `convertWorkspaceResourcesForEnv` (`server/internal/daemon/daemon.go`) into `TaskContextForEnv.WorkspaceResources` (`server/internal/daemon/execenv/execenv.go`), renders the brief's `## Workspace Resources` section from it (`writeWorkspaceResources` / `formatWorkspaceResource`, `server/internal/daemon/execenv/runtime_config_sections.go` and `runtime_config.go`), and writes `.enact/project/resources.json` from it (`writeWorkspaceResourcesFile`, `server/internal/daemon/execenv/context.go`). The on-disk path keeps its `project` segment on purpose — installed agents and skills already read it there.
- `github_repo.resource_ref.ref` is lifted into `RepoData.Ref` by `applyWorkspaceResourcesToClaim`; `server/internal/daemon/daemon.go` stores it per task (`taskRepoDefaultRef`), and `server/internal/daemon/health.go` uses it as the default `/repo/checkout` ref when the checkout request does not pass one.
- Artifacts: `ListArtifacts` (`server/internal/handler/artifact.go`) serves `GET /api/artifacts` from `ListAttachmentsByWorkspace` (`server/pkg/db/queries/attachment.sql`). The query's `OwnerIssueID` / `OwnerIssueNumber` / `OwnerIssueTitle` are nullable, so a chat-origin attachment comes back with no owner and the handler omits all four `owner_issue_*` fields rather than synthesising `ENA-0`. `?limit=` is clamped by `artifactLimit` (default 500, max 2000) and the response's `truncated` flag reports that the cap was hit.
