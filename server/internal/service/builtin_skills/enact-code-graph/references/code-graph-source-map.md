# Code graph source map

- `server/cmd/enact/cmd_graph.go` registers `graph status/report/query/path/explain/affected/communities` and owns repository resolution: `--repo`, else `git config --get remote.origin.url`, normalized by `codegraph.NormalizeRepoURL` and matched against the workspace's `github_repo` resources. A repository that is absent, not a workspace resource, or not opted in returns `errGraphUnavailable`, which `cmd/enact/main.go` prints as one line and exits 2.
- Every read goes to `/api/code-graph/resources/{resourceId}/...`, registered by `RegisterCodeGraphRoutes` in `server/internal/handler/code_graph.go` and mounted next to the semantic routes in `server/cmd/server/router.go`. Membership is rechecked on every call (`codeGraphScope`); task tokens may read everything, and only a human owner/admin may `rebuild`.
- The opt-in is `resource_ref.code_graph` on a `github_repo` resource, validated in `server/internal/handler/workspace_resource.go` (`githubRepoRef.CodeGraph`, `rejectCodeGraphFlag`). `local_directory` and `knowledge_repo` are refused: the builder clones over the network, and a knowledge base is documents, not code.
- Builds are rows in `code_graph_build` (migration `540_code_graph_build`, indexes `541`/`542`), queried through `server/pkg/db/queries/code_graph_build.sql`. `EnqueueCodeGraphBuild` is guarded by `NOT EXISTS (... queued|building)`, which is what collapses a push burst, a flag flip and a poll onto one pending build.
- `server/internal/handler/code_graph_worker.go` claims rows with a Postgres lease (`ClaimQueuedCodeGraphBuild`), mints a short-lived clone credential (GitHub App installation token, or the stored VCS token for a self-hosted instance), calls the container, and records the verdict. Attempts are capped at 3; `busy` and `unavailable` are retried, anything else is recorded as `failed` for the member to read.
- Triggers: the opt-in flip (`CreateWorkspaceResource` / `UpdateWorkspaceResource`), a GitHub `push` on the tracked branch (`handlePushEvent`, debounced 5 minutes), a 6-hour head sweep (`RefreshHeads`), and a status read that finds the ready build behind the known head.
- `server/internal/codegraph` is the container client: `Build`, `Status`, `Delete`, `Health`, and `Forward`, which proxies a read to the container and copies its status. Container errors collapse onto `ErrDisabled` / `ErrUnavailable` / `ErrBusy` / `ErrNotBuilt`; the container's own message is never surfaced.
- `report_md` is stored in Postgres and served by `GET .../report` from there. It is deliberately absent from status payloads: a monorepo report runs past 200 KB while the status endpoint backs a UI chip. Graph data itself never enters Postgres — it stays on the container volume in graphify's own `graphify-out/` layout.
- Confidence values (`EXTRACTED` / `INFERRED` / `AMBIGUOUS`) and the `calls` resolution limits come from graphify's extractors; cross-file call resolution is strongest in Python. The container pins its graphify version and echoes it in `stats.graphify_version`.
- The brief points at this skill from `writeRepositories` in `server/internal/daemon/execenv/runtime_config_sections.go`; that sentence is fixed text, because the brief must stay byte-identical across the runs of one resumed session.
