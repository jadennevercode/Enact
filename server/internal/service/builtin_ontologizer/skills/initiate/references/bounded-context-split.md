# 拆成有界上下文

只在规模检查判 `over` 且人选了 `split_bounded_contexts` 时才走这一步。
拆分是个代价不小的决定：每一块要有自己的章程、自己的证据登记、自己的版本线。

## 怎么找切口

按"同一个词在两块里意思不同"来切，不是按部门切。

日记账这个例子里，"分录"在总账域是一条待过账的凭证行集合，
在报表域是一个已结账的余额来源——同一个词，两种身份、两套生命周期。
这就是一条真实的边界。

其他可靠的切口信号：

- **术语冲突**：同名不同义，或同义不同名。这是最硬的信号。
- **负责人不同**：两块材料的确认人不是同一个人，说明业务归属不同。
- **引用稀疏**：两块之间只有三五条关系，而块内密密麻麻。
- **生命周期不同**：一边按月结周期走，一边按凭证走，节奏对不上。

不可靠的切口：文件目录结构、数据库 schema 划分、组织架构图。
它们反映的是历史，不是语义。

## 拆完要交代的三件事

**1 · 每块一句话问题陈述。** 拆出来的每块都要能独立说清"它回答什么问题"。
说不清的那块，说明它不是一个上下文，是另一块的一部分。

**2 · 跨块的关系显式列出来。** 拆分不等于两块之间没有关系。
把跨块引用写进各自章程的 `out_of_scope` 附近，说明"这条关系存在，但由哪一块负责定义"。
不写的结果是两边各定义一次，然后在提交时发现对不上。

**3 · 先做哪一块，为什么。** 通常是问题陈述最紧、材料最全的那块。
把这个顺序和理由记进 `scope_and_boundary` 的裁决理由。

## 每块是一个独立项目

一块一个工作区，各自 init：

```bash
python3 <pkg>/scripts/state.py init <目录>/gl-reversal --slug gl-reversal --domain "总账 · 冲销" --goal "..."
python3 <pkg>/scripts/state.py init <目录>/period-close --slug period-close --domain "期末关账" --goal "..."
```

不要用一个工作区装两块。共用一份证据登记与一条版本线，
"这个对象属于哪一块"就没有地方记录，而这正是拆分要解决的问题。

## 也可能拆不动

材料看下来发现处处交叉、术语一致、负责人是同一个人——那就是一块业务，只是大。
这时候老实说拆不动，改选分阶段交付。假装能拆而拆出来的边界，
会在生成阶段以"这个实体到底归哪块"的形式回来。
