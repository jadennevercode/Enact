# 高风险内容

流程 §7.2-4 要求对七类内容标高风险待审。它们的共同点：**抽取错了，
错误看起来完全正常**——没有乱码、没有缺失，只是内容不对。

标出来的东西进 manifest 的 `high_risk_content`，并在 `confirm` 那一步优先让人过目。

## 七类

| 类别 | 典型错法 | 这批材料里的实例 |
|---|---|---|
| 标识符 | 大小写、前后缀、连字符被规整掉 | `JE-2026-0091` 被写成 `JE20260091`，与 `reversal_of` 对不上 |
| 表格 | 表头行认错、合并单元格拉平、列错位 | `journal-entries-sample.csv` 的 `tax_included` 与 `currency` 相邻，串列后金额口径全反 |
| 代码 | 缩进、转义、注释被吞 | 无 |
| 数字 | 千分位、负号、单位、精度 | `-45000.00`（负号是冲销分录的关键）、`50,000` 的逗号、`86400.00` |
| 不清的连接线 | 箭头方向读反，或凭直觉补一条不存在的线 | 流程图「审批通过?」的否分支连线断开 |
| 缺失的端点 | 分支没有终点，抽取时顺手补一个"合理"的 | 否分支无去向；回滚之后无去向 |
| 结构不一致 | 同一份材料里两种编号体系、两种表述被当成一种 | 手册用 §6.2/1-5 编号，政策用 §3.1-3.4，混引会指错地方 |

## 数字这一类特别要小心

`50,000` 这个阈值在两份材料里都出现，都没说含税与币种。样本里恰好有两条卡在边界上：

- `JE-2026-0110`：金额 50,000，`tax_included=Y`。含税算就正好达标由 Controller 批，
  不含税算就低于阈值由主管批。**同一条分录，两种口径下审批人不同。**
- `JE-2026-0105`：7,300 USD。按原币远低于阈值，按本位币折算后可能超过。

所以这条要同时进 `high_risk_content` 和一条 `assumption`（`asm.001`），
再挂一条有主的未决事项（`ud.002`）。只标高风险不开假设，它会在生成时被
默默按某一种口径写进属性。

## 连接线与端点

流程图上"这条线通向哪里"是最容易被善意填补的地方。抽取时的规矩：

> **图上没有的线，抽取里就没有。**

`flow-diagram-notes.md` 里三处：

1. 「审批通过?」的否分支连线断开，没有指向任何节点；
2. 回滚之后指向哪里，图上没有画；
3. 右下角一个标着「复核」的孤立方框，没有任何连线进出。

正确的抽取是把这三件事**作为事实记下来**——图上就是这样。
锚点的 `exact_snippet` 记图上有什么（"否 →（图上此处连线断开）"），
不记我们认为它应该是什么。

补线是 `interview` 的活。访谈里 PO1 说"退回制单人"，那时才在 FAGC 里
新增一条 `fact`，`source_ids` 指访谈，`location` 写 `访谈 q.202`。
证据阶段直接补上去，就是把推断写成了文档里的事实。

第 3 条最微妙：「复核」方框和政策 §3.4 的"制单、审批、复核三项职责不得由同一人承担"
显然有关。但"有关"是我们的联想，图上没有任何线支持它。
记成 `high_risk_content` 加一条 open path，不要记成"复核是流程的一个环节"。

## 标了之后怎么用

`high_risk_content` 里的每一条，在 `confirm` 那一步单独摆给人看，
一次一条，带原文与我们的读法，问的是"这样读对吗"，不是"确认吗"。

标了但没人看过的高风险内容，等于没标。所以 `human_confirmation_status`
在有 `high_risk_content` 的条目上，`confirmed` 的含义是"这些高风险点都过目了"，
不是"这份材料大致没问题"。
