# 模型卡

一张卡 = 一条"我们打算把这个东西建成一个对象"的线索。

卡不是 candidate。卡上没有稳定技术 ID、没有基数、没有 support 链、没有 definition——
那些是 `generate` 的活。卡的唯一作用是：**让人在生成之前就看见我们打算建什么，
并且当场改掉错的。**

## 形状

```yaml
cards:
  - id: mc.006
    kind: role                                  # 六选一
    name: 审批人
    aliases: [审核人]                            # 原始短语，不翻译不归一
    source_phrase: "审批人不得是该分录的制单人"    # 引证据或访谈原话
    source_ref: ev.001 §6.2/3
    note: 人改过一次——原先当成实体，确认后是员工在一次申请里的资格
    raised_in_round: 2
```

必填只有三样：`kind`、`name`，以及 `source_phrase` 或 `assumption_ref` 之一。
检查项 `model_cards_sourced` 核这三样，并且会拿 `assumption_ref` 去 FAGC
里查那个 `statement_id` 是否真的存在。

## 出处二选一

**`source_phrase`** —— 一句原话，来自证据或访谈。逐字，中英混排照抄。
配 `source_ref` 指出它在哪（`ev.001 §6.2/3` 或 `访谈 q.202`）。

**`assumption_ref`** —— 指向 FAGC 里一条 `assumption` 的 `statement_id`。
用在"这个东西材料里没直接说，但我们判断它存在"的场合。

```yaml
  - id: mc.005
    kind: attribute
    name: 金额口径
    assumption_ref: asm.001        # 政策明说没定义含税与币种，挂假设
    note: ud.002 未裁决前不要写成事实
```

两样都没有的卡过不了检查，而且这条检查存在的理由就写在它的失败提示里：
**它是从哪里来的必须能说出口。** 一张说不出出处的卡，会在生成阶段变成一个
说不出依据的对象，而那时候它已经长得像模像样了。

## 六种 kind

判据全在 `knowledge/discovery-heuristics.md`，这里只给这批材料里的落点和最容易错的那几个。

| kind | 这个域里的例子 |
|---|---|
| `entity` | 日记账分录、冲销分录、冲销申请单、会计期间、原因代码、员工 |
| `event` | 冲销分录生成、审批通过、过账成功 |
| `relationship` | 冲销了（`reversal_of`）、属于期间 |
| `attribute` | 金额、状态、过账日期、原因代码取值 |
| `role` | 制单人、审批人、复核 |
| `state` | draft、posted、reversed |

**最常见的三种错判：**

1. **把角色建成实体。** 「审批人」在文本里和「员工」长得一样，但它是员工在
   一次冲销申请里的资格——同一个人在另一条分录上可能是制单人。
   检查问题：换一条分录，他还是"审批人"吗？不是 → 是角色。

2. **把状态建成实体。** 「已冲销」是分录生命周期上的一个可枚举条件，不是一个对象。
   检查问题：它有独立的编号或主键吗？

3. **只建名词漏掉事件。** 「冲销」既是事件（`evt.reversal_created`）又是关系
   （`rel.reverses`），两个都要建。只建关系，模型就答不出"什么时候冲的、谁批的"；
   只建事件，就答不出"这条冲销分录对应哪条原始分录"（cq.003）。

## 卡与 readiness 的关系

`core_objects` 这一项被 `corrected` 时，通常意味着有一张卡要改 `kind` 或者要删掉。
两处要一起改，不要只改 readiness 的 `answer` 而把卡留在原地——

`readiness.yaml` 记的是人说了什么，`model-cards.yaml` 记的是我们据此打算建什么。
两者分叉之后，生成阶段读的是后者，而人以为自己已经纠正过了。

## 一张卡可以先记着不确定

卡上允许有 `note` 写明还没想清楚的部分：

```yaml
  - id: mc.008
    kind: role
    name: 复核
    source_phrase: "制单、审批、复核三项职责不得由同一人承担"
    source_ref: ev.002 §3.4
    note: >-
      流程图右下角有个孤立的「复核」方框，没有任何连线进出。
      政策说它是三职之一，但没有材料说明它在冲销流程里做什么、什么时候做。
      建成角色还是步骤未定，等 PO 补一份说明。
```

这比两种选择：（a）不记，等于假装没看见；（b）猜一个 kind 记上，等于把猜测
变成默认。第三条路——记下来并写明未定——是唯一让它在审阅时还能被看见的做法。
