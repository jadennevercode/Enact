マーケットプレイスは、インストールできる機能のディレクトリです。[スキル](/skills)、エージェントテンプレート、Agent Family、MCP サーバーの項目が並びます。インストールすると自分のワークスペースに**コピー**が作られ、以後は自分で書いたものと同じように編集できます。

<Callout>
現在、公開は運営側が管理しています。ディレクトリの中身はデプロイ自身が用意したもので（AI-SDLC の開発体制が同梱されています）、アプリ上に公開・管理の操作は表示されません。API はワークスペースの owner または admin からの公開を今も受け付けており、デプロイ自身の項目はそこを通って入っています。
</Callout>

## 何が入っているか

| 項目 | 内容 |
|---|---|
| **AI-SDLC Delivery** | intake、explore、contract、build、QA、release、operate、learn と、記録をまたいで判断する orchestrator の 9 ロールからなる Agent Family。実行に使う 10 個の `sdlc-*` スキルつき |

各メンバーエージェントと各スキルは単体の項目としても並んでいます。Family 全体ではなく一部だけ欲しいチームのためです。

ディレクトリの各項目には、自分のワークスペースから見て**インストール済み**か**未インストール**かが表示され、どちらでも絞り込めます。すでに取り込んだ Agent Family も、1 つのスキルと同じようにインストール済みとして表示されます。

## 公開できるもの

| 種類 | 一緒に渡るもの | 渡らないもの |
|---|---|---|
| **スキル** | `SKILL.md` とすべての参考ファイル | なし —— スキルは文章であり、書かれたまま公開されます |
| **エージェントテンプレート** | 名前、説明、指示、モデルと思考の設定、付属するスキル、必要な MCP サーバー | 環境変数、ランタイムの紐づけ、ランタイムの設定、誰が呼び出せるかの設定 |
| **Agent Family** | Family の説明と連携の方針、そして各エージェントメンバーの完全なテンプレート —— それぞれが自分のスキルと MCP サーバーを持ったまま渡ります | 中にいる人間のメンバー、そしてリーダーの行 ID。リーダーは「どのメンバーか」で識別されます |
| **MCP サーバー** | 認証情報をすべて取り除いたサーバー項目 | `env` とヘッダーの値。公開すると指定しない限り URL も渡りません |

1 つの Agent Family が持てるエージェントは最大 16 体、そのエージェント 1 体が持てるスキルは最大 32 個です。人間のメンバーは公開されずに取り除かれます。指しているのは自分のワークスペースのメンバーであって、ほかのワークスペースのメンバーではないからです。Family をインストールした人が、自分のところのメンバーを追加します。

<Callout type="warn">
公開でブラウザから内容がアップロードされることはありません。自分のワークスペースにあるエンティティを指定すると、サーバーがそれを読み取り、認証情報を含むフィールドをすべて取り除いてから結果を保存します。この仕組みだからこそ、伏せ字の処理を信頼できます。
</Callout>

## 公開する

ディレクトリを運営側が管理している間、アプリ上に公開・管理の操作は表示されません。以下は API が今も実行する公開の説明です。デプロイ自身のディレクトリもこの経路を通っており、公開が開放されたときに画面に戻ってくるのもこれです。

公開ではメタデータのほかに、決めることが 2 つあります。

- **公開範囲。**`このワークスペースのみ`はチーム内部のライブラリです。`公開`にすると、このデプロイのすべてのワークスペースに届きます。まず内部で公開し、準備ができてから公開に切り替えられます。インストールの手順はどちらも同じです。
- **バージョン。**公開済みのバージョンが上書きされることはありません。同じハンドルで再度公開すると、同じ項目にバージョンが 1 つ追加されるので、リンクはそのまま使え、履歴も 1 か所にまとまります。すでにある version 文字列での再公開は拒否されます。

### 公開元が伏せる値

MCP サーバーでは、`env` の値、ヘッダーの値、URL が空の値に置き換えられ、マニフェストには**インストール時に入力が必要な値**として並びます。項目をインストールする人が自分の値を入力します。ある値が本当に認証情報ではない場合 —— たとえば公開されたエンドポイントなど —— は、そのまま公開するよう指定できます。

サーバーの `command` や `args`、あるいはエージェントのカスタム引数に認証情報が直接書かれている場合は、伏せ字にするのではなく**公開が失敗します**。プロセスの起動コマンドを黙って書き換えるほうが、拒否するより悪い結果になるからです。その値をサーバーの環境変数へ移してから、あらためて公開してください。

## インストールする

項目を開くと、インストールで何が作られるかがわかります。エージェントテンプレートなら、付属するスキルと必要な MCP サーバーが並び、Agent Family ならすべてのメンバーエージェントが漏れなく並びます。確認したら**インストール**を選びます。

フォームで聞かれるのは、項目側では知りようがないものだけです。

- **このワークスペースでの名前。**空欄のままにすると公開時の名前を使います。
- **ランタイム**（エージェントテンプレートまたは Agent Family の場合）。テンプレートはマシンを指定しないので、自分のワークスペースから 1 つ選びます。Family ではすべてのメンバーがそのランタイムに紐づき、あとから 1 体ずつ移すこともできます。テンプレートが別のプロバイダー向けに作られていても、そのランタイムが対応していない設定は未設定のままになるだけで、インストールが止まることはありません。
- **公開元が伏せた値**（その項目にある場合）。Family の場合は、2 つのメンバーが同じ名前のサーバーを必要とすることがあるため、サーバー名だけでなくメンバー名でも区別されます。

### Agent Family をインストールする

Family のインストールは 1 回の操作で、必要なものをすべて作ります。メンバーの各エージェント、それぞれが付属するスキル、それぞれが必要とする MCP サーバー、そしてそれらをまとめる Family が、公開時のリーダーと役割のまま作られます。すべてが作られるか、1 つも作られないかのどちらかです。メンバーが半分しか届かなかった Family は、存在しないエージェントに仕事を割り振ってしまいます。

名前がすでにワークスペースで使われているメンバーは、既存のものを置き換えるのではなく、接尾辞の付いた名前でインストールされます。インストールされたエージェントはどれも最初はあなただけのものなので、チームから使ってほしいものには、あとから必要な公開範囲を設定してください。

名前がすでに使われている場合は、スキルのインポートと同じ選択肢が示されます。別の名前でインストールするか、既存のものを置き換えるかです。置き換えられるのは、置き換え対象のスキルを最初に作成した本人だけです。

## インストールはコピーであって、購読ではない

インストールしたスキルやエージェントが、その後に元の項目を追いかけることはありません。自分のコピーは安全に編集できますし、項目に新しいバージョンが出ても、誰かがインストールするまでは何も変わりません。

マーケットプレイスはどのバージョンを取り込んだかを覚えているので、新しいものが公開されると、すでに持っている項目に**vX に更新**と表示されます。更新を取り込むことは、そのバージョンを自分の意思でインストールすることです。

<Callout>
インストール済みのスキルは、スキルのページから再取得できません。「ソースから更新」は、ある URL が今日返す内容を再ダウンロードするものです。マーケットプレイスの更新は、自分で選んだバージョンをインストールする操作です。項目のページを使ってください。
</Callout>

## 項目を取り下げる

公開元のワークスペースは、項目を**非推奨にする**ことができます。この場合、一覧からは見えなくなりますが、すでに依存している人はインストールできます。**取り下げる**と、新しいインストールが完全に止まります。ディレクトリを運営側が管理している間、どちらも API からの操作です。

どちらも、すでにインストールしたワークスペースには影響しません。そのコピーはインストールした側のものです。

## オントロジー

マーケットプレイスの最後のタブにはオントロジーが並びます。これらは項目ではありません。Capability Hub から提供され、ワークスペースにコピーされるのではなく、エージェントに紐づけられます。このタブがあるのは、機能を 1 か所で見つけられるようにするためです。紐づけの管理は[オントロジー](/skills)のページで行います。

自分のワークスペースがすでに紐づけているオントロジーも、ほかと同じように**インストール済み**と表示され、インストール済み／未インストールの絞り込みはこのタブでも効きます。

## CLI を使う

```bash
enact marketplace list --kind skill --output json
enact marketplace list --not-installed --output json
enact marketplace get <listing-id> --output json
enact marketplace install <listing-id> --output json

# エージェントテンプレートにはランタイムと、伏せられた値が必要です。
enact marketplace install <listing-id> \
  --runtime-id <runtime-id> \
  --secret env.GITHUB_TOKEN=... \
  --output json

# Agent Family の kind は squad です。すべてのメンバーが 1 つのランタイムに紐づき、
# 伏せられた値はサーバー名だけでなくメンバー名も含みます。
enact marketplace list --kind squad --output json
enact marketplace install <listing-id> \
  --runtime-id <runtime-id> \
  --secret reviewer/github/env.GITHUB_TOKEN=... \
  --output json
```

`enact marketplace list` は行ごとに `INSTALLED` を表示します。自分が持っているバージョンか、`no` です。`--installed` / `--not-installed` を使うと、どちらか一方に絞り込めます。

公開のコマンドはありません。公開はワークスペースから何を出すかについての管理者の判断であり、API はエージェントからの呼び出しを拒否します。デプロイ同梱の項目は、それを保持するワークスペースから起動時にサーバーが公開します。

## 権限

| 操作 | 誰ができるか |
|---|---|
| 項目の閲覧と表示 | ワークスペースのメンバー全員 |
| スキル、エージェントテンプレート、Agent Family のインストール | ワークスペースのメンバー全員 |
| MCP サーバーのインストール | ワークスペースの owner または admin |
| 項目の公開、編集、非推奨化、取り下げ | 公開元ワークスペースの owner または admin（API 経由。管理中は画面に入口はありません） |

エージェントは閲覧とインストールができます。公開はできません。
