新しいワークスペースには、受信トレイのメッセージが 1 通と、4 つのステップを持つタスクが 1 つ用意されています。どちらもあるのは、ここでのエージェントがチャット窓ではないからです。実在のコンピュータで動き、実在のファイルを読み、あなたのプロジェクトが何かを知っているほど良い仕事をします。

ステップは自動的に閉じます。ランタイムが接続されたか、リソースがあるか、プロファイルが記入されたか——それぞれ実際の状態と照合されるので、タスクを開かなくても、やれば閉じます。

## 4 つのステップ

### コンピュータを接続する

エージェントはあなたが管理するマシン上で、あなた自身の agent CLI とアカウントで動きます。コードも認証情報も今ある場所にとどまります。サイドバーの **ランタイム** を開いてください。まずはノート PC で十分です。

ランタイムが接続されるまで何も動かないので、これが最初です。

### コードを接続する

**設定 → リソース** で、ワークスペースを Git リポジトリか、接続済みマシン上のディレクトリに向けます。

リソースはポインタであってコピーではありません。タスクが必要とするときだけエージェントがチェックアウトし、Enact には何もアップロードされません。

### このプロジェクトが何かを伝える

**プロジェクトプロファイル**は、プロジェクトについての一言か二言、使っている技術スタック、そしてここで扱う仕事の種類です。**設定 → ワークスペース** で記入するか、チャットで Mika に頼んでください。いくつか質問して代わりに書いてくれます。

<Callout>
最も多くを変えるのがこのステップです。以下のすべてがこれに依存します。
</Callout>

### 推奨された能力を見る

プロファイルができると、[Marketplace](/marketplace) がそれを基準にディレクトリを並べ替え、合うものを理由とともに上位に表示します。入れたいものを入れ、不要なものを却下すれば、このステップは閉じます。

## プロファイルが実際にすること

読み手は 2 つあります。ワークスペースコンテキストの中の一段落ではなく独立したフィールドである理由がそこにあります。

**すべてのエージェント実行がここから始まります。** 実行のブリーフに独立したセクションとして描画されるので、実行のたびに手当たり次第のファイルから慣習を推測せずに済みます。これは指示ではなく背景情報です。セクション自身がそう書いており、実行はワークスペースコンテキストを要件として適用し、プロファイルは説明として参照します。

**Marketplace がこれを基準に並べ替えます。** `stack` と `typical_work` が、リスティングが何のためのものかと照合されます。プロファイルが空なら並べ替えの根拠がなく、このデプロイが提供するものへのフォールバックになります。

`typical_work` は固定リストです——コードを書く、コードレビュー、プロダクト計画、調査・分析、ドキュメント作成、運用自動化、データ分析、知識モデリング、デザイン、サポート、コンプライアンス。固定なのは、推奨エンジンがこれらの値をリスティングのテキストに対応づけるからで、自由記述に対してはルールが書けません。収まらないものは概要か制約に書けば、やはりすべての実行に届きます。

ワークスペースコンテキストと違い、プロファイルはどのメンバーでも編集できます。何の権限も与えず何も指示せず、それを埋めるインタビューは一般メンバーの権限で動きます。

## リポジトリを読む

初めてリポジトリを接続したとき——ワークスペースにすでにプロファイルがあり、ランタイムに紐づいた Mika がいれば——それを読むためのタスクが 1 つ作られます。

彼女はリポジトリをチェックアウトし、README、パッケージマニフェスト、CI 設定、ツリーの上位数階層を読み、見つけたことをプロファイルの **リポジトリ** フィールドに書きます。言語、フレームワーク、ビルド方法、テスト方法、ツリーの構成です。

このフィールドは設定画面では読み取り専用です。実際にコードを読んだ実行が書いたもので、プロジェクトについてのあなた自身の言葉ではなくリポジトリについての証拠だからです。概要を書き直してもこれは失われず、その実行があなたの概要を書き換えることもありません。

プロファイルがまだない、あるいはランタイムがない場合、何も作られません。誰も説明していないプロジェクトに付けられたリポジトリレポートは、誰も求めていないレポートです。

## CLI から

```bash
enact workspace profile get --output json

enact workspace profile set --json-stdin <<'JSON'
{
  "summary": "中堅運送会社向けの物流コントロールタワー。",
  "domain": "logistics",
  "stack": ["go", "typescript", "postgres"],
  "languages": ["ja", "en"],
  "typical_work": ["ship_code", "review_code"],
  "constraints": "本番変更には二人目のレビューが必要。"
}
JSON
```

`profile set` はマージではなく**全体置換**です。省いたフィールドはクリアされます。まず現在のものを読み、変更を加えて送り返してください。例外はリポジトリ関連の 2 フィールドで、ドキュメントがそれらに一切触れていない場合は引き継がれます。

## この機能より前に作られたワークスペース

Marketplace またはウェルカムモーダルを開くとチェックリストが読まれ、読むこと自体が不足しているステップを作成します。手作業の移行は不要で、すでに満たされているステップは同じ読み取りで閉じます。
