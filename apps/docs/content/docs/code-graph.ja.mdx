コードグラフは 1 つのリポジトリの構造マップです。ファイル、クラス、関数、それらの間のインポートと呼び出し、そしてそれらの接続が形づくるサブシステムを含みます。Enact はリポジトリのソースから [graphify](https://github.com/safishamsi/graphify)（Apache-2.0 / MIT）を使ってサーバー側で構築し、tree-sitter による構文解析だけを行います。モデルは呼び出さないため構築にトークンはかからず、リポジトリは Enact デプロイメントの内部でのみクローンされます。

エージェントはファイルを読み始める前に正しいサブシステムを見つけるために使い、人はリポジトリがどのように組み立てられているかを見るために使います。

## リポジトリごとに有効化する

コードグラフはリポジトリ単位のオプトインで、それ以外に設定するものはありません。

- **設定 → リソース** で **GitHub から選択** するか Git URL を貼り付けるとき、**選択したリポジトリのコードグラフを構築する** にチェックを入れます。この選択は、そのダイアログで追加するすべてのリポジトリに適用されます。
- 後から、リポジトリ行のメニューで **コードグラフ** をオン / オフに切り替えられます。

オンにすると最初の構築がキューに入ります。オフにすると、そのリポジトリのすべての構築がサーバー上のデータも含めて削除されます。

デプロイメントにコードグラフサービスがない場合（[デプロイ](#デプロイ)を参照）、チェックボックスは注記付きで無効になります。ローカルディレクトリには提供されません。サーバーはあなたのマシン上のディレクトリを読む手段を持たないためです。

## ステータスチップの意味

有効化すると、リポジトリ行にチップが表示されます。

| チップ | 意味 |
|---|---|
| **準備完了 · a1b2c3d · 2 時間前** | そのコミットのグラフを照会できます。チップをクリックするとコードグラフページが開きます。 |
| **構築中…** | 構築がキューにあるか実行中です。その間、エージェントはファイルツールで作業を続けます。 |
| **スキップ · ファイル数超過** | リポジトリがファイル数の上限を超えています。何も構築されず、部分的なグラフもありません。 |
| **失敗 · 理由** | クローンまたは構築に失敗しました。**再試行** で再度キューに入れます。 |
| *（チップなし）* | このリポジトリではコードグラフが有効になっていません。 |

## コードグラフページ

有効化した各リポジトリには **インテリジェンス → コードグラフ** の下にページがあり、チップからも開けます。ヘッダーには構築元のコミット、構築時刻、サイズが表示されます。ワークスペースのオーナーと管理者は **再構築** を実行できます。

| タブ | 表示内容 |
|---|---|
| **概要** | 構築レポート：最大のサブシステム、最も接続の多いノード、意外なサブシステム間のリンク、前回の構築からの変更点。 |
| **サブシステム** | 各サブシステムのサイズと凝集度、生成された説明記事、主要ファイル（構築時のコミットで GitHub にリンク）。 |
| **グラフ** | サブシステムをノードとし、辺の太さが相互参照の多さを示します。サブシステムをクリックすると展開し、ノードをクリックすると近傍と `ファイル:行` が表示されます。大きな投影は次数で切り詰められ、その旨が表示されます。 |
| **ツリー** | ファイルとシンボルの階層を折りたたみツリーで表示します。 |
| **コールフロー** | サブシステムごとに 1 つの図で、それをつなぎ止めている呼び出しを示します。 |

<Callout type="info">
サブシステムは、グラフのクラスタリングが見つけたコミュニティで、最も接続の多いメンバーの名前が付きます。ディレクトリではなく構造的なグルーピングです。1 つのサブシステムが複数のパッケージにまたがることも、1 つのパッケージが複数に分かれることもあります。
</Callout>

## エージェントの使い方

`enact` CLI は、有効化されたリポジトリをチェックアウトしたすべてのエージェントにグラフを公開します。組み込みスキルはエージェントに、まず `enact graph status` を実行し、グラフが準備完了ならファイルを開く前にレポートを読み、グラフに照会するよう指示します。

```bash
enact graph status                 # 準備完了 / 構築中 / 未有効、およびコミット
enact graph report                 # 概要タブと同じレポート
enact graph query "webhook 配信はどこでリトライされるか"
enact graph path "IssueHandler" "TaskQueue"
enact graph explain "WebhookDeliveryWorker"
enact graph affected "EnqueueTask"  # このシンボルに依存するもの
enact graph communities
```

各コマンドは `--repo <url>` を受け付けます。省略すると現在のディレクトリにチェックアウトされているリポジトリが使われます。グラフが有効化されていない、まだ構築されていない、あるいはデプロイメントにコードグラフサービスがない場合、コマンドは終了コード 2 と理由を示す 1 行で終了し、エージェントは通常のファイルツールで作業を続けます。[CLI リファレンス](/cli#enact-graph)を参照してください。

`calls` の辺は構文木から推論されたもので、すべての回答でその旨が示されます。強いヒントとして扱い、証明とは考えないでください。ファイル間の解決は Python で最も完全で、Go と TypeScript では薄いため、「グラフにない」は決して「コードにない」を意味しません。

## 最新に保つ

グラフはデフォルトブランチの 1 つのコミットから構築され、チップには常にそのコミットが表示されます。

- GitHub 上の**デフォルトブランチへの push** で再構築がキューに入ります。リポジトリごとに 5 分あたり 1 回にデバウンスされます。
- webhook のないリポジトリは **6 時間ごとにポーリング**され、ブランチの先端が動いていれば再構築がキューに入ります。
- 読み取り時にグラフが既知の先端より遅れていると判明した場合、**stale** としてマークされ、再構築が 1 回キューに入ります。既存のグラフは引き続き照会できます。

再構築はインクリメンタルです。前回の構築以降に変更されたファイルだけが再度解析されます。

## 制限

- デフォルトのファイル数上限はリポジトリあたり 20,000 ソースファイル（`CODEGRAPH_MAX_FILES`）で、超えると構築はスキップされます。
- グラフタブは投影あたり最大 500 ノードと 1,500 辺を表示し、切り詰めた場合はその旨を示します。
- ローカルディレクトリはサポートされません。
- 解析されるのはソースコードだけです。リポジトリ内の Markdown、PDF、画像は無視されます。それは[ナレッジベース](/knowledge-bases)の役割です。

## デプロイ

コードグラフサービスはオプションのコンテナです。なければチェックボックスが無効になるだけで、他の機能は変わりません。

```bash
docker compose -f docker-compose.selfhost.yml -f docker-compose.codegraph.yml up -d
```

| 場所 | 変数 | 意味 |
|---|---|---|
| Enact サーバー | `ENACT_CODEGRAPH_SERVICE_URL` | サービスの内部 URL。compose では `http://codegraph:8767`。空にすると機能が無効になります |
| Enact サーバー | `ENACT_CODEGRAPH_SERVICE_KEY` | すべてのリクエストに付与される共有キー |
| コンテナ | `CODEGRAPH_SERVICE_KEY` | サーバーのキーと一致する必要があります。キーがなければサービスはすべてを拒否します |
| コンテナ | `CODEGRAPH_ALLOWED_HOSTS` | サービスがクローンを許可するホスト。デフォルトは `github.com`。セルフホスト Git では自分の Git ホストを追加します |
| コンテナ | `CODEGRAPH_MAX_FILES` | リポジトリあたりのファイル数上限。デフォルト `20000` |
| コンテナ | `CODEGRAPH_BUILD_TIMEOUT_S` | 構築ごとのタイムアウト。デフォルト `900` |

サービスは各リポジトリのチェックアウトとグラフを `codegraph_state` ボリュームに保持します。ボリュームが失われても、Enact データベースに保存されたステータスとレポートは残り、グラフ・ツリー・コールフローの各タブとエージェントの照会は「未構築」を返し、次の再構築（手動または push によるトリガー）がリポジトリからすべてを復元します。移行が必要なものはありません。

プライベートリポジトリのクローンには、短期の GitHub App インストールトークン、またはセルフホスト Git 連携に保存されたトークンを使います。トークンは 1 回のクローンのためだけにサービスへ渡され、ディスクにもログにも書き込まれません。

## コードグラフと Ontology

両者は異なる問いに答え、データを共有しません。コードグラフはリポジトリのコードがどのように構造化されているかを記述します。Ontology はビジネスドメイン（エンティティ、アクション、ポリシー）を記述し、人の承認のもとで実システムに紐付けます。文書は[ナレッジベース](/knowledge-bases)に置くもので、コードグラフはそれらを読みません。
