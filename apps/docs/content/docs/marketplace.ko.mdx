import { Callout } from "fumadocs-ui/components/callout";

Capability Hub는 설치할 수 있는 기능 목록입니다. [스킬](/skills), 에이전트 템플릿, Agent Family, MCP 서버 항목이 있습니다. 하나를 설치하면 내 워크스페이스에 **사본**이 만들어지고, 이후에는 직접 작성한 것처럼 수정할 수 있습니다.

<Callout>
현재 공개는 운영 측에서 관리합니다. 목록은 배포 자체가 채웁니다 — AI-SDLC 딜리버리 체계가 함께 제공됩니다 — 그리고 앱에는 공개·관리 동작이 표시되지 않습니다. API는 워크스페이스 owner 또는 admin의 공개를 여전히 받으며, 배포 자체의 항목도 그 경로로 들어옵니다.
</Callout>

## 무엇이 들어 있나

| 항목 | 내용 |
|---|---|
| **AI-SDLC Delivery** | intake, explore, contract, build, QA, release, operate, learn과 기록 전반을 판단하는 orchestrator까지 아홉 역할의 Agent Family. 이들이 사용하는 `sdlc-*` 스킬 열 개 포함 |

각 구성원 에이전트와 각 스킬도 개별 항목으로 올라와 있습니다. Family 전체가 아니라 일부만 원하는 팀을 위해서입니다.

목록의 모든 항목에는 내 워크스페이스 기준으로 **설치됨** 또는 **설치 안 됨**이 표시되고, 두 상태로 필터링할 수 있습니다. 이미 가져온 Agent Family도 스킬 하나와 똑같이 설치됨으로 표시됩니다.

## 공개할 수 있는 것

| 종류 | 함께 전달되는 것 | 전달되지 않는 것 |
|---|---|---|
| **스킬** | `SKILL.md`와 모든 참고 파일 | 없음 — 스킬은 글이며 작성된 그대로 공개됩니다 |
| **에이전트 템플릿** | 이름, 설명, 지시문, 모델과 추론 설정, 함께 제공되는 스킬, 필요한 MCP 서버 | 환경 변수, 런타임 연결, 런타임 설정, 누가 호출할 수 있는지에 대한 설정 |
| **Agent Family** | Family의 설명과 협업 방식, 그리고 모든 에이전트 멤버의 완전한 템플릿 — 각자의 스킬과 MCP 서버까지 함께 전달됩니다 | 그 안의 사람 멤버, 그리고 리더의 행 ID. 리더는 어떤 멤버인지로 식별됩니다 |
| **MCP 서버** | 모든 자격 증명을 제거한 서버 항목 | `env`와 헤더 값, 그리고 공개로 표시하지 않은 URL |

Agent Family 하나에는 에이전트가 최대 16개, 그 에이전트 하나에는 스킬이 최대 32개까지 담깁니다. 사람 멤버는 공개되지 않고 제외됩니다. 그들은 내 워크스페이스의 멤버를 가리킬 뿐, 다른 워크스페이스의 멤버는 아니기 때문입니다. Family를 설치하는 사람이 자기 워크스페이스의 사람을 직접 추가합니다.

<Callout type="warn">
공개할 때 브라우저에서 내용을 업로드하는 일은 없습니다. 내 워크스페이스의 항목 하나를 지정하면 서버가 그것을 읽어 자격 증명이 담긴 필드를 모두 제거한 뒤 결과를 저장합니다. 그래서 이 제외 처리를 믿을 수 있습니다.
</Callout>

## 공개하기

목록을 운영 측에서 관리하는 동안 앱에는 공개·관리 동작이 표시되지 않습니다. 아래는 API가 여전히 수행하는 공개에 대한 설명입니다. 배포 자체의 목록도 이 경로를 지나며, 공개가 열릴 때 화면으로 돌아오는 것도 이것입니다.

공개할 때는 메타데이터 외에 두 가지를 정합니다.

- **볼 수 있는 대상.** `이 워크스페이스만`은 팀 내부 라이브러리입니다. `공개`는 이 배포의 모든 워크스페이스에 닿습니다. 먼저 내부에서 공개했다가 준비되면 공개로 바꾸면 됩니다. 설치 방법은 둘 다 같습니다.
- **버전.** 공개된 버전은 절대 덮어쓰지 않습니다. 같은 핸들로 다시 공개하면 같은 항목에 버전이 하나 추가되므로 링크는 계속 동작하고 이력도 한곳에 모입니다. 이미 있는 버전 문자열로 다시 공개하면 거부됩니다.

### 공개자가 제외하는 값

MCP 서버에서는 `env` 값, 헤더 값, URL이 빈 값으로 바뀌고 매니페스트에 **설치 시 입력해야 하는 값**으로 표시됩니다. 항목을 설치하는 사람이 자신의 값을 입력합니다. 어떤 값이 정말 자격 증명이 아니라면 — 예를 들어 공개된 엔드포인트라면 — 작성된 그대로 공개하도록 표시할 수 있습니다.

서버의 `command`나 `args`, 또는 에이전트의 사용자 지정 인자에 자격 증명이 직접 적혀 있으면 값이 제외되는 대신 **공개가 실패합니다**. 프로세스 실행 명령을 말없이 고쳐 쓰는 것은 거부하는 것보다 나쁩니다. 그 값을 서버의 환경 변수로 옮긴 뒤 다시 공개하세요.

## 설치하기

항목을 열면 설치했을 때 무엇이 만들어지는지 볼 수 있습니다. 에이전트 템플릿이라면 함께 제공되는 스킬과 필요한 MCP 서버가, Agent Family라면 모든 멤버 에이전트가 빠짐없이 표시됩니다. 확인한 뒤 **설치**를 선택하세요.

양식에서는 항목이 알 수 없는 것만 묻습니다.

- **이 워크스페이스에서 사용할 이름.** 비워 두면 공개된 이름을 그대로 사용합니다.
- **런타임**(에이전트 템플릿 또는 Agent Family의 경우). 템플릿은 머신을 지정하지 않으므로 내 워크스페이스에서 하나를 고릅니다. Family는 모든 멤버를 그 런타임에 연결하며, 설치한 뒤 하나씩 옮길 수 있습니다. 템플릿이 다른 제공자 기준으로 작성되었더라도, 해당 런타임이 지원하지 않는 설정은 설치를 막는 대신 설정되지 않은 채로 남습니다.
- **공개자가 제외한 값**(항목에 있는 경우). Family의 값은 서버 이름뿐 아니라 멤버 이름으로도 구분됩니다. 두 멤버가 같은 이름의 서버를 필요로 할 수 있기 때문입니다.

### Agent Family 설치하기

Family 설치는 필요한 모든 것을 한 번에 만들어 내는 동작입니다. 모든 멤버 에이전트, 각자가 지닌 스킬, 각자가 필요로 하는 MCP 서버, 그리고 이들을 묶는 Family가 공개된 리더와 역할 그대로 만들어집니다. 전부 만들어지거나 하나도 만들어지지 않거나 둘 중 하나입니다. 멤버가 절반만 도착한 Family는 존재하지 않는 에이전트에게 작업을 넘기게 됩니다.

이름이 내 워크스페이스에서 이미 사용 중인 멤버는 기존 항목을 대체하지 않고 접미사가 붙은 이름으로 설치됩니다. 설치된 에이전트는 모두 처음에는 나에게만 보이므로, 팀이 사용해야 하는 에이전트에는 설치한 뒤 필요한 공개 범위를 지정하세요.

이름이 이미 사용 중이면 스킬 가져오기와 같은 선택지가 주어집니다. 다른 이름으로 설치하거나, 기존 항목을 대체하는 것입니다. 대체는 대체 대상 스킬을 처음 만든 사람만 할 수 있습니다.

## 설치는 사본이지 구독이 아닙니다

설치한 스킬이나 에이전트는 이후로 원래 항목을 따라가지 않습니다. 내 사본은 안전하게 수정할 수 있고, 항목에 새 버전이 나와도 누군가 설치하기 전까지는 아무것도 바뀌지 않습니다.

Capability Hub는 어떤 버전을 받았는지 기억하므로, 더 새로운 버전이 공개되면 이미 가지고 있는 항목에 **vX로 업데이트**가 표시됩니다. 업데이트를 받는 것은 그 버전을 의도적으로 설치하는 일입니다.

<Callout>
설치된 스킬은 스킬 페이지에서 다시 받을 수 없습니다. "소스에서 업데이트"는 어떤 URL이 오늘 제공하는 내용을 다시 내려받는 것이고, Capability Hub의 업데이트는 내가 고른 버전을 설치하는 것입니다. 항목 페이지를 사용하세요.
</Callout>

## 항목 내리기

공개한 워크스페이스는 항목을 **지원 중단**으로 표시할 수 있습니다. 그러면 목록에서는 보이지 않지만 이미 그 항목에 의존하는 사람은 계속 설치할 수 있습니다. 또는 **내리기**를 하면 새로운 설치가 완전히 중단됩니다. 목록을 운영 측에서 관리하는 동안 둘 다 API 동작입니다.

둘 다 이미 설치한 워크스페이스에는 영향을 주지 않습니다. 그 사본은 그들의 것입니다.

## 이 프로젝트에 추천

디렉터리 위쪽에서 Capability Hub는 설치 가능한 것들을, 이 워크스페이스가 자기 프로젝트에 대해 말한 것 — 스택, 도메인, 여기서 다루는 일의 종류 — 을 기준으로 정렬합니다. **설정 → 워크스페이스**에서 채우거나, 채팅으로 Enact에게 부탁하면 몇 가지 물어보고 대신 작성해 줍니다.

모든 추천이 그 이유를 밝힙니다. 프로필의 어떤 값이 일치했고, 어느 필드에서 일치했는지입니다. 발행자가 직접 붙인 태그는 문단 속 한 번의 언급보다 무겁게 계산됩니다. 인기도에는 상한이 있습니다 — 그렇지 않으면 모두가 설치한 리스팅이, 여러분의 프로젝트에 대한 것이어야 할 정렬을 지배해 버립니다.

일부 결과에는 **이 프로젝트에 대한 것이 아님**이라고 표시됩니다. 그것들은 이 배포가 제공하는 것이며, 더 맞는 것이 없어서 보여진 것입니다. 숨기지 않고 표시하므로, 빈 추천 영역이 "여기에는 당신을 위한 게 없다"는 뜻이 되는 일은 없습니다.

정렬은 페이지를 열 때마다 그 시점의 디렉터리를 기준으로 계산됩니다. 오늘 오후에 공개된 것이 오늘 아침에 만들어진 워크스페이스에 도달합니다.

**이건 아님**은 여러분이 본 버전에 대한 거절입니다. 그 리스팅의 새 버전이 공개되면 다시 나타납니다. 새 버전은 다른 제안이기 때문입니다.

<Callout>
이 정렬에는 모델이 관여하지 않습니다. 리스팅 메타데이터에 대한 점수 계산이라 빠르고 비용이 없으며, 그래서 각 결과가 무엇에 일치했는지 말해 줄 수 있습니다. 그 위의 판단 — 무엇을 설치하고 설치 후 무엇을 바꿀지 — 은 Enact에게 물어보세요.
</Callout>

## 전제 조건

리스팅은 사본이 동작하기 전에 여러분 쪽에서 참이어야 하는 것을 선언할 수 있습니다. 호스트 도구, 플러그인, 디렉터리 구조 같은 것입니다. 아무것도 이를 검사하지 않습니다 — 조건은 서버가 아니라 여러분의 machine에 있습니다 — 그래서 설치 전에 보여줄 뿐입니다.

읽어 보세요. 발행자의 호스트에 설치된 엔진을 호출하는 스킬을 가진 Agent Family는, 여러분의 machine에 없는 명령을 전제로 도착합니다.

## 온톨로지

Capability Hub의 마지막 탭에는 온톨로지가 표시됩니다. 이것은 항목이 아닙니다. Capability Hub가 제공하며 워크스페이스로 복사되지 않고 에이전트에 연결됩니다. 이 탭이 있는 이유는 기능을 한곳에서 찾을 수 있게 하기 위해서이며, 연결 관리는 [온톨로지](/skills) 페이지에서 합니다.

내 워크스페이스가 이미 연결한 온톨로지도 다른 항목과 똑같이 **설치됨**으로 표시되고, 설치됨 / 설치 안 됨 필터가 이 탭에서도 적용됩니다.

## CLI 사용

```bash
enact marketplace list --kind skill --output json
enact marketplace list --not-installed --output json
enact marketplace recommend --output json
enact marketplace get <listing-id> --output json
enact marketplace install <listing-id> --output json

# 에이전트 템플릿에는 런타임과 제외된 값이 필요합니다.
enact marketplace install <listing-id> \
  --runtime-id <runtime-id> \
  --secret env.GITHUB_TOKEN=... \
  --output json

# Agent Family의 kind는 squad입니다. 모든 멤버를 하나의 런타임에 연결하고,
# 제외된 값은 서버 이름뿐 아니라 멤버 이름도 함께 씁니다.
enact marketplace list --kind squad --output json
enact marketplace install <listing-id> \
  --runtime-id <runtime-id> \
  --secret reviewer/github/env.GITHUB_TOKEN=... \
  --output json
```

`enact marketplace list`는 행마다 `INSTALLED`를 보여 줍니다. 내가 가지고 있는 버전이거나 `no`입니다. `--installed` / `--not-installed`로 한쪽만 볼 수 있습니다.

공개 명령은 없습니다. 공개는 무엇이 워크스페이스를 벗어나는지에 대한 관리자의 결정이며, API는 에이전트 호출자의 공개 요청을 거부합니다. 배포에 포함된 항목은 서버가 시작할 때 그것을 보유한 워크스페이스에서 공개합니다.

## 권한

| 동작 | 대상 |
|---|---|
| 항목 둘러보기와 열기 | 모든 워크스페이스 멤버 |
| 스킬, 에이전트 템플릿 또는 Agent Family 설치 | 모든 워크스페이스 멤버 |
| MCP 서버 설치 | 워크스페이스 owner 또는 admin |
| 항목 공개, 수정, 지원 중단, 내리기 | 공개한 워크스페이스의 owner 또는 admin, API 경유 — 관리 중에는 화면에 진입점이 없습니다 |

에이전트는 둘러보고 설치할 수 있습니다. 공개는 할 수 없습니다.
