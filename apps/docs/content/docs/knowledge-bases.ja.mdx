ナレッジベースは、エージェントが読む文書の git リポジトリです。ドメインの背景、プロダクト上の決定、新しいメンバーに説明が必要なことなどが入ります。チームが作業する[リソース](/resources)のリポジトリと並ぶ存在ですが、ワークスペース全体ではなく個々のエージェントに紐付く点が異なります。

## ナレッジベースと skill の使い分け

どちらもエージェントに文章を届けるものですが、読み込まれるタイミングが違います。

| | skill | ナレッジベース |
|---|---|---|
| 答えるもの | やり方 | チームが知っていること |
| 読み込み | 使う作業のたびに全文 | 索引は毎回、文書は必要なときだけ |
| 編集する人 | skill の管理者 | リポジトリの権限を持つ人と振り返りエージェント |
| 置き場所 | Enact 内、skill ごとにバージョン管理 | 自分たちの git リポジトリ |

毎回適用されるルールは [skill](/skills) に置きます。skill は全文が読み込まれるものであり、誰も読まないルールは何も変えないからです。ときどき必要になる背景はナレッジベースに置きます。毎回すべてを読み込めば、それを必要としない作業にコンテキスト予算を払わせることになるからです。

## エージェントはどう読むか

作業が始まる前に、ランタイムがリポジトリをマシン上にチェックアウトし、各文書の front-matter を読みます。エージェントのブリーフには、1 文書 1 行の索引が載ります。

```text
## Knowledge

### ドメインハンドブック

- Location: `/…/.knowledge/…/docs`
- Source: https://github.com/acme/handbook.git (`main`)
- Documents: 12

- **リリース枠** — いつ出荷してよいか。(`deploy-window.md`)
- **価格モデル** — 各プランの値付け。(`pricing.md`)
```

エージェントは毎回この索引を読み、本当に関係する 1〜2 件だけを、コードと同じファイルツールで開きます。文書の本文がブリーフに貼られることはありません。

だから front-matter は必須です。`title` と `description` は、後続の作業がその文書を開くかどうかを判断する唯一の材料であり、中身を言い当てていない description は、その文書が見つからないことを意味します。

```markdown
---
title: リリース枠
description: いつ出荷してよいか、例外を誰が承認するか。
updated: 2026-09-05
source: ENA-1234
---
```

<Callout type="info">
60 件を超えると、索引はディレクトリとその件数の一覧に切り替わり、この節はナレッジベースの成長に伴って膨らまなくなります。エージェントはディレクトリを一覧して必要なものを読みます。
</Callout>

## ナレッジベースを追加する

**設定 → リソース**でリポジトリを追加し、読ませたいエージェントに紐付けます。どのエージェントにも紐付いていないナレッジベースは見えません。受信箱の仕分けだけをするエージェントのブリーフにドメインハンドブックが入らないのは、この仕組みのおかげです。

```bash
# ワークスペースにリソースを作る
enact resource add --type knowledge_repo --url https://github.com/acme/handbook.git \
  --path docs/knowledge --label "ドメインハンドブック" --output json

# 特定のエージェントに読ませる
enact agent knowledge add <agent-id> --resource-id <resource-id> --output json
enact agent knowledge list <agent-id> --output json
```

| フィールド | 意味 |
|---|---|
| `url` | ランタイムから到達できる任意の git URL |
| `ref` | 読むブランチ、タグ、コミット（既定はリポジトリの既定ブランチ） |
| `path` | 文書が置かれたサブディレクトリ。他の内容と 1 つのリポジトリを共有できます |
| `delivery` | `pull_request`（既定）または `commit`。下記参照 |

紐付けを外してもリソースはワークスペースに残り、他のエージェントが使えます。リソースを削除すると、すべてのエージェントの紐付けも消えます。

## 書き戻し

エージェントはコードと同じやり方で文書を書きます。ブリーフに載っている索引済みの場所は、そのマシン上のすべての作業で共有され、作業ごとにリセットされるため、エージェントがそこを編集することはありません。`enact repo checkout <url>` で自分専用のチェックアウトを取得し、そこに書いて、次のいずれかで届けます。

- **`pull_request`**（既定）はプルリクエストを開き、マージは人に委ねます。ナレッジベースは紐付いたすべてのエージェントの以後すべての作業に読まれるので、レビューされていない文書は 1 つの悪いファイルではなく、何か月も引用され続ける悪いファイルになります。
- **`commit`** はその ref に直接 push します。すべてのメモをレビューしたくないチーム向けです。

## 振り返りエージェント

ナレッジベースが腐らずに積み上がるのは、これがあるからです。[振り返りエージェント](/retrospect)は終わった作業を振り返り、学んだことを書き留めます。ナレッジベースを紐付ければ、その文書は誰も開き直さない添付ファイルではなく、ナレッジベースに残ります。

書く前に索引を読むので、同じ主題をすでに扱っている文書があればその隣に 2 つ目を作らず、その文書を編集します。
