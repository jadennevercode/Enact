새 워크스페이스에는 받은편지함 메시지 하나와, 네 개의 단계를 가진 태스크 하나가 준비되어 있습니다. 둘 다 있는 이유는 여기서의 에이전트가 채팅창이 아니기 때문입니다. 실제 컴퓨터에서 돌고 실제 파일을 읽으며, 여러분의 프로젝트가 무엇인지 알수록 더 나은 결과를 냅니다.

단계는 스스로 닫힙니다. 런타임이 연결되었는지, 리소스가 있는지, 프로필이 채워졌는지 — 각각 실제 상태와 대조되므로, 태스크를 열지 않아도 그 일을 하면 닫힙니다.

## 네 단계

### 컴퓨터 연결하기

에이전트는 여러분이 관리하는 machine에서, 여러분의 agent CLI와 계정으로 실행됩니다. 코드와 자격 증명은 원래 있던 자리에 그대로 있습니다. 사이드바의 **런타임**을 여세요. 노트북 한 대로 시작해도 충분합니다.

런타임이 연결되기 전에는 아무것도 실행되지 않으므로 이것이 첫 번째입니다.

### 코드 연결하기

**설정 → 리소스**에서 워크스페이스를 Git 저장소나, 연결된 machine의 디렉터리로 지정합니다.

리소스는 포인터이지 사본이 아닙니다. 태스크가 필요로 할 때만 에이전트가 체크아웃하며, Enact로 업로드되는 것은 없습니다.

### 이 프로젝트가 무엇인지 알려주기

**프로젝트 프로필**은 프로젝트에 대한 한두 문장, 사용하는 스택, 그리고 여기서 다루는 일의 종류입니다. **설정 → 워크스페이스**에서 채우거나, 채팅으로 Mika에게 부탁하세요. 몇 가지 물어보고 대신 작성해 줍니다.

<Callout>
가장 많은 것을 바꾸는 단계입니다. 아래의 모든 것이 여기에 의존합니다.
</Callout>

### 추천된 역량 살펴보기

프로필이 생기면 [Marketplace](/marketplace)가 그것을 기준으로 디렉터리를 정렬해, 맞는 것을 이유와 함께 위에 보여줍니다. 원하는 것을 설치하고 원하지 않는 것을 무시하면 이 단계는 닫힙니다.

## 프로필이 실제로 하는 일

읽는 곳이 두 군데입니다. 워크스페이스 컨텍스트 안의 또 하나의 문단이 아니라 독립된 필드인 이유가 여기 있습니다.

**모든 에이전트 실행이 여기서 시작합니다.** 실행의 브리프에 자체 섹션으로 렌더링되므로, 실행할 때마다 열어본 파일에서 관례를 추측하지 않아도 됩니다. 이것은 지시가 아니라 맥락입니다. 섹션 자체가 그렇게 밝히고 있으며, 실행은 워크스페이스 컨텍스트를 요구사항으로 적용하고 프로필은 설명으로 참고합니다.

**Marketplace가 이것을 기준으로 정렬합니다.** `stack`과 `typical_work`가 리스팅이 무엇을 위한 것인지와 대조됩니다. 프로필이 비어 있으면 정렬의 근거가 없어, 이 배포가 제공하는 것으로 되돌아갑니다.

`typical_work`는 고정 목록입니다 — 코드 작성, 코드 리뷰, 제품 기획, 조사·분석, 문서 작성, 운영 자동화, 데이터 분석, 지식 모델링, 디자인, 지원, 컴플라이언스. 고정인 이유는 추천 엔진이 이 값들을 리스팅 텍스트에 대응시키기 때문이며, 자유 서술에는 규칙을 쓸 수 없습니다. 여기 맞지 않는 것은 요약이나 제약에 쓰면 여전히 모든 실행에 전달됩니다.

워크스페이스 컨텍스트와 달리 프로필은 어느 멤버든 편집할 수 있습니다. 아무 권한도 주지 않고 아무것도 지시하지 않으며, 이를 채우는 인터뷰는 일반 멤버의 권한으로 실행됩니다.

## 저장소 읽기

저장소를 처음 연결할 때 — 워크스페이스에 이미 프로필이 있고, 런타임에 연결된 Mika가 있다면 — 그것을 읽는 태스크 하나가 생성됩니다.

Mika는 저장소를 체크아웃하고 README, 패키지 매니페스트, CI 설정, 트리 상위 몇 단계를 읽은 뒤 발견한 것을 프로필의 **저장소** 필드에 씁니다. 언어, 프레임워크, 빌드 방법, 테스트 방법, 트리 구성입니다.

이 필드는 설정에서 읽기 전용입니다. 실제로 코드를 읽은 실행이 작성한 것이고, 프로젝트에 대한 여러분의 말이 아니라 저장소에 대한 증거이기 때문입니다. 요약을 다시 써도 이것은 사라지지 않으며, 그 실행이 여러분의 요약을 고쳐 쓰지도 않습니다.

프로필이 아직 없거나 런타임이 없으면 아무것도 생성되지 않습니다. 아무도 설명하지 않은 프로젝트에 붙은 저장소 보고서는 아무도 요청하지 않은 보고서입니다.

## CLI에서

```bash
enact workspace profile get --output json

enact workspace profile set --json-stdin <<'JSON'
{
  "summary": "중형 운송사를 위한 물류 관제탑.",
  "domain": "logistics",
  "stack": ["go", "typescript", "postgres"],
  "languages": ["ko", "en"],
  "typical_work": ["ship_code", "review_code"],
  "constraints": "프로덕션 변경에는 두 번째 리뷰어가 필요합니다."
}
JSON
```

`profile set`은 병합이 아니라 **전체 교체**입니다. 생략한 필드는 지워집니다. 현재 것을 먼저 읽고 변경해서 다시 보내세요. 예외는 저장소 관련 두 필드로, 문서가 그것들을 전혀 언급하지 않으면 그대로 유지됩니다.

## 이 기능 이전에 만들어진 워크스페이스

Marketplace나 환영 모달을 열면 체크리스트를 읽고, 읽는 행위 자체가 빠진 단계를 생성합니다. 수동 마이그레이션은 필요 없으며, 이미 충족된 단계는 같은 읽기에서 닫힙니다.
