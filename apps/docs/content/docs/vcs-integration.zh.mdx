<Callout type="warn">
企业 GitLab 连接仅适用于自部署 Enact。启用 `ENACT_VCS_INTEGRATION_ENABLED=true`，并设置 base64 编码的 32 字节 `ENACT_VCS_SECRET_KEY`。该密钥用于加密 API token、Git token、Webhook secret 与企业 CA。
</Callout>

所有代码托管设置集中在 **来源 → 代码与目录**。GitHub 使用 GitHub App；第一阶段的 GitLab 使用 HTTPS。Forgejo/Gitea 旧连接仍可接收 Webhook，但暂不提供仓库浏览或托管 Git 凭据。

## 三条独立链路

连接卡片分别显示：

1. **Enact Server → GitLab API**：用于身份验证、分页浏览项目和创建 Merge Request。
2. **GitLab → Enact Webhook**：用于 Merge Request 与 Pipeline 事件。
3. **Enact daemon → Git HTTPS remote**：用于 clone、fetch 与 push；每台 daemon、每个仓库单独记录结果。

API 成功不代表 Webhook 或 Git transport 可用。页面会保留每条链路自己的状态和错误。

## GitLab 凭据

优先创建有到期时间、只加入所需项目的 **Service Account**。也可选择 Project、Group 或 Personal access token。连接表单显式记录 token 类型、范围与到期日。

- **API token**：需要 `api`，只在 Enact Server 解密，用于项目浏览与创建 MR。
- **Git HTTPS token**：需要 `write_repository`，只通过 daemon 专用、仓库限定的凭据接口下发。

秘密不会出现在普通浏览器 API，也不会再次回显。替换 token 或轮换 Webhook secret 时输入新值。

agent 在受管仓库中提交后使用 `enact repo push`。daemon 会即时获取仓库限定凭据，通过 `0600` 临时 credential store 完成 push，然后删除临时文件。随后使用 `enact repo change-request --title "…"` 创建 PR/MR；provider API token 仍只在 Enact Server 内使用。

## 企业网络与 CA

填写 GitLab API URL 和 HTTPS clone host。默认使用系统信任链；如果企业使用私有 CA，可粘贴连接级 PEM。Enact 将其加入系统信任链用于服务端 API，daemon Git 也使用同一 CA。TLS 校验始终开启，没有“跳过校验”选项。

GitLab 自托管实例可能默认禁止 Webhook 请求访问内网地址。请让 GitLab 管理员在 **Admin → Settings → Network → Outbound requests** 中仅放行 Enact Webhook 的域名或 IP。

## 添加仓库

选择 GitLab 连接后，Enact 通过 `/api/v4/projects` 分页搜索可见项目，保留 subgroup 完整路径、私有状态、默认分支、归档状态和权限。批量选择后，每条资源保存 provider、连接 ID、provider repository ID、完整路径、HTTPS URL、默认分支、可选固定 ref 和启用状态。

旧版本只保存 URL 的仓库会显示为 **待配置** 并停用，直到管理员绑定连接。待配置仓库不会下发给 daemon。

## Webhook

连接成功时 Webhook secret 只显示一次。在 GitLab 项目或群组中注册：

- URL：页面显示的 Webhook URL；
- Secret token：一次性显示的 secret；
- 事件：**Merge request events** 与 **Pipeline events**。

Enact 只处理当前工作区中已启用、且绑定到该连接的仓库事件。收到第一个通过 secret 校验的事件后，Webhook 状态会变为已验证。

## GitHub App 权限

GitHub App 需要 **Contents: Read & write**、**Pull requests: Read & write**、**Checks: Read** 和 **Commit statuses: Read**。Enact 按任务和单仓库签发短期 installation token。

## 第二阶段：SSH

SSH 将作为后续独立阶段提供，包括 Ed25519 生成/导入、daemon 实机扫描 host key、管理员确认指纹、自定义 host/port、受控 `known_hosts` 与多连接 host alias。SSH 只替换 Git transport，创建 PR/MR 仍走服务端 API。
