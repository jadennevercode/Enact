코드 그래프는 하나의 저장소에 대한 구조 지도입니다. 파일, 클래스, 함수와 그 사이의 import 및 호출, 그리고 이 연결이 형성하는 서브시스템을 담습니다. Enact는 저장소 소스로부터 [graphify](https://github.com/safishamsi/graphify)(Apache-2.0 / MIT)를 사용해 서버에서 구축하며, tree-sitter 파싱만 수행합니다. 모델을 호출하지 않으므로 구축에 토큰이 들지 않고, 저장소는 Enact 배포 내부에서만 클론됩니다.

에이전트는 파일을 읽기 시작하기 전에 올바른 서브시스템을 찾는 데 사용하고, 사람은 저장소가 어떻게 구성되어 있는지 보는 데 사용합니다.

## 저장소별로 활성화

코드 그래프는 저장소 단위 옵트인이며, 그 외에 설정할 것은 없습니다.

- **설정 → 리소스**에서 **GitHub에서 선택**하거나 Git URL을 붙여 넣을 때 **선택한 저장소의 코드 그래프 구축**을 체크합니다. 이 선택은 해당 대화 상자에서 추가하는 모든 저장소에 적용됩니다.
- 나중에 저장소 행의 메뉴에서 **코드 그래프**를 켜거나 끌 수 있습니다.

켜면 첫 번째 구축이 큐에 들어갑니다. 끄면 해당 저장소의 모든 구축이 서버의 데이터를 포함하여 삭제됩니다.

배포에 코드 그래프 서비스가 없으면([배포](#배포) 참고) 체크박스는 안내 문구와 함께 비활성화됩니다. 로컬 디렉터리에는 제공되지 않습니다. 서버는 사용자 컴퓨터의 디렉터리를 읽을 방법이 없기 때문입니다.

## 상태 칩의 의미

활성화하면 저장소 행에 칩이 표시됩니다.

| 칩 | 의미 |
|---|---|
| **준비됨 · a1b2c3d · 2시간 전** | 해당 commit의 그래프를 조회할 수 있습니다. 칩을 클릭하면 코드 그래프 페이지가 열립니다. |
| **구축 중…** | 구축이 큐에 있거나 실행 중입니다. 그동안 에이전트는 파일 도구로 계속 작업합니다. |
| **건너뜀 · 파일 수 초과** | 저장소가 파일 수 상한을 넘었습니다. 아무것도 구축되지 않으며 부분 그래프도 없습니다. |
| **실패 · 이유** | 클론 또는 구축이 실패했습니다. **다시 시도**로 다시 큐에 넣습니다. |
| *(칩 없음)* | 이 저장소에는 코드 그래프가 활성화되어 있지 않습니다. |

## 코드 그래프 페이지

활성화된 각 저장소는 **인텔리전스 → 코드 그래프** 아래에 페이지가 있으며 칩에서도 열 수 있습니다. 헤더에는 그래프가 구축된 commit, 시각, 크기가 표시됩니다. 워크스페이스 소유자와 관리자는 **다시 구축**을 실행할 수 있습니다.

| 탭 | 표시 내용 |
|---|---|
| **개요** | 구축 리포트: 가장 큰 서브시스템, 연결이 가장 많은 노드, 예상 밖의 서브시스템 간 연결, 이전 구축 이후 변경 사항. |
| **서브시스템** | 각 서브시스템의 크기와 응집도, 생성된 설명 문서, 주요 파일(구축 시점 commit의 GitHub로 링크). |
| **그래프** | 서브시스템을 노드로, 간선 두께로 상호 참조 정도를 표시합니다. 서브시스템을 클릭하면 펼쳐지고, 노드를 클릭하면 인접 영역과 `파일:행`이 표시됩니다. 큰 투영은 차수 기준으로 잘리며 그 사실을 표시합니다. |
| **트리** | 파일과 심볼의 계층을 접을 수 있는 트리로 표시합니다. |
| **호출 흐름** | 서브시스템마다 하나의 다이어그램으로, 서브시스템을 묶어 주는 호출을 보여 줍니다. |

<Callout type="info">
서브시스템은 그래프 클러스터링이 찾아낸 커뮤니티로, 연결이 가장 많은 구성원의 이름을 따릅니다. 디렉터리가 아닌 구조적 그룹입니다. 하나의 서브시스템이 여러 패키지에 걸칠 수도 있고, 하나의 패키지가 여러 서브시스템으로 나뉠 수도 있습니다.
</Callout>

## 에이전트의 사용 방법

`enact` CLI는 활성화된 저장소를 체크아웃한 모든 에이전트에 그래프를 제공합니다. 내장 skill은 에이전트에게 먼저 `enact graph status`를 실행하고, 그래프가 준비되었으면 파일을 열기 전에 리포트를 읽고 그래프를 조회하라고 안내합니다.

```bash
enact graph status                 # 준비됨 / 구축 중 / 비활성, 그리고 commit
enact graph report                 # 개요 탭과 같은 리포트
enact graph query "webhook 전송은 어디에서 재시도되는가"
enact graph path "IssueHandler" "TaskQueue"
enact graph explain "WebhookDeliveryWorker"
enact graph affected "EnqueueTask"  # 이 심볼에 의존하는 것
enact graph communities
```

각 명령은 `--repo <url>`을 받습니다. 생략하면 현재 디렉터리에 체크아웃된 저장소를 사용합니다. 그래프가 활성화되지 않았거나 아직 구축되지 않았거나 배포에 코드 그래프 서비스가 없으면 명령은 종료 코드 2와 이유를 설명하는 한 줄로 끝나며, 에이전트는 일반 파일 도구로 계속 작업합니다. [CLI 참조](/cli#enact-graph)를 참고하세요.

`calls` 간선은 구문 트리에서 추론된 것이며 모든 답변에 그렇게 표시됩니다. 강한 힌트로 다루고 증명으로 여기지 마세요. 파일 간 해석은 Python에서 가장 완전하고 Go와 TypeScript에서는 얇으므로, "그래프에 없음"이 "코드에 없음"을 의미하지는 않습니다.

## 최신 상태 유지

그래프는 기본 브랜치의 한 commit에서 구축되며, 칩에는 항상 그 commit이 표시됩니다.

- GitHub의 **기본 브랜치에 push**가 있으면 다시 구축이 큐에 들어갑니다. 저장소별로 5분에 한 번으로 디바운스됩니다.
- webhook이 없는 저장소는 **6시간마다 폴링**되며, 브랜치 끝이 바뀌었으면 다시 구축이 큐에 들어갑니다.
- 읽기 시점에 그래프가 알려진 끝보다 뒤처져 있으면 **stale**로 표시되고 다시 구축이 한 번 큐에 들어갑니다. 기존 그래프는 계속 조회할 수 있습니다.

다시 구축은 증분 방식입니다. 마지막 구축 이후 변경된 파일만 다시 파싱합니다.

## 제한

- 기본 파일 수 상한은 저장소당 소스 파일 20,000개(`CODEGRAPH_MAX_FILES`)이며, 초과하면 구축이 건너뜁니다.
- 그래프 탭은 투영당 최대 500개 노드와 1,500개 간선을 표시하며, 잘린 경우 그 사실을 표시합니다.
- 로컬 디렉터리는 지원되지 않습니다.
- 소스 코드만 파싱합니다. 저장소의 Markdown, PDF, 이미지는 무시됩니다. 그것은 [지식 베이스](/knowledge-bases)의 역할입니다.

## 배포

코드 그래프 서비스는 선택적 컨테이너입니다. 없으면 체크박스가 비활성화될 뿐 다른 기능은 바뀌지 않습니다.

```bash
docker compose -f docker-compose.selfhost.yml -f docker-compose.codegraph.yml up -d
```

| 위치 | 변수 | 의미 |
|---|---|---|
| Enact 서버 | `ENACT_CODEGRAPH_SERVICE_URL` | 서비스의 내부 URL. compose에서는 `http://codegraph:8767`. 비워 두면 기능이 비활성화됨 |
| Enact 서버 | `ENACT_CODEGRAPH_SERVICE_KEY` | 모든 요청에 함께 보내는 공유 키 |
| 컨테이너 | `CODEGRAPH_SERVICE_KEY` | 서버의 키와 같아야 함. 키가 없으면 서비스는 모든 요청을 거부 |
| 컨테이너 | `CODEGRAPH_ALLOWED_HOSTS` | 서비스가 클론할 수 있는 host. 기본값 `github.com`. 자체 호스팅 Git은 자신의 Git host를 추가 |
| 컨테이너 | `CODEGRAPH_MAX_FILES` | 저장소당 파일 수 상한. 기본값 `20000` |
| 컨테이너 | `CODEGRAPH_BUILD_TIMEOUT_S` | 구축별 제한 시간. 기본값 `900` |

서비스는 각 저장소의 체크아웃과 그래프를 `codegraph_state` 볼륨에 보관합니다. 볼륨이 손실되어도 Enact 데이터베이스에 저장된 상태와 리포트는 남고, 그래프·트리·호출 흐름 탭과 에이전트 조회는 "구축되지 않음"을 반환하며, 다음 다시 구축(수동 또는 push로 트리거)이 저장소에서 모든 것을 복원합니다. 마이그레이션할 것은 없습니다.

비공개 저장소 클론에는 단기 GitHub App installation token 또는 자체 호스팅 Git 연동에 저장된 token을 사용합니다. token은 한 번의 클론을 위해서만 서비스에 전달되며 디스크나 로그에 기록되지 않습니다.

## 코드 그래프와 Ontology

둘은 다른 질문에 답하며 데이터를 공유하지 않습니다. 코드 그래프는 저장소 코드가 어떻게 구조화되어 있는지를 설명합니다. Ontology는 비즈니스 도메인(엔티티, 액션, 정책)을 설명하고 사람의 승인 아래 실제 시스템에 바인딩합니다. 문서는 [지식 베이스](/knowledge-bases)에 두며, 코드 그래프는 문서를 읽지 않습니다.
