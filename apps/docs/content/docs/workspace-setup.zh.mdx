新工作区建好之后，收件箱里会有一条消息，任务列表里会有一个任务和它下面的四个步骤。之所以有这两样东西，是因为这里的智能体不是一个聊天窗口：它跑在一台真实的电脑上，读真实的文件，知道你的项目是什么的时候，活会干得更好。

步骤会自己关闭。每一步都对着真实状态检查——有没有连运行时、有没有资源、画像填没填——所以把事做了就会关掉那一步，不管你有没有打开过那个任务。

## 四个步骤

### 连接一台电脑

智能体跑在你自己控制的机器上，用你自己的 agent CLI 和你自己的账号，所以代码和凭据仍然待在它们本来就在的地方。打开侧边栏的 **运行时**。先用一台笔记本就够了。

没连上运行时之前什么都跑不起来，所以它排在第一。

### 接入你的代码

在 **设置 → 资源** 里把工作区指向一个 Git 仓库，或者某台已连接机器上的一个目录。

资源是一个指针，不是一份拷贝。只有任务需要时智能体才会去检出仓库，不会有东西被上传到 Enact。

### 告诉 Enact 这个项目是什么

**项目画像**是一两句话的项目说明、你用的技术栈，以及你通常拿到这里做的事。在 **设置 → 工作区** 里填，或者在聊天里找 Enact——她会问几个问题然后替你写好。

这一步改变的东西最多。下面所有内容都依赖它。
</Callout>

### 看看推荐的能力

有了画像之后，[能力中心](/marketplace) 会照着它给整个目录排序，把匹配的放在最前面并说明为什么匹配。想装的装上，不想要的忽略掉，这一步就关了。

## 画像到底起什么作用

有两处会读它。这也是为什么它是一个独立字段，而不是工作区上下文里的又一段话。

**每一次智能体运行都从它开始。** 它会作为一个单独的段落渲染进运行的简报，所以运行不用再从随手打开的文件里猜你的约定。它是背景信息，不是指令：段落里就是这么写的，运行会把工作区上下文当成要求来执行，把画像当成描述来参考。

**能力中心 照着它排序。** `stack` 和 `typical_work` 会和 listing 声明的用途做匹配。画像为空意味着排序没有依据，只能退回到这个部署本身提供的东西。

`typical_work` 是一份固定清单——写代码、代码审查、产品规划、调研分析、写文档、运维自动化、数据分析、知识建模、设计、支持运营、合规治理。之所以固定，是因为推荐引擎要把这些值映射到 listing 的文本上，而针对自由文本写不出规则。放不进去的东西写进一句话说明或者约束里，它们照样会到达每一次运行。

和工作区上下文不同，任何成员都可以编辑画像。它不授予任何权限、不下达任何指令，而且填写它的那轮访谈是以一个普通成员的身份运行的。

## 读你的代码仓库

你第一次接入代码仓库时——如果工作区已经有画像，并且有一个绑定了运行时的 Enact——会有一个任务被建出来，让她去读。

她会把仓库检出，读 README、包清单、CI 配置和目录树的上面几层，然后把发现写进画像的 **代码仓库** 字段：语言、框架、怎么构建、怎么测试、目录怎么划分。

那个字段在设置里是只读的。它是由真正读过代码的那次运行写的，是关于仓库的证据而不是你自己对项目的表述——所以改一句话说明不会把它弄丢，那次运行也不会去改你的说明。

如果工作区还没有画像，或者没有运行时，就不会建这个任务。给一个还没人描述过的项目附一份仓库报告，是一份没人要的报告。

## 从命令行

```bash
enact workspace profile get --output json

enact workspace profile set --json-stdin <<'JSON'
{
  "summary": "面向中型承运商的物流控制塔。",
  "domain": "logistics",
  "stack": ["go", "typescript", "postgres"],
  "languages": ["zh", "en"],
  "typical_work": ["ship_code", "review_code"],
  "constraints": "生产变更需要第二个人评审。"
}
JSON
```

`profile set` 是**整体替换**，不是合并：你没写的字段会被清空。先读一遍当前的，改完再发回去。两个例外是代码仓库相关的字段，你的文档里完全不提它们时它们会被保留。

## 这个功能之前建的工作区

打开 能力中心 或者那个欢迎弹窗时会读一次清单，读的动作本身就会把缺的步骤补上。不需要手工迁移任何东西；已经成立的步骤会在同一次读取里关闭。
