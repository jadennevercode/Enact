市场是一份可以安装的能力目录：[skills](/skills)、智能体模板、Agent Family 和 MCP server 条目。安装其中一项，会在你自己的工作区里放上一份**副本**，之后你可以像编辑自己写的内容一样编辑它。

<Callout>
目前发布是由官方统一维护的。目录里的内容来自你的部署本身 —— AI-SDLC 交付体系随产品发布在里面 —— 应用里不再显示发布和管理操作。API 仍然接受来自工作区 owner 或 admin 的发布，部署自己的条目正是这样进来的。
</Callout>

## 里面有什么

| 条目 | 是什么 |
|---|---|
| **AI-SDLC Delivery** | 九个角色组成的 Agent Family —— intake、explore、contract、build、QA、release、operate、learn，以及跨记录做判断的 orchestrator —— 连同它们运行所依赖的十个 `sdlc-*` skill |

每个成员智能体和每个 skill 也都有各自独立的条目，方便只想要其中一块、而不是整个 Family 的团队。

目录里的每一项都会针对你的工作区标注**已安装**或**未安装**，并且可以按这两种状态筛选。已经引入的 Agent Family，和单个 skill 一样会显示为已安装。

## 可以发布什么

| 类型 | 会带走什么 | 不会带走什么 |
|---|---|---|
| **Skill** | `SKILL.md` 和全部参考文件 | 没有 —— skill 就是一段文字，按写好的样子发布 |
| **智能体模板** | 名称、描述、指令、模型和思考强度设置、它附带的 skill、它需要的 MCP server | 它的环境变量、运行时绑定、运行时配置，以及谁有权调用它 |
| **Agent Family** | Family 的描述和协作指令，以及每一个智能体成员的完整模板 —— 各自带着自己的 skill 和 MCP server | 里面的人类成员，以及负责人的行 ID；负责人通过"是哪一个成员"来标识 |
| **MCP server** | 移除全部凭据后的服务条目 | `env` 和请求头的值；URL 也一样，除非你标记为按原样发布 |

一个 Agent Family 最多带 16 个智能体，每个智能体最多带 32 个 skill。人类成员会被丢弃而不是发布：他们指向的是你工作区里的人，而不是别人工作区里的人。安装这个 Family 的人自己添加。

<Callout type="warn">
发布永远不会从你的浏览器上传内容。你指定自己工作区里的一个实体，由服务器读取它、剥离每一个带凭据的字段，再保存结果。正是这一点让这套隐去机制值得信赖。
</Callout>

## 发布

在目录由官方统一维护期间，应用里不显示发布和管理操作。下面描述的是 API 仍然执行的那条发布路径 —— 部署自己的目录就是走它进来的，等发布重新开放时，界面上回来的也是它。

一次发布除了元数据，还要决定两件事：

- **谁可以看到。**`仅本工作区`是团队内部的资料库。`公开`则覆盖当前部署里的每个工作区。可以先内部发布，准备好之后再设为公开 —— 两者的安装方式完全一样。
- **一个版本。**已发布的版本永远不会被覆盖。用同一个标识再次发布，只会给同一个条目加上一个版本，链接依然有效，历史也集中在一处。重复发布已经存在的版本号会被拒绝。

### 发布方隐去的值

对于 MCP server，`env` 的值、请求头的值和 URL 会被替换成空值，并在清单里列为**安装时必须提供的值**。安装这个条目的人自己填写。如果某个值确实不是凭据 —— 比如一个公开的端点 —— 你可以把它标记为按原样发布。

如果凭据直接写在服务的 `command` 或 `args` 里，或者写在智能体的自定义参数里，发布会**直接失败**，而不是把它隐去。悄悄改写一条进程调用命令，比拒绝发布更糟糕；请把这个值移到该服务的环境变量里，再重新发布。

## 安装

打开一个条目，就能看到安装后会创建什么 —— 智能体模板会列出它附带的 skill 和需要的 MCP server，Agent Family 则会完整列出每一个成员智能体 —— 然后选择**安装**。

表单只会问那些条目本身无法知道的内容：

- **在本工作区中的名称。**留空则沿用发布时的名称。
- **一个运行时**，针对智能体模板或 Agent Family。模板不指定具体机器，所以要从你自己的运行时里挑一个；Family 会把每一个成员都绑定到它上面，装完之后可以单独调整。如果这个模板是为另一个提供方编写的，该运行时不支持的设置会保持未设置，而不会阻止安装。
- **发布方未公开的值**，如果这个条目有的话。Family 的这类值除了服务名还带成员名，因为两个成员可能各自需要一个同名的服务。

### 一键引入 Agent Family

安装一个 Family 是一次动作，把它需要的一切都创建出来：每一个成员智能体、各自附带的 skill、各自需要的 MCP server，以及绑定它们的 Family，负责人和角色都与发布时一致。要么全部落地，要么一个都不落地 —— 成员只装了一半的 Family，会把工作派给并不存在的智能体。

如果某个成员的名称在你的工作区里已被占用，它会以带后缀的名称安装，而不会替换你已有的东西。安装出来的每个智能体默认都是私有的，装完之后再给需要被团队使用的那些设置可见性。

如果名称已被占用，你会看到和导入 skill 时一样的几个选择：用另一个名称安装，或者替换已有的那个。替换仅限被替换 skill 的原始创建者。

## 安装得到的是副本，不是订阅

已安装的 skill 或智能体此后不再跟随原条目。编辑你的副本是安全的；条目有了新版本，在有人安装之前也不会改变任何东西。

市场会记住你取用的是哪个版本，所以当更新的版本发布时，你已经拥有的条目会显示**更新到 vX**。取用这个更新，就是有意去安装那个版本。

<Callout>
已安装的 skill 无法从 skill 页面刷新。"从来源更新"重新下载的是某个 URL 今天提供的内容；而市场的更新，是安装你选定的那个版本。请使用条目页面。
</Callout>

## 下架一个条目

发布方工作区可以把条目**标记为弃用**，这会让它不再出现在浏览列表里，但已经依赖它的人仍然可以安装；也可以把它**下架**，这会彻底停止新的安装。在目录由官方统一维护期间，这两个动作都只能通过 API 完成。

两者都不会影响已经安装过它的工作区。他们的副本是他们自己的。

## Ontologies

市场的最后一个标签页列出 ontology。它们不是条目：它们由 Capability Hub 提供，并附加到智能体上，而不是复制进工作区。这个标签页的存在，是为了让各种能力在同一个地方就能找到；附加关系的管理在 [Ontologies](/skills) 页面进行。

已经被你的工作区附加的 ontology，会和其他内容一样标注为**已安装**，已安装/未安装的筛选在这个标签页同样有效。

## 使用 CLI

```bash
enact marketplace list --kind skill --output json
enact marketplace list --not-installed --output json
enact marketplace get <listing-id> --output json
enact marketplace install <listing-id> --output json

# 智能体模板需要一个运行时，以及所有被隐去的值。
enact marketplace install <listing-id> \
  --runtime-id <runtime-id> \
  --secret env.GITHUB_TOKEN=... \
  --output json

# Agent Family 的 kind 是 squad。它把每个成员都绑定到同一个运行时，
# 被隐去的值除了服务名还带成员名。
enact marketplace list --kind squad --output json
enact marketplace install <listing-id> \
  --runtime-id <runtime-id> \
  --secret reviewer/github/env.GITHUB_TOKEN=... \
  --output json
```

`enact marketplace list` 的 `INSTALLED` 列会显示你持有的版本，或者 `no`；`--installed` / `--not-installed` 可以把结果收窄到其中一侧。

没有发布命令。发布是管理员对什么可以离开这个工作区做出的决定，API 会拒绝来自智能体的调用。部署自带的条目由服务端在启动时从承载它们的工作区发布。

## 权限

| 操作 | 谁可以做 |
|---|---|
| 浏览和打开条目 | 任何工作区成员 |
| 安装 skill、智能体模板或 Agent Family | 任何工作区成员 |
| 安装 MCP server | 工作区 owner 或 admin |
| 发布、编辑、弃用或下架条目 | 发布方工作区的 owner 或 admin，走 API —— 目录统一维护期间界面上没有入口 |

智能体可以浏览和安装，但不能发布。
