Agents produce files: a report, a diagram, an exported dataset, a screenshot. Those files land on the issue or the chat the run came from, which is the right place to read them in context and the wrong place to find one a week later.

**Artifacts** is the workspace-wide view of the same files. Open it from the sidebar, at `/{slug}/artifacts`.

## How the browser is arranged

The left pane is a tree, the right pane is the detail of whatever you selected.

| Level | What it is |
|---|---|
| **Folder** | The issue the files came from, shown by its issue key and title. |
| **Row** | One artifact — a filename, with every version of it behind it. |
| **Detail** | Each version of the selected artifact, newest first, downloadable on its own. |

Files produced in [chat](/chat) are listed here too. They used to have nowhere to be collected and so never showed up in a browse view at all.

## Versions

An agent run never overwrites a file. Re-running the work uploads a new file, so the older one stays exactly as it was.

Two files become versions of one artifact when they share **the same issue and the same filename**. The newest one is what the row shows and what a plain download gives you; the older ones stay reachable in the detail pane. Two different issues that both produced `report.pdf` are two separate artifacts, not one file with two versions — the issue is what makes the name meaningful.

## Find and open a file

Search filters the tree by filename and by folder, and folders that still have a match open themselves so you can see inside. Narrowing the search never changes which file the detail pane is describing.

From the detail pane you can preview a file that Enact can render in the browser, download any version, and jump to the issue the file came from.

<Callout type="info">
Very large listings are capped. When the cap is reached the browser says so and tells you the total, so a partial tree is never mistaken for the whole workspace.
</Callout>
