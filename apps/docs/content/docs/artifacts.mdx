Agents produce files: a report, a diagram, an exported dataset, a screenshot. Those files belong to the work that produced them, so that is where you find them.

**Artifacts** is a browser over one issue's files, or one chat session's. Open it from the folder button in the issue header, at `/{slug}/issues/{id}/artifacts`, or from the same button in the chat session header, at `/{slug}/chat/{id}/artifacts`.

## What an issue's artifacts include

Three sources land in one listing.

| Source | Where it appears |
|---|---|
| **Files on the issue** | The top group, under *This issue*. |
| **Files attached in a comment** | The same top group — a comment belongs to its issue. |
| **Files a sub-issue produced** | One folder per sub-issue, labelled with its issue key and title. |

Sub-issues are included one level deep. A sub-issue is where delegated work lands, so a parent whose children did the producing would otherwise look empty. A grandchild's files stay with the child that owns them.

A chat session has nothing to delegate to, so its listing is flat.

## Versions

An agent run never overwrites a file. Re-running the work uploads a new file, so the older one stays exactly as it was.

Two files become versions of one artifact when they share **the same producing issue and the same filename**. The newest one is what the row shows and what a plain download gives you; the older ones stay reachable in the detail pane. An issue and its sub-issue that both produced `report.pdf` have two separate artifacts, not one file with two versions — the issue is what makes the name meaningful. Inside a chat session the filename alone identifies a file.

## Find, open and remove a file

Search filters the list by filename, and by issue for a sub-issue folder. Folders that still have a match open themselves. Narrowing the search never changes which file the detail pane is describing.

From the detail pane you can preview a file that Enact can render in the browser, download any version, jump to the sub-issue a file came from, and delete a version.

<Callout type="warn">
Deleting removes that version for everyone and cannot be undone. If the file is shown inline in a description or a comment, that image or link breaks. The uploader and workspace admins can delete; other members cannot.
</Callout>

<Callout type="info">
Very large listings are capped. When the cap is reached the browser says so and tells you the total. The issue's own files are kept ahead of its sub-issues', so a capped listing sheds delegated work first.
</Callout>
