**经验**是一条针对某个 [skill](/skills) 的改动提议，写于工作已经结束、并被完整看过一遍之后。由成员决定采纳还是驳回。一旦采纳，skill 立即改变，用到它的每一个智能体都会跟着改变。

关键在于这个循环：只靠手写 skill 的工作区，改进速度取决于有没有人想起来回去修改它；跑着经验沉淀的工作区，改进速度取决于它完成了多少工作。

## 经验是怎么提交的

每个工作区都有一名叫 **Lesson Learner** 的智能体。只有它能提交经验，而它也只做这一件事。

这是刻意的。值得写成规则的信号，是好几件工作里重复出现的模式 —— 同一个澄清问题被问了两次，同一个地方反复返工 —— 这些在单次运行内部都看不见。一名被派来完成具体工作的智能体，如果还要判断自己这次运行是否意味着一条长期规则，它既没有那个视野，也没有那个距离。

Learner 的工作从一次**复盘**开始：把一批已完成的工作扫一遍。有三种发起方式。

| 发起方式 | 范围 | 怎么开始 |
|---|---|---|
| **主动推荐** | 单个任务 | 智能体参与过的任务进入 done 状态后，Enact 会在任务页和收件箱里推荐一次复盘。 |
| **手动发起** | 单个任务、单个项目或整个工作区 | 在经验沉淀页面点击**发起复盘**，也可以从任务里发起。 |
| **定时执行** | 单个项目或整个工作区 | 一条分配给 Lesson Learner 的[自动化](/autopilots)。 |

复盘会作为一条普通任务分配给 Learner，因此它有可以阅读的执行记录、可以用来引导它的评论区，也有汇报发现的地方。

<Callout>
任务完成后的推荐每个任务只出现一次，无论你怎么回答都不会再出现。选择"不用了"是正常回答。如果工作区觉得这个提示太吵，可以在工作区设置里关掉，手动发起和定时执行的复盘不受影响。
</Callout>

## 一条提议包含什么

四个字段是必填的，缺任何一个 API 都会拒绝这条提议：

| 字段 | 回答什么 |
|---|---|
| **发生了什么** | 具体发生的事，并指明它们发生在哪些运行、任务和评论里。 |
| **什么时候适用** | 这条规则成立的条件。 |
| **什么时候不适用** | 一个照做反而会错的情形。 |
| **改动说明** | 对 skill 的具体改动。 |

反例是最容易被跳过的一项，也是最吃重的一项。一条连作者都说不出边界在哪里的规则，通常还没有真正被找到 —— 只是把一个个例推广了。一开始就要求写出来，比事后才发现便宜得多：那时它已经悄悄影响了一个月里的每一次运行。

## 审阅一条经验

从**经验沉淀**页面或收件箱打开一条经验。页面按这个顺序展示：

1. 这条提议现在是否还能采纳；
2. 它观察到了什么、什么时候适用、什么时候不适用；
3. 目前有哪些智能体在用目标 skill —— 也就是行为会因此改变的全部对象；
4. 与 skill 当前内容的对比。

采纳立即生效。中间没有单独的发布步骤，所以不会出现决定和 skill 实际内容不一致的时刻。

有权修改某个 skill 的人就可以决定针对它的经验 —— 它的创建者，或工作区 `owner` / `admin`。提议新建 skill 的经验需要 `owner` 或 `admin`。**智能体永远不能决定一条经验，包括它自己提交的那条。** 相关接口会拒绝智能体身份。

### 已过期的提议

提议会记下它当时针对的那个 skill 版本。如果 skill 在这期间改过，提议会被标记为已过期，无法采纳。

这不是为了给流程添麻烦。没有这一层，审阅的人可能会批准一份针对早已没人在用的内容写的改动。请让它基于当前版本重新写一份 —— 并且重新读一遍，因为在 skill 现在的内容之上，这条改动可能已经不成立了。

## 版本历史与撤销

skill 内容的每一次变化都会记为一个版本，不管是什么引起的：在应用里编辑、导入、从来源更新、采纳经验，或恢复历史版本。skill 页面的**版本**列表会列出全部版本，并标明各自由什么产生。

有两条回退的路：

- 在 skill 页面**恢复某个版本**。恢复的内容会作为新版本追加，而不是回退历史，所以恢复本身也可以再撤销。
- 在经验页面**撤回这条经验**。这会把 skill 还原成之前的样子 —— 除非 skill 之后又被改过，那么后来的改动会原样保留，只把这条经验标记为已撤回。撤回必须填写原因。

撤回的经验会保留记录。试过又被推翻的规则，和从来没有人提过的规则不是一回事，下一个想到同样主意的人需要能查到究竟是哪一种。

## 使用 CLI

```bash
enact lesson list --status proposed
enact lesson get <id>

# 先找到要针对的版本，再提交提议。
enact skill versions <skill-id>
enact lesson propose \
  --skill <skill-id> --base-version <version-id> \
  --title "交接时写明运行时" \
  --observation "连续两次运行都在问该用哪台机器。" \
  --applies-when "涉及本地仓库的任务。" \
  --counterexample "纯云端的工作只有一个运行时，写出来反而是噪音。" \
  --change-summary "在交接清单里加一行。" \
  --content ./proposed-SKILL.md

enact lesson approve <id> --reason "出现过两次，边界也清楚"
enact lesson reject <id> --reason "只发生过一次"
enact lesson withdraw <id> --reason "纯云端的工作也被它命中了"

enact retrospective start --scope workspace --since-days 14
enact retrospective list
```

`--base-version` 没有默认值，也不会有。提议指向的是它写作时依据的那个版本；替你解析出"当前版本"，等于悄悄把这个字段本来要消除的竞争条件放回来。
